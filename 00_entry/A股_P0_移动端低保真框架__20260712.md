# A股 P0 移动端低保真框架

更新时间：2026-07-12

## 用途

- 把 A 股 P0 首页的移动端方案压成可直接出低保真的 frame 级说明。
- 明确小屏下哪些信息必须留在首屏，哪些信息必须进入抽屉或次级入口。
- 重点验证移动端是否仍能顺走 `事件流 -> 解释卡 -> 决策记录 -> 回看` 这条主路径。

## 使用边界

- 当前只定义移动端首页低保真的结构、抽屉状态和走查重点。
- 当前不定义：
  - 视觉皮肤
  - 最终图标体系
  - 动画时长
  - 正式前端实现

## 首屏目标

- 首屏必须先出现 `今日事件流`，而不是大图、大卡或历史区。
- 用户点开事件后，解释卡和决策记录用同一个收口区处理。
- 历史回看可达，但不能顶替首页主路径。

## Frame 结构

### M01 默认首屏

```text
+----------------------------------+
| 顶部：全局状态条                 |
| - 市场一句话 - 待处理数          |
+----------------------------------+
| 今日事件流                       |
| - 事件卡 1                       |
| - 事件卡 2                       |
| - 事件卡 3                       |
| - ...                            |
+----------------------------------+
| 底部固定栏                       |
| [首页] [历史回看]                |
+----------------------------------+
```

### M02 事件选中后，半高抽屉

```text
+----------------------------------+
| 顶部：全局状态条                 |
+----------------------------------+
| 今日事件流（保留部分可见）       |
| - 当前选中事件高亮               |
| - 相邻事件仍可看到               |
+----------------------------------+
| 半高抽屉                         |
| - 事件标题                       |
| - 触发逻辑                       |
| - 影响推演                       |
| - 按钮：展开详情                 |
| - 按钮：记录决策                 |
+----------------------------------+
| 底部固定栏                       |
+----------------------------------+
```

### M03 抽屉展开后，解释与记录共区

```text
+----------------------------------+
| 顶部：抽屉头                     |
| - 事件标题                       |
| - 关闭 / 收起                    |
+----------------------------------+
| 解释卡内容                       |
| - 触发对象 / 时间                |
| - 触发逻辑                       |
| - 影响推演                       |
| - 历史类比（可折叠）             |
| - 下一次复查点                   |
+----------------------------------+
| 决策记录区                       |
| - 动作                           |
| - 理由标签                       |
| - 预期周期                       |
| - 备注                           |
| - 提交                           |
+----------------------------------+
```

### M04 提交后

- 抽屉回到半高或收起
- 事件流中该事件显示 `已记录`
- 用户可继续处理下一条事件

## 组件约束

### C01 顶部全局状态条

- 只留一句市场状态和待处理数量
- 不要堆多行摘要
- 不要在顶部放大图或复杂筛选器

### C02 事件流

- 首屏至少看到 `2~3` 条事件卡
- 当前选中态必须明显
- 每条事件卡只保留最必要信息：
  - 标题
  - 时间
  - 持仓关系
  - 状态

### C03 底部抽屉

- 默认半高，用于先展示简解释
- 可上拉到更高层，进入完整解释和记录区
- 禁止抽屉里再套第二层抽屉

### C04 决策记录区

- 与解释卡放在同一滚动上下文
- 提交按钮始终明显可达
- 键盘弹起时不能遮住提交按钮和预期周期字段

### C05 历史回看

- 放在底部 Tab 或单独次级页
- 不与首页事件流混排
- 首页中不默认展示大段历史列表

## 关键状态

### S01 空状态

- 事件流为空时，只显示一句状态说明
- 不自动切换成资讯页或历史页

### S02 半高抽屉状态

- 用于让用户快速判断是否值得深入
- 此时仍能看见一部分事件流，避免迷失位置

### S03 全展开状态

- 显示完整解释卡和决策记录区
- 用户可以不跳页完成决策记录

### S04 键盘弹起状态

- `动作`、`预期周期`、`提交` 三项必须保持可操作
- 若遮挡，优先调整提交区位置，不牺牲解释主路径

## 出稿护栏

- 不让移动端首屏出现第二主轴。
- 不让解释卡和记录决策分到两个页面。
- 不让历史回看抢占首页主区域。
- 不让抽屉层级超过 `1` 层。

## 低保真最小交付

- `1` 张默认首页
- `1` 张半高抽屉状态
- `1` 张全展开解释与记录状态
- `1` 张键盘弹起检查状态

## 当前重点验证

- 事件流首屏是否仍是主入口
- 半高抽屉是否足够传达事件含义
- 全展开后提交按钮是否依然明显
- 历史回看是否次要但可达
