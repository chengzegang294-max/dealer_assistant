## 5. 建议的下一阶段顺序

下面建议按四段推进，不交叉乱开。

### 阶段 A：先把信息源链路全部整理好

目标：

- 形成信息源清单
- 明确每个信息源的价值、抓取方式、稳定性、成本
- 先把现有 `信息直播间` 收口成标准模板

本阶段要交付的正式产物：

1. 信息源总表
2. 信息直播间模板说明
3. 第一批重点房间状态卡
4. 特殊分型清单

阶段 A 通过门槛：

- 至少 3 到 5 个房间可稳定复跑
- 至少 1 个特殊分型被单独归类
- 当前页导出、增量导出、checkpoint 口令固定

### 阶段 B：再讨论产品/功能需求

等阶段 A 收口后，再讨论：

- 系统到底需要哪些功能页
- 每个功能是为哪个信息源服务
- 哪些是必须做，哪些只是锦上添花

本阶段讨论重点：

1. 首页需要看什么
2. 房间/信息源列表页需要看什么
3. 历史回看与检索要做到什么程度
4. 标注、评分、摘要、告警分别要不要做

阶段 B 的产物：

- 功能需求清单
- P0 / P1 / P2 分层
- 每个功能的触发依据

### 阶段 C：再讨论补哪些付费/免费信息源

不要一开始就广撒网，建议在功能需求清单出来后再补源。

讨论顺序建议：

1. 先补免费且结构稳定的信息源
2. 再评估哪些付费源是“非补不可”
3. 最后才讨论是否需要为了某个功能专门买新源

建议按三类看：

- `免费基础源`：如公开行情、公告、基础新闻、公开榜单
- `半结构化源`：如直播间、评论流、社区帖流
- `付费强化源`：如高时效盘口、深度资金流、专有题材/异动源

阶段 C 的输出：

- 信息源扩展候选表
- 成本/收益判断
- 接入优先级

### 阶段 D：最后讨论指标组合

指标组合应放在信息源和功能需求之后。

原因：

- 指标组合不是先验真理，而是建立在你最终有哪些源、哪些字段、哪些页面之上
- 如果现在就讨论，会反复改口径

到阶段 D 再讨论：

1. 哪些是基础指标
2. 哪些是情绪指标
3. 哪些是事件触发指标
4. 哪些是给“打板/异动/龙虎榜”服务的组合指标

阶段 D 的输出：

- 指标池清单
- 指标分层
- 指标组合候选
- 每个组合的使用场景
