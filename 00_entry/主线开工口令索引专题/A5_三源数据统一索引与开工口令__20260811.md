## 第4节 3 个故障兜底

### 兜底 1：00_raw 为空怎么办
**现象**：闭市后抓取结束，`02_runtime/quicktiny_capture/batch_XX/00_raw/` 下无当日 JSON，或仅 <1KB 空壳。  
**处理顺序**：① 先重开 quicktiny 桌面端 → 按 F5 刷新页面 → 重新点「导出」。② 若仍空，切浏览器直接访问 `ladder_live.html` 同构站点，手动复制 JSON 粘贴为 `ladder_day__YYYYMMDD.json`。③ 仍失败，取前一日 `batch_05_min_day_sample__20260807/00_raw/` 为基线，标注 `[GAP_FILLED_FROM_PREV_DAY]` 在 meta 中，次日优先补抓。

### 兜底 2：批量脚本回归基线 FAIL 怎么办
**现象**：`calc_ladder_metrics_batch_v1.py` 或其他批处理脚本返回非 0，`metrics_history_test.tsv` 未更新，或 `test_calc_ladder*.py` FAIL。  
**处理顺序**：① 先跑 `python test_calc_ladder_v2_extended_25tests.py -v` 看哪条断言挂。② 单挂则取 `dry_run_20260810.tsv` 基线做 diff，确认是输入格式变还是逻辑回归。③ 输入格式变 → 临时加 `--legacy-input` 兼容开关跑；逻辑回归 → `git stash` 回滚到上一版脚本，先产出当日数据再修 bug。

### 兜底 3：连板 ladder JSON 只有 35 字节空壳怎么办
**现象**：`00_raw/ladder_day__YYYYMMDD.json` 文件大小 ≈35B，内容 `{"data":[],"status":"ok"}` 无实际连板数据。  
**处理顺序**：① 立即重登 quicktiny → 检查「连板天梯」页是否停在「加载中…」，等待 30 秒再导出。② 重抓仍空 → 打开东方财富 PC 端「涨停板分析」手动抄 3 列：代码/名称/连板数，存为 `ladder_day__YYYYMMDD_MANUAL_FALLBACK.json` 按字段字典兼容格式。③ 同时在当日 `sample_acceptance__YYYYMMDD.md` 记录 `[LADDER_EMPTY_FALLBACK_MANUAL]` 标签，次日列入 first-class 补抓清单。
