## 任务卡总表

### E01 事件驱动扩展验证

- 对应合同簇：
  - `事件驱动`
- 验证目标：
  - 判断 `事件驱动最小合同` 是否值得从 `T03` 的单点降级判断，升级为独立事件扩展候选。
- 所需输入：
  - `event_type / event_bias / hold_horizon_days`
  - 公告日期与可交易确认日期
  - 首批事件样本
- 执行动作：
  1. 以 `业绩预告 / 指数调样 / 大股东增持 / 股权激励` 四类做最小样本盘点
  2. 检查字段是否能稳定映射到统一输入
  3. 抽样评估 `positive_follow / observe / negative_or_skip` 标签是否有解释增量
  4. 判断哪些事件类型适合进入下一轮验证
- 预期产出：
  - 事件类型覆盖摘要
  - 字段可得性结论
  - 事件扩展优先级建议
- 通过标准：
  - 能回答哪些事件值得进入下一轮正式验证

### E02 市场择时 gate 候选验证

- 对应合同簇：
  - `市场择时`
- 验证目标：
  - 判断 `市场一致性 R² / 产业资本增减持` 是否值得进入下一轮市场阶段 gate 候选验证。
- 所需输入：
  - `timing_signal_state / timing_bias / hold_horizon_weeks`
  - `r2_value / industrial_capital_net_value`
  - 市场阶段样本分段
- 执行动作：
  1. 盘点两类信号的最小字段可得性
  2. 映射到当前 `G01 / G02 / G03` 市场阶段框架
  3. 判断它更适合做：
     - 阶段解释层
     - 二级过滤层
     - future_only
  4. 给出是否进入下一轮 gate 验证的建议
- 预期产出：
  - 市场择时字段可得性结论
  - gate 候选角色建议
  - 不接线说明
- 通过标准：
  - 能判断市场择时信号是否值得进入下一轮 gate 候选层

### E03 相关性选股 -> 动态因子联动验证

- 对应合同簇：
  - `相关性选股`
  - `动态因子有效性`
- 验证目标：
  - 判断 `静态相关性选股框架` 与 `动态因子评估层` 是否存在可执行的联动接口。
- 所需输入：
  - `factor_family / selected_factors / stock_score / portfolio_bucket`
  - `dynamic_eval_family / dynamic_factor_state / factor_selection_bias`
  - 首批候选字段映射表
- 执行动作：
  1. 先梳理静态因子框架输出字段
  2. 再梳理动态评估层输入/输出字段
  3. 判断能否形成：
     - `selected_factors -> dynamic_factor_state`
     - `dynamic_factor_state -> add / drop / keep`
  4. 给出联动验证是否可启动的结论
- 预期产出：
  - 联动字段映射摘要
  - 可行/不可行边界
  - 下一轮验证建议
- 通过标准：
  - 能判断“相关性选股 -> 动态因子”是否值得进入下一轮扩展验证
