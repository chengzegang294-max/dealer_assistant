# Butler Stage Roadmap

更新时间：2026-07-09

## 目标

- 把当前项目从“边整理边试探”切到“按阶段推进、每阶段有入口、有产物、有退出条件”。
- 先把资料整理、入口合同、增量并入流程固定好，再进入测试、交互、接入与软件测试阶段。
- 避免在阶段边界没收口前，把时间和额度大量消耗在低复用探索上。

## 当前定位

- 当前项目仍处在 `阶段A + 阶段B` 之间：
  - `阶段A`：资料整理准备与仓库归位
  - `阶段B`：新增资讯并入流程定型
- 当前最顺主线不是继续发散功能，而是：
  - 继续把来源资料、历史运行时和入口层整理到合同内目录
  - 继续把默认入口、批次 README、执行卡、artifact index 刷成统一口径
  - 同时把“后续新资料怎么并进来”写成固定流程

## 阶段总览

### 阶段A：资料整理准备

- 目标：
  - 把技术面、基本面、方法论、历史运行时、活跃入口全部归到明确目录角色。
  - 让 `00_entry / 04_active_main_docs / 10_source_library_archive / 12_tooling_runtime_archive / 02_runtime` 各自只做自己的事。
- 主要产物：
  - repo 级入口卡、执行清单、目录角色合同、批次 README / execution card / artifact index。
  - 技术面与基本面资料的批次化来源层承接。
- 退出条件：
  - 默认入口稳定。
  - 大块“裸目录 / 裸产物 / 无说明 batch”基本清完。
  - 当前资料不再依赖聊天记忆才能找到。

### 阶段B：新增资讯并入与制式融合

- 目标：
  - 固化“新来的电子书、视频、文章、研报、运行产物”如何进入仓库并与旧资料对齐。
  - 让新增资讯不再造成第二套入口、第二套命名、第二套裁决。
- 固定流程：
  1. 先落 `10_source_library_archive/<batch>/00_raw_snapshot`
  2. 补 `README + manifest + provenance`
  3. 判断它影响的是 `对象卡 / 合同 / runtime / 主文档入口` 哪一层
  4. 只把稳定结论提升到 `00_entry / 01_active_objects / 02_runtime / 04_active_main_docs`
  5. 保留原始快照与提升后入口之间的回链
- 退出条件：
  - 新资料进入时有固定 intake 路由。
  - 同类资料能按统一模板并入，不再每次现场临时发明流程。

### 阶段C：技术面与基本面对象化

- 目标：
  - 把技术面、基本面的核心知识从“资料堆”升级成“对象卡 / 合同 / 样本计划 / runner / acceptance”。
  - 形成可对账、可维护、可继续扩展的知识-信号桥梁。
- 主要产物：
  - 对象卡字段合同
  - 样本计划
  - runner
  - batch acceptance
- 退出条件：
  - 核心技术面与基本面主题都至少有最小对象化入口。
  - 不再只能靠长文描述规则。

### 阶段D：技术面与基本面测试

- 目标：
  - 对对象卡、规则、指标解释和聚合逻辑做针对性测试。
  - 区分“看起来合理”与“样本上可验收”。
- 测试范围：
  - 单对象样本验收
  - 多对象组合验收
  - `registry_v0` 聚合层验收
  - 关键样本回放与反例校验
- 退出条件：
  - 技术面与基本面的关键对象有稳定 acceptance。
  - 聚合层的 BUY / SELL / NO_TRADE 等核心决策路径有可复验样本。

### 阶段E：可视化交互与调试

- 目标：
  - 把当前入口、对象、测试结果和决策过程做成可视化交互界面。
  - 给后续调试、解释、人工复核提供更好的交互面。
- 主要产物：
  - 可视化原型
  - 调试视图
  - 决策过程展示
  - 关键对象 drill-down 页面
- 退出条件：
  - 至少有一条从 `入口 -> 对象 -> 聚合 -> 验收` 的完整可视化链路。
  - 调试不再只能靠手翻文档和 TSV。

### 阶段F：本地程序 / 本地 AI 接入

- 目标：
  - 把本地程序侧能力接入到现有入口和流程里，而不是另起一套孤立工作流。
  - 让本地助手、脚本执行、策略调度与已有合同层对齐。
- 主要产物：
  - 本地接入入口说明
  - 调用边界
  - 输入输出合同
  - 调试与回退方案
- 退出条件：
  - 本地接入不破坏现有 repo 结构。
  - 接入后的动作能回写到现有入口与验收链。

### 阶段G：软件测试与发布门禁

- 目标：
  - 在功能、交互和本地接入形成后，补齐软件测试阶段。
  - 把“能跑”升级为“可维护、可回归、可发布”。
- 测试范围：
  - 单元测试
  - 集成测试
  - 关键流程 smoke
  - UI / 交互测试
  - 数据合同回归测试
- 退出条件：
  - 关键主线有回归门禁。
  - 新改动不会轻易破坏已有入口、对象和聚合链。

## 电子书 / 视频小结的开启条件

- 不在资料归位未收口时大规模开电子书或视频总结。
- 当前先做两件事：
  - 把资料放对位置
  - 把新资料并入流程写死
- 当 `阶段A + 阶段B` 达到最小收口后，再明确两类 backlog：
  - `电子书精读 / 摘录 / 规则提炼 backlog`
  - `视频小结 / 方法论拆解 / 可量化规则 backlog`
- 后续所有小结都必须能回链到：
  - 原始来源快照
  - 对象卡或合同层
  - 当前主文档入口

## 当前并行原则

- A 线：继续收入口、计划、执行清单、主文档层的 repo-global 规划与短链。
- B 线：继续粗颗粒批量整理来源库 README、边界卡和归档说明，不再细碎逐个停顿。
- 只有当 `阶段A + 阶段B` 的入口和流程稳定后，才明显加速 `阶段C ~ G`。

## 当前禁止

- 不在阶段边界没固定前，就大规模发散到 UI、接入、自动化全栈实现。
- 不在资料还没归位时，先做大量电子书 / 视频总结正文。
- 不让新增资讯绕开 intake 流程直接进入默认入口。
- 不让 runtime、来源库、冻结层、主文档层重新混层。
