## 一、结论（冻结范围 + 修改门禁）

### 1.1 冻结范围

本合同冻结 `sector_capital_flow_snapshot__YYYYMMDD.json → data.rows[]` 按 `mainNetAmount` 降序取前 5 名后，展平为 **7 字段 JSON 对象数组** 的完整字段清单，用于 P1 第 1 栏「结构-资金矩阵」中 sector 资金档计算、头部比值判断、低分散假强警示。所有消费方（P1 模板脚本 / 资金集中度可视化 / 对齐度计算）**只认本合同 7 字段 + 固定前 5 排序**，不读原始 snapshot 其他字段。

输出 JSON 结构固定：
```json
{
  "tradeDate": "YYYYMMDD",
  "snapshotMinute": "15:00",
  "top5": [
    { "sectorName": "锂电池", "mainNetAmountYi": 20.94, "bigOrderAmountYi": 6.61,
      "strength": 1584, "pctChg": 1.261, "memberCount": 117, "relativeInflowYi": 0.152 },
    ...
  ],
  "top5SumYi": 72.48,
  "top1Top5Ratio": 2.57
}
```
> `top5SumYi` 和 `top1Top5Ratio` 是衍生汇总字段，也一并冻结（防止下游各自重算出现不一致）。

### 1.2 修改门禁（与天梯 16 列同规则）

| 门禁等级 | 条件 | 流程 |
|---------|------|------|
| 🟢 紧急修复 | 某字段在 8/10 真实样例中出现 null/空/越界（如 memberCount 负数） | 当日提交 PR → 次日回归 1 天 → 第 3 天生效 |
| 🟡 常规增删 | 新增指标需要新字段 / 某字段确认无用 | 提案 → 连续 3 个交易日回归（8/11, 8/12, 8/13）→ 第 4 天生效 |
| 🔴 口径变更 | 如 `mainNetAmountYi` 从「亿元」改「万元」/ `relativeInflowYi` 公式变更 | 提案 → 3 天回归 + 全量历史 top5 JSON 重刷验证 → 第 7 天生效 |

**冻结声明**：本合同自 2026-08-11 起生效。任何改字段 / 改排序规则（如前 5 改成前 10）/ 改 `top5SumYi` 汇总公式，必须先过 **至少 3 个连续交易日** 的回归验证（P1 第 1 栏 sector 资金档偏差 ≤1 档，头部比值偏差 ≤0.3），未过回归不得上线。

## 二、7 字段表格（逐字段 + 空值兜底规则）

> 数据来源路径：`sector_capital_flow_snapshot__YYYYMMDD.json → data.rows[]`，按 `mainNetAmount` **降序取前 5**，不足 5 条时后面补占位对象（见空值兜底第 8 条）。
> 真实值样例：全部取自 2026-08-10（周一）sector_capital_flow_snapshot__20260810.json 前 5 行（锂电池/有色/黄金/军工/酿酒）。

| # | 字段名（JSON key） | 数据类型 | 取值范围 / 格式 | 8/10 真实值样例（5 条） | 来源 / 计算公式 | 空值兜底规则 |
|---|-------------------|---------|----------------|------------------------|---------------|------------|
| 1 | `sectorName` | str | 板块中文名称，2-8 字 | `"锂电池"` / `"有色金属"` / `"黄金"` / `"军工"` / `"酿酒"` | `rows[].sectorName` | 缺 / null / 空串 → 写 `"UNKNOWN_SECTOR"`（禁止空值对象进入 top5 数组） |
| 2 | `mainNetAmountYi` | float | `(-∞, +∞)`；单位 **亿元**；正数=净流入 / 负数=净流出 | `20.94` / `17.65` / `15.40` / `10.33` / `8.16` | `rows[].mainNetAmount ÷ 100000000`，保留 2 位小数 | null / 缺 → `0.0`；原始 `mainNetAmount` 非数字 → `0.0` 并记告警日志 |
| 3 | `bigOrderAmountYi` | float | `(-∞, +∞)`；单位 **亿元**；大单（通常 ≥100 万手口径）净额 | `6.61` / `3.58` / `5.46` / `4.08` / `2.10` | `rows[].bigOrderNetAmount ÷ 100000000`，保留 2 位小数 | null / 缺 → `0.0`（不影响 P1 主计算；仅用于辅助判断大单是否跟随主力） |
| 4 | `strength` | int | `(-∞, +∞)`；无单位，相对强度；正数=强于大盘 / 负数=弱于大盘 | `1584` / `2637` / `2935` / `2039` / `2477` | `rows[].strength` 原始整数（不做除法） | null / 缺 → `0`；注意：`strength=0` 不代表「无数据」，可能是真实中性值，需结合 `pctChg` 判断 |
| 5 | `pctChg` | float | `(-20, +30)`；单位 **%值**（如 1.26 表示 +1.26%） | `1.261` / `2.256` / `2.851` / `1.309` / `2.117` | `rows[].pctChg` 原始值（通常 1-3 位小数） | null / 缺 → `0.0`；与 `strength` 同时为 0 时，该板块标记为「可疑空值」记日志 |
| 6 | `memberCount` | int | `[0, +∞)`；成分股数；`0` 不代表缺失（可能是数据源未提供） | `117` / `0` / `11` / `176` / `0` | `rows[].memberCount` 原始整数 | null / 缺 → `0`；禁止写负数（若原始数据出现负数，强制置 0 并告警） |
| 7 | `relativeInflowYi` | float | `(-∞, +∞)`；**相对流入比例**（非金额）；含义 = 主力净额 / 板块流通市值 × 归一化系数；值越大表示资金相对于板块体量越集中 | `0.1524` / `0.2800` / `0.5102` / `0.1127` / `0.2717` | `rows[].relativeInflow` 原始值（通常保留 3-4 位小数；**注意：后缀 Yi 仅表示与亿元级字段并列，本字段本身是比例值不是金额**） | null / 缺 → `0.0`；`floatMarketCap` 为 0 导致无法计算时 → `0.0`，不报错 |

### 2.1 汇总衍生字段（同时冻结，禁止下游各自重算）

| 字段名 | 类型 / 公式 | 8/10 真实值 | 用途 | 兜底 |
|--------|------------|-----------|------|------|
| `top5SumYi` | float = `Σ(mainNetAmountYi for top5)` | `72.48` | P1 「低分散假强警示」阈值判断（<100 亿=低分散） | 前 5 不足 5 条时，只累加实际存在的对象，**不**补默认值凑数 |
| `top1Top5Ratio` | float = `top5[0].mainNetAmountYi ÷ top5[4].mainNetAmountYi`，保留 2 位 | `2.57`（20.94 ÷ 8.16） | P1 「头部比值」判断（>4=真抱团尖峰 / <3=头部钝） | `top5[4]` 为 0 或缺失 → 写 `0.0` 并告警；禁止 Infinity / NaN 进入 JSON |

## 三、操作步骤（日常排序导出 + 空值兜底执行清单 + 改列流程）

### 3.1 日常：从 snapshot → top5 JSON（标准 6 步）

1. **输入校验**：打开 `sector_capital_flow_snapshot__YYYYMMDD.json`，检查：
   - `success === true`
   - `data.returned ≥ 5`（若 <5，跳 3.2 空值兜底第 8 条）
   - `data.actualTradeDate` 与文件名日期一致
2. **全量排序**：对 `data.rows[]` 按 `mainNetAmount` **降序**排序（大 → 小）
3. **切前 5**：取排序后第 0-4 条（共 5 条）；不足 5 条时实际取 N 条，后面用占位对象补到 5 条
4. **字段映射 + 单位转换**：
   - `mainNetAmountYi` = `mainNetAmount / 100000000`，`toFixed(2)` 后转回 float
   - `bigOrderAmountYi` = `bigOrderNetAmount / 100000000`，同上
   - 其余 5 字段按「二、7 字段表格」直接取值，不做转换
5. **汇总字段计算**：
   - `top5SumYi` = 前 5 条 `mainNetAmountYi` 求和，保留 2 位
   - `top1Top5Ratio` = 第 0 条 / 第 4 条 `mainNetAmountYi`，保留 2 位（除零兜底）
6. **写盘 + 自检**：
   - 文件名：`sector_top5__YYYYMMDD.json`
   - 自检清单：① top5 数组长度 = 5；② 所有 7 字段无 undefined/null（都有兜底值）；③ `top5[0].mainNetAmountYi ≥ top5[1] ≥ ... ≥ top5[4]`；④ `top5SumYi` 手工加一遍对得上

### 3.2 空值兜底规则（逐条对应 7 字段，严格按顺序执行）

| 优先级 | 场景 | 执行动作 | 日志级别 |
|-------|------|---------|---------|
| 1 | `sectorName` 缺 / 空串 | 写 `"UNKNOWN_SECTOR"` | WARN |
| 2 | `mainNetAmount` 缺 / null / 非数字 | `mainNetAmountYi = 0.0`；该条不参与排序（排到最后） | WARN |
| 3 | `bigOrderNetAmount` 缺 / null | `bigOrderAmountYi = 0.0` | INFO（不影响主路径） |
| 4 | `strength` 缺 / null | `strength = 0` | INFO |
| 5 | `pctChg` 缺 / null | `pctChg = 0.0`；若与 `strength` 同时为 0 → WARN | 组合为 WARN |
| 6 | `memberCount` 缺 / null / 负数 | 非负 → `0`；负数 → 强制 `0` | 负数 = WARN |
| 7 | `relativeInflow` 缺 / null / NaN | `relativeInflowYi = 0.0` | INFO |
| 8 | **总兜底**：全量 `rows` 不足 5 条（如当天仅 3 个板块有数据） | 第 4、5 条用占位对象补：`{sectorName:"EMPTY_PLACEHOLDER", mainNetAmountYi:0, bigOrderAmountYi:0, strength:0, pctChg:0, memberCount:0, relativeInflowYi:0}`；同时 `top1Top5Ratio = 0.0` | ERROR（当天数据质量问题，需要人工确认是否缺抓取） |

### 3.3 改列提案流程（与天梯 16 列同口径）

1. **提案页**：旧仓 90 区新建 `sector_top5_proposal__YYYYMMDD.md`，写明：
   - 改字段类型（增/删/改类型/改公式/改前 N 数量）
   - 动机（哪个 P1 栏位卡壳 / 哪个阈值连续 3 天误判）
   - 新旧口径对比样例（必须用 8/10 真实 snapshot 跑：输出 top5 JSON + P1 第 1 栏 sector 资金档结论）
2. **Day 1-3 回归**：
   - 每日收盘后，新 / 旧口径各跑一份 top5 JSON
   - 对比：① `top5SumYi` 偏差 ≤±5 亿；② `top1Top5Ratio` 偏差 ≤±0.3；③ P1 sector 资金档（高/中/低）偏差 ≤1 档
   - 3 天累计：无 1 天同时触发 2 项以上超阈值
3. **生效**：
   - 附 3 天回归对比表 → 更新本合同「二、字段表格 + 2.1 汇总字段」
   - 版本号 +1，文末追加「变更历史」
   - 通知 P1 模板脚本 / 可视化脚本维护人同步更新 reader

### 3.4 违规应急（top5 排序错了 / 单位转错）

1. 当日立即 **回滚到上一版合同**，重新生成 top5 JSON
2. 在 `batch_datasource_gap__20260811/` 下记 `sector_top5_incident__YYYYMMDD.md`
3. 下次改列提案时，本次事故场景纳入「回归必测项清单」
