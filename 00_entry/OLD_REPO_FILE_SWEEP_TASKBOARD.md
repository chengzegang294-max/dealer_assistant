# Old Repo File Sweep Taskboard

## 目的

- 这份任务板用于约束：旧仓库不能再“看到文件就复制”，而要先扫清作用、来源、当前角色，再决定是否纳入新仓库。
- 重点先处理 `py`，因为旧仓库里最容易出现“脚本还在、结果也在，但谁对应谁说不清”的混乱状态。

## 当前新主线

- 当前不是把“迁移”和“全量吃透”拆成两条线，而是合成同一条主线：
  - 一边继续全量吃透旧仓库
  - 一边把已说明、已定责、可长期维护的内容迁入新仓库
  - 一边压掉旧主文档里的重复结论、错误过程和冗余段落
- 当前已明确补进两条刚性规则：
  - 允许按需要重命名或移动到新文件夹，但必须带原路径、现路径、作用说明
  - 禁止盲目复制源文件

## 总处理动作

- `COPY_WITH_NOTE`
  - 适用于：作用已明确、后续仍维护、输入输出合同能说清的文件
  - 要求：复制时必须同时补 `README / EXECUTION_CARD / ARTIFACT_INDEX / NOTEBOARD` 之一
- `NEW_IN_NEW_REPO`
  - 适用于：旧仓库缺少说明、但新仓库必须有的入口卡、合同、备注、wrapper、skill 副本
  - 要求：正文中文说明，文件名优先英文
- `MOVE_LATER_AFTER_REF_CHECK`
  - 适用于：理论上应从旧仓库移走，但当前还有旧路径引用、脚本调用或历史锚点
  - 要求：先复制并稳定运行，再做引用检查，最后再决定是否移动
- `KEEP_OLD_FROZEN`
  - 适用于：历史产物、一次性脚本、职责不清文件、无法确认是否仍被使用的目录
  - 要求：先留旧仓库冻结，不直接迁入新仓库正式层
