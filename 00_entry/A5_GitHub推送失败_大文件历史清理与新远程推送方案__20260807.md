## 主负责人裁决

### 这次选什么

选：

- `新远程 + 本地历史瘦身后再首推`

### 为什么选这个

- 当前远端几乎是空仓，改写本地历史成本最低。
- 真正值钱的是：
  - 当前代码
  - 入口文档
  - 信息直播间脚本与 runtime 证据
- 真正不适合继续放在 GitHub 普通仓主历史里的，是大批冷原始资产和老大体量回测输出。

### 为什么不选另外几个

#### 不选：继续硬推

- 已经打出 `6.00 GiB` 包并触发 `HTTP 500`
- 再试大概率还是重复失败

#### 不选：把所有大文件都迁进 Git LFS

- 当前大头不是“少量需要协作的大模型文件”，而是“大批冷原始快照与冷归档”
- 全量转 LFS 会把仓库变成“超大资料仓”，不是当前这条主线要的代码仓

#### 不选：只删当前工作区未跟踪大目录

- 推送失败来自历史 pack，不是当前未跟踪尾巴
- 只删工作区，无法缩小已提交历史

## 推荐执行顺序

### A. 先保护现场

1. 新建本地备份分支
2. 把当前值钱的未提交改动单独提交或暂存
3. 把不该入库的 `scratch` 与临时大包继续留在工作区外缘

### B. 再做冷资产保护

把“必须先出历史”的大目录先复制到 Git 工作树外的本地冷存放路径，例如：

- `D:\Stock\_cold_archive\trading_assistant_big_assets__20260807\`

这里只是出 Git 历史，不是要求你删除本地原件。

### C. 再做历史清理

优先路线：

1. 安装 `git filter-repo`
2. 按“第一层必须出历史目录”重写历史
3. 清理旧 pack 并复查最大文件

### D. 最后再推新远程

建议最终统一到：

- 本地分支：`main`
- 远端分支：`origin/main`

并以瘦身后的历史首次推送。
