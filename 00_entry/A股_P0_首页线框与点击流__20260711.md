# A股 P0 首页线框与点击流

更新时间：2026-07-11

## 用途

- 把 A 股 P0 首页从抽象结构压成可讨论、可原型化的线框说明。
- 固定首页四卡、主工作区、桌面端与移动端的交互主路径。
- 避免在原型阶段重新长回“普通行情看板”或“资料仓入口”。

## 首页四卡

1. `全局状态条`
2. `今日事件流`
3. `待处理决策台`
4. `历史决策追踪`

## 首页主轴

- 首页绝对主轴是：
  - `今日事件流`
- 首页不以 K 线、热榜、新闻流或持仓长表为主轴。

## 桌面端线框

```text
+---------------------------------------------------------------+
| 全局状态条                                                    |
+-----------------------------+---------------------------------+
| 今日事件流                  | 主工作区                        |
| - 事件 1                    | - 解释卡                        |
| - 事件 2                    | - 决策记录区                    |
| - 事件 3                    |                                 |
| - 事件 4                    |                                 |
| - ...                       |                                 |
+-----------------------------+---------------------------------+
| 历史决策追踪（底部折叠区或右侧次级区）                        |
+---------------------------------------------------------------+
```

## 桌面端布局原则

- 左侧是事件流，不做第二主轴。
- 右侧主工作区只服务当前选中的事件。
- 历史决策追踪不抢主工作区，只做回看层。
- 待处理决策台默认不独立成新页面，而是由主工作区中的决策记录区承担。

## 桌面端点击流

1. 用户进入首页
2. 先扫一眼 `全局状态条`
3. 在 `今日事件流` 中点开某条事件
4. 右侧主工作区加载该事件的解释卡
5. 用户在解释卡底部直接做决策记录
6. 提交后，事件状态更新
7. 用户可在 `历史决策追踪` 中回看最近处理结果

## 桌面端解释卡显示顺序

- 默认展示：
  - 事件标题
  - 触发对象
  - 触发时间
  - 触发逻辑
  - 影响推演
- 展开后展示：
  - 历史类比
  - 下一次复查点

## 桌面端决策记录区

- 放在解释卡底部或解释卡下方同一主工作区中
- 默认字段：
  - 关联事件ID
  - 动作
  - 理由标签
  - 预期周期
  - 备注
- 记录完成后，不跳走到新页面

## 移动端线框

```text
+-----------------------------+
| 全局状态条                  |
+-----------------------------+
| 今日事件流                  |
| - 事件 1                    |
| - 事件 2                    |
| - 事件 3                    |
| - ...                       |
+-----------------------------+
| 底部抽屉 / 固定底栏         |
| - 解释卡                    |
| - 决策记录                  |
+-----------------------------+
| 底部 Tab: 历史决策追踪      |
+-----------------------------+
```

## 移动端布局原则

- 主屏优先给 `今日事件流`
- 点击事件后，不跳出到多级页面树
- 解释卡与决策记录使用同一个底部抽屉或等价收口区
- 历史决策追踪放底部 Tab 或次级页面，不抢事件流位置

## 移动端点击流

1. 用户进入首页
2. 浏览事件流
3. 点击某条事件
4. 下方抽屉滑出解释卡
5. 抽屉底部直接记录决策
6. 提交后返回事件流，并显示该事件已处理状态
7. 用户通过底部 Tab 回看历史决策

## 当前明确不放在首页主路径里的东西

- 大面积 K 线图
- 新闻资讯流
- 大量历史研报链接
- 多维筛选器
- 多市场总览
- 复杂统计大屏
- 自由问答主界面

## 当前线框验证重点

- 事件流是否足够明确地成为单轴主路径
- 解释卡与决策记录共区是否自然
- 移动端抽屉是否会把记录入口压得过深
- 历史决策追踪是否过于抢眼
