## 三、操作步骤（日常 SENTINEL 更新 + NOTES 四节填写 + 改列流程）

### 3.1 日常：SENTINEL 索引刷新 + NOTES 加载标准流程

1. **SENTINEL 刷新（每日收盘后）**：
   - 运行：`python sentinel_update_rooms_index_v1.py --rooms-root <rooms目录>`
   - 检查输出 `SENTINEL_INDEX.md`：① 24 房序号与本合同 2.1 完全一致；② A/B 分桶无跳变；③ Raw 文件数 / 最后 Raw 日期正确
   - 若出现 24 房名单变动 → 触发 🔴 改列门禁（不是日常刷新，是改列提案）

2. **NOTES 四节加载校验（脚本每日自动跑）**：
   - 逐房打开 `10_ingest/NOTES.md`，检查 4 个一级标题是否齐全（顺序也要对：盯盘记录 → 金句区 → 踩雷区 → 元信息区）
   - 盯盘记录表 8 列表头逐字比对（含括号 / 空格），不一致的房 → 记 WARN 日志 + P1 预期差跳过该房
   - 踩雷记录表 3 列表头逐字比对，不一致 → 记 INFO 日志（仅影响命中率统计，不挡 P1）
   - 元信息 4 条缺失 → 按「二、2.2 第四节」兜底规则自动补填

3. **手动填 NOTES（人工作业）**：
   - 盯盘记录：一条观点一行，**严格 8 列**；多条观点按日期倒序（最新在最上面）
   - 金句区：只加不改，老师的金句确认是「长期说的」再加（不要把单日观点当金句）
   - 踩雷区：事后验证后再填，**不要预判**；改口 / 删帖也要记（即使观点本身对了）
   - 元信息区：建议每 3 天更新一次 Raw 文件数 / 最新 Raw 日期

### 3.2 NOTES 空值兜底（脚本自动执行优先级）

| 优先级 | 场景 | 执行动作 | 日志级别 | P1 预期差影响 |
|-------|------|---------|---------|-------------|

| 3 | 某数据行「日期」空 | 跳过该行（不报错） | INFO | 仅丢失该行 |
| 4 | 「情绪定性」非枚举值 | 强制写 `谨慎` | INFO | 权重降 20% |

| 6 | 缺第四节标题 / 某条 | 从 SENTINEL 反查补填 / 写默认值 | INFO | 不影响 |

### 3.3 改列提案流程（24 房变动 + NOTES 结构变动）

1. **提案页**：旧仓 90 区新建 `rooms_notes_proposal__YYYYMMDD.md`，写明：
   - 改列类型：24 房名单（A/B对调/增删房）/ NOTES 四节结构 / 盯盘记录表 8 列 / 其他
   - 动机：举例（B桶某房连续 10 天无 Raw / 某列长期空值率 >90% / P1 预期差缺字段）
   - 新旧口径对比：用最近 5 个交易日数据，分别跑：① P1 第 5 栏预期差 4 档结论；② 24 房老师命中率 Top10 排序；记录两者差异

2. **Day 1-3 回归**：
   - 每日收盘后，新 / 旧口径各跑一次 P1 预期差 + 命中率统计
   - 对比：① P1 预期差 4 档（⭐真/🟢共鸣/⚠️共识/🔴陷阱）的结论差异 ≤ 同一条目跨房偏差 1 档；② 命中率 Top10 排序偏差 ≤ 2 名；③ 新口径不会导致任何一房间连续 3 天「无预期差可出」
   - 3 天累计：不出现 🔴 门禁级别的严重偏差

3. **生效**：
   - 附 3 天回归对比表 → 更新本合同「二、2.1 + 2.2」
   - 版本号 +1，文末追加「变更历史」
   - 通知：① `sentinel_update_rooms_index_v1.py` 维护人更新 `ROOMS_ORDERED` 常量；② P1 预期差脚本维护人更新 NOTES parser；③ 所有手动填 NOTES 的同学收到新表头模板

### 3.4 违规应急（24 房名单错了 / NOTES parser 崩溃）

1. 当日立即：① 回滚 `ROOMS_ORDERED` 到上一版；② 回滚 NOTES parser 到上一版；③ 重新生成当日 P1 预期差
