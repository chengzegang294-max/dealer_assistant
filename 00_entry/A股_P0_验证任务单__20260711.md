# A股 P0 验证任务单

更新时间：2026-07-11

## 用途

- 把 `A股_P0_验证清单__20260711.md` 中的待验证项压成可以直接执行的任务卡。
- 为后续数据验证、原型验证、用户测试和合规审查提供统一任务入口。
- 避免验证清单停留在“知道要验证什么”，但没有进入“谁来做、拿什么做、产出什么”的状态。

## 使用方式

- 本文档只写可执行验证任务，不再重写功能合同。
- 每张任务卡至少回答：
  - 验证目标
  - 所需输入
  - 执行动作
  - 预期产出
  - 通过标准

## 任务卡总表

### T01 量价阈值触发密度验证

- 对应验证项：
  - `V01 量价异常阈值触发密度`
- 验证目标：
  - 确认 `20日均量 1.8 倍 + 当日涨跌幅绝对值 > 4.5%` 是否落在可消费的触发密度区间。
- 所需输入：
  - A 股近一段历史行情数据
  - 当前量价阈值口径
- 执行动作：
  1. 用统一口径跑离线扫描
  2. 统计每日触发数量
  3. 抽样查看极多、极少和典型交易日
  4. 观察触发是否过度集中在微盘股或热门股
- 预期产出：
  - 每日触发数统计表
  - 典型样例列表
  - 初步误报/漏报观察结论
- 通过标准：
  - 能判断当前阈值是偏吵、偏静，还是基本可用

### T02 主力资金主触发验证

- 对应验证项：
  - `V02 主力资金主触发口径`
- 验证目标：
  - 验证 `主力资金主触发 / 北向增强 / 融资融券不进首页主触发` 是否合理。
- 所需输入：
  - 主力资金数据
  - 北向资金数据
  - 分市场阶段样本
- 执行动作：
  1. 按不同市场环境分段统计
  2. 对比主力资金与北向资金的信号覆盖度
  3. 观察主力资金连续条件下的触发稳定性
  4. 确认融资融券若放进首页是否显著增噪
- 预期产出：
  - 主力/北向对比摘要
  - 触发口径建议
  - 是否继续排除融资融券的结论
- 通过标准：
  - 能明确主触发和增强标签的职责分工

### T03 业绩预期差降级验证

- 对应验证项：
  - `V03 业绩预期差口径`
- 验证目标：
  - 确认一致预期口径是否稳定可得，并写清缺失时的降级路径。
- 所需输入：
  - 一致预期数据可得性信息
  - 业绩快报/预告样本
- 执行动作：
  1. 盘点是否具备稳定一致预期口径
  2. 若有，评估更新频率与覆盖度
  3. 若无，设计同比显著变化的降级规则
  4. 评估“简版提醒”是否可接受
- 预期产出：
  - 业绩事件主口径
  - 业绩事件降级规则
- 通过标准：
  - 业绩事件在无一致预期时不会直接失效

### T04 行业轮动阈值敏感度验证

- 对应验证项：
  - `V04 行业轮动阈值敏感度`
- 验证目标：
  - 评估行业/板块轮动事件是否在普涨普跌环境下过度触发。
- 所需输入：
  - 行业指数历史数据
  - 大盘基准数据
  - 当前轮动口径
- 执行动作：
  1. 统计不同市场环境下的触发密度
  2. 抽样检查普涨日和普跌日的伪触发
  3. 观察轮动事件对持仓解释是否真的有增量
- 预期产出：
  - 行业轮动触发分布
  - 伪触发案例
  - 是否需要微调的建议
- 通过标准：
  - 能判断该事件在 P0 是否值得保留当前灵敏度

### T05 历史类比样本门槛验证

- 对应验证项：
  - `V05 历史类比最小样本量`
- 验证目标：
  - 验证 `N < 5 隐藏统计` 是否是合适门槛。
- 所需输入：
  - 近一年各类事件的行业样本分布
- 执行动作：
  1. 统计 6 类事件在行业维度的样本量
  2. 观察 `N=5` 下的覆盖率
  3. 评估若门槛调到 `3` 或 `8` 会怎样
- 预期产出：
  - 样本门槛建议
  - 各类事件覆盖率摘要
- 通过标准：
  - 既不过度误导，也不会长期“没有统计可看”

### T06 影响推演文案理解验证

- 对应验证项：
  - `V06 影响推演文案理解`
- 验证目标：
  - 确认用户能否把 `常见路径` 理解为经验性提示，而不是未来预测。
- 所需输入：
  - 解释卡模板例句
  - 两套对照原型文案
- 执行动作：
  1. 准备“简版”与“完整模板版”两组卡片
  2. 让测试用户阅读并复述理解
  3. 记录是否被误解为预测
  4. 观察是否提升记录意愿
- 预期产出：
  - 文案理解反馈
  - 是否保留 `常见路径` 的结论
  - 需要禁用的危险措辞
- 通过标准：
  - 大部分用户能够把该字段理解为辅助判断，而不是预测承诺

### T07 移动端共用工作区验证

- 对应验证项：
  - `V07 移动端交互可用性`
- 验证目标：
  - 验证移动端底部抽屉/固定底栏是否会压住解释和决策入口。
- 所需输入：
  - 移动端首页线框
  - 可点击低保真原型
- 执行动作：
  1. 让测试用户从事件流进入解释卡
  2. 观察是否能顺利找到记录决策入口
  3. 记录键盘弹起、抽屉高度、字段遮挡问题
- 预期产出：
  - 移动端卡点列表
  - 推荐交互收口方案
- 通过标准：
  - 解释与记录在手机端仍能走通单条主路径

### T08 “调仓”动作理解验证

- 对应验证项：
  - `V08 调仓动作理解`
- 验证目标：
  - 确认用户能否正确理解 `调仓 = 持仓内部切换，总仓位大体不变`。
- 所需输入：
  - 动作词表定义卡
  - 决策记录原型
- 执行动作：
  1. 在原型中提供含糊和清晰两组示例
  2. 观察用户会不会把 `调仓` 误当 `减仓`
  3. 判断是否需要额外 tooltip
- 预期产出：
  - `调仓` 是否保留原词
  - 是否需要增强说明
- 通过标准：
  - 大部分测试用户能稳定区分 `调仓`、`减仓`、`观察`
