# A股 P0 原型走查脚本

更新时间：2026-07-12

## 用途

- 给桌面端与移动端低保真原型提供统一走查脚本。
- 让原型评审不再停留在“看上去不错”，而是按固定任务逐步过单。
- 把 `A股_P0_首页原型审阅清单__20260711.md` 中的检查点变成真实可执行的走查动作。

## 使用边界

- 当前适用于：
  - 纸面低保真
  - Figma 低保真
  - 可点击原型
- 当前不适用于：
  - 视觉稿审美评估
  - 前端开发验收
  - 数据正确性验收

## 走查角色

- 主持人：
  - 负责按脚本推进，不临场改题
- 观察者：
  - 只记录卡点，不当场重设计
- 走查用户：
  - 按脚本完成任务，不先解释产品设计

## 走查前准备

1. 准备桌面端低保真
2. 准备移动端低保真
3. 准备 `1` 条持仓相关事件样本
4. 准备 `1` 条非持仓但关注相关事件样本
5. 准备动作词与理由标签样本

## 任务脚本

### T01 首次进入首页

- 指令：
  - `你刚打开首页，先说你第一眼会看哪里。`
- 观察重点：
  - 是否自然先看 `今日事件流`
  - 是否被其它区域抢走注意力
- 记录项：
  - 第一眼落点
  - 是否提到 K 线、历史区或其它干扰项

### T02 打开一条事件

- 指令：
  - `请打开你认为现在最需要处理的一条事件。`
- 观察重点：
  - 是否容易找到入口
  - 打开后解释卡是否出现得足够近
- 记录项：
  - 点击路径
  - 是否出现迷失或多余跳转

### T03 理解解释卡

- 指令：
  - `请用你的话复述这条事件在说什么，以及它为什么值得你处理。`
- 观察重点：
  - 用户是否能复述 `触发逻辑`
  - 是否把 `常见路径` 误当成未来预测
- 记录项：
  - 复述是否准确
  - 哪个字段最难理解

### T04 记录一个决策

- 指令：
  - `如果你现在要处理它，请完成一次记录。`
- 观察重点：
  - 决策区是否顺手可达
  - `观察`、`调仓` 是否会混淆
- 记录项：
  - 完成时长
  - 是否出现动作词误选

### T05 回看刚才的记录

- 指令：
  - `请找到你刚刚记录的那条决策，并确认它已经记下。`
- 观察重点：
  - 历史回看是否可达
  - 历史区是否过度抢位
- 记录项：
  - 回看路径
  - 是否回到了错误区域

## 桌面端专用检查

- 事件流是否明显位于左侧主入口
- 右侧解释卡与决策区是否共用主工作区
- 历史追踪区是否只做回看层

## 移动端专用检查

- 首屏是否先看见事件流
- 半高抽屉是否足够让用户理解事件
- 全展开后提交按钮是否明显
- 键盘弹起后是否遮挡关键字段

## 通过口径

- 用户不需要额外教学，就能完成：
  - 找到事件
  - 看懂解释
  - 记录决策
  - 回看结果
- 用户不会明显误把首页当成：
  - 普通行情看板
  - 历史台账首页
  - 资讯流入口

## 常见失败信号

- 第一眼不看事件流
- 解释卡出现太远
- 决策记录区需要额外跳页
- `调仓`、`观察` 被频繁混淆
- 移动端提交按钮被抽屉或键盘压住

## 走查输出模板

- 走查对象：
  - `桌面端 / 移动端`
- 完成情况：
  - `顺利 / 轻微卡顿 / 明显失败`
- 最大卡点：
  - `...`
- 需要修改的区域：
  - `事件流 / 解释卡 / 决策区 / 历史区 / 抽屉`
- 是否通过本轮：
  - `yes / no`
