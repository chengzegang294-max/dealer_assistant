# A5 A股 P0 首页工作台 Batch1 展示边界继续收紧页

更新时间：2026-07-21

## 一、这页用途

- 本页只做：
  - 冻结 `A股 P0 Batch1` 当前这轮继续推进的唯一主线
  - 说明为什么要把首页展示层继续从领域对象里隔离出去
  - 写死这一轮允许继续下沉的范围与停止规则
- 本页不做：
  - 重开 `A股 P0` 产品方向
  - 重开 `batch_149` 吸收价值判断
  - 重开 `FV gate`、第四窗、新 evidence type、多市场、本地 AI 技术栈

## 二、当前主线与当前不是

- 当前主线：
  - `A股 P0 Batch1` 首页工作台实现线
- 当前不是：
  - `batch_149` 新一轮吸收线
  - `FV gate` / 第四窗 / 新 evidence type
  - 多市场扩展
  - 本地 AI 技术栈讨论

## 三、为什么这一手最值钱

- 当前 `hook` 与 `workspaceModel` 已经把状态切换、不变量、提交结果下沉到逻辑层。
- 若展示组件继续直接吃完整 `EventItem / DecisionRecord / FinanceDisclosureContext`，后续接真数据时仍会把：
  - 字段裁剪
  - 展示拼接
  - 文案口径
  混回组件内部。
- 因此这一手最值钱的不是继续加新功能，而是继续把：
  - `首页编排层`
  - `展示适配层`
  - `纯展示组件`
  三者边界再压紧一格。

## 四、本轮允许继续下沉的范围

- 允许继续下沉：
  - `EventStreamPanel`
  - `HomeSidebar`
  - `HomeHero`
  - `StockSearchBar`
  - `MainWorkspacePanel` 的空态/标题层
- 允许新增：
  - 展示用 `view model`
  - 轻量展示文案适配
  - 只服务 `Batch1` 的静态展示字段整形
- 不允许借机扩展：
  - 新页面
  - 新数据协议
  - 真标的页跳转
  - 问答深挖
  - 自动交易动作

## 五、当前已经明确的边界

- 已写死的不变量仍然只有：
  - 切事件时强制重置 `homeRecordDraft`
  - 切事件时清空 `latestSubmitEcho`
- 已完成的下沉层：
  - `fixtures`
  - `hook`
  - `workspaceModel`
  - `workspace subcomponents`
- 当前继续收紧的口径：
  - 展示组件优先接收裁剪后的 view model
  - 页面编排层负责组装 view model
  - 领域对象尽量停在 adapter 之前

## 六、本轮停止规则

- 满足以下三项即可视为这一小段收口：
  1. `HomeHero / StockSearchBar / EventStreamPanel / HomeSidebar / MainWorkspacePanel` 中至少大部分固定展示文案与展示字段已先经 adapter 再入组件
  2. `npm run build` 通过
  3. `npm run lint` 通过

  - `HomeHero`
