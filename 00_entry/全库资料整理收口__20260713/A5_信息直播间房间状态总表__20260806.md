## 二、验收口径（统一）

### 当前页导出通过

1. `export_version` 为仓库最新（当前：`live_info_current_page_export_v1.5`）
2. `room_anchor` 正确（含说话人别名 / 优先房归一；允许 `forced_room_anchor`）
3. `visible_messages` 非空，且与当前屏幕可见卡片一致
4. 倒序观看下：`display_date / display_time / excerpt` 取**当前可见里时间最新**一条
5. 不含 UI 壳：`历史记录 / 搜索直播间消息 / 选择日期 / 倒序观看历史记录`
6. 不含单独广告壳：`更多资讯加微信好友…` 不得作为唯一正文

### 增量导出通过

1. 视觉滚动真实发生（不是只改外层 `scrollTop`）
2. 滚动后能稳定并入新消息且去重
3. 到顶 / 无新消息可正常收口
4. checkpoint 可续跑

## 八、分型清单（冻结）

1. **标准文字卡片型**：右栏 `cu-card` + 时间标题 + 正文
2. **说话人前缀分离型**：正文以主讲名开头，房间名靠别名映射
3. **增量滚动容器敏感型**：当前页可过，增量依赖真实滚动节点
4. **广告文案覆盖型**：正文可能被固定广告句盖住（天机 `163547`：480/486 条几乎只有微信引流句）
5. **图片为主型**：暂不进文字主链
6. **房间锚点侧栏漂移 / 混标签型**：内容属本房，但脚本 `room_anchor` 易写成侧栏邻近名或正文里的串台标签（周期女王曾误写 `浮光`/`k神`；天机曾误写 `先知`；格兰曾误写 `k神`）。**成因备注（主负责人）**：此类直播间常有机器人扒取痕迹，页面/正文可能混入他人房间标签或侧栏噪声；验收时以人工确认房间身份 + `scroll_end` 为准，不以单次 JSON 内 `room_anchor` 一票否决
