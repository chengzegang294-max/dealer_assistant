# A5 视频资料提取与多AI交叉校对流程页

更新时间：2026-07-23

## 一、这页用途

- 本页只做：
  - 固定视频资料进入 repo 前的最小提取流程
  - 固定“用什么 AI 做哪一步”的分工
  - 固定防丢失、防串题、防过度摘要的输出合同
- 本页不做：
  - 替代某条具体视频的吸收稿
  - 把视频口述直接当最终规则真值

## 二、主负责人裁决

- 视频资料处理必须遵守：
  - `raw 保留`
  - `时间戳保留`
  - `观点/规则/反例分层`
  - `至少一轮交叉校对`
- 不允许只留一篇“读后感摘要”就删原始转写。
- 最终裁决人仍是：
  - `Trae`
- `Cursor` 不是这条线的默认第一责任人；
  只有当抽取结果即将进入代码合同、字段合同或实现结构时，才适合接入实现向审校。

## 三、推荐 AI 分工

### 1. `多模态长上下文模型`

- 负责：
  - 通读整段视频或整份转写
  - 做时间戳分段
  - 把内容切成主题块
  - 标出截图/图表/口播切换点

### 2. `长文本结构化模型`

- 负责：
  - 从每个时间块里抽：
    - 规则
    - 条件
    - 动作
    - 反例
    - 失败前兆
    - 不确定项

### 3. `低成本复核模型`

- 负责：
  - 查漏
  - 看是否漏了反例/例外条件
  - 看是否把原话过度改写
  - 看不同段落之间是否发生语义冲突

### 4. `Trae`

- 负责：
  - 判断这条视频是否值得继续吸收
  - 做多 AI 回包吸收
  - 把结果落成 repo 可回链文档
  - 决定进入：
    - `future_only`
    - `weak_evidence`
    - 正式吸收

## 四、最小提取流程

### 1. `原件入场`

- 必备输入至少包括：
  - 视频 URL
  - 标题
  - 作者
  - 日期
  - 原始转写
- 若有关键画面，还要保留：
  - 截图
  - 图表截图
  - 关键页截图

### 2. `时间戳切块`

- 先按时间切出主题段。
- 每段必须保留：
  - 起止时间
  - 原话摘录
  - 这一段主要在讲什么

### 3. `第一轮结构抽取`

- 每个时间块都按同一合同抽：
  - `claim`
  - `rule`
  - `entry_condition`
  - `exit_condition`
  - `risk_control`
  - `exception`
  - `counterexample`
  - `unknown`

### 4. `第二轮 repo 映射`

- 把上一步结构项映射到 repo 内的目标层：
  - `10_source_library_archive`：保留 raw 与来源说明
  - `00_entry`：规则裁决页 / 触发页 / 吸收页
  - `02_runtime`：若未来进入验证，再落执行卡
  - `20_tools_workspace`：若未来进入实现，再落实现工作区

### 5. `交叉校对`

- 至少再用 `1` 个不同模型复核以下四件事：
  - 是否漏掉关键反例
  - 是否误把举例当硬规则
  - 是否把“经验偏好”误写成通用真理
  - 是否存在前后自相矛盾

### 6. `主负责人收口`

- `Trae` 必须最后写清：
  - 哪些能吸收
  - 哪些只能保留为 `NEED_EVIDENCE`
  - 哪些只是背景噪音
  - 下一手是否值得继续

## 五、防丢失输出合同

- 每条被吸收的结论，至少同时保留：
  - 原始时间戳
  - 原话或极短摘录
  - 结构化抽取项
  - repo 映射位置
  - 当前证据状态
- 若缺任一项，不算完成吸收。

## 六、正式落点规则

- `raw transcript / screenshot / exported notes`
  - 进入 `10_source_library_archive/<batch>/00_raw_snapshot/`
- `吸收总结 / 规则映射 / 对象映射`
  - 进入对应 batch 的 `02_absorb_index/` 或 repo-global `00_entry/`
- `当前主线判断页`
  - 进入 `00_entry/`
- 禁止把最终真值只留在：
  - 对话框
  - 临时粘贴区
  - 单个 AI 回包

## 七、停止规则

- 若一轮完整流程跑完后仍出现以下任一情况，则停止继续深挖：
  - 时间戳无法对齐
  - 原话缺失
  - 关键结论高度互相矛盾
  - 只能产出空泛观点，无法映射到 repo 对象
- 停止后只允许登记：
  - `future_only`
  - `weak_evidence`

## 八、与当前仓库的直接口径

- 本页服务的是后续技术分析验证阶段，而不是回头重开 `Batch2`。
- 当前若真的补某条视频，默认要同时生成：
  - `raw 保留`
  - `时间戳切块`
  - `结构抽取`
  - `repo 映射`
  - `主负责人裁决`
- 不允许只让一个模型出一版摘要就当吸收完成。

## 九、一句话口径

- 视频资料必须走“raw 保留 -> 时间戳切块 -> 结构抽取 -> 多AI交叉校对 -> Trae 裁决”五段流程，才能避免核心内容丢失或被误写成伪规则。
