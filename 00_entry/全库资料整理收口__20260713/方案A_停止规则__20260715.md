# 方案A 停止规则

更新时间：2026-07-15

## 用途

- 这份文件只做一件事：
  - 防止 `方案A` 再次掉回资料泥潭
- 它不是讨论稿，而是执行约束。

## 总原则

- 当前允许补资料，但只允许：
  - `缺口驱动补采`
- 当前不允许：
  - `兴趣驱动补采`
  - `先收藏再说`
  - `顺手扩一个相关主题`

## 一、什么时候可以开一个新缺口族

- 必须同时满足以下 5 条，才允许开：

### 1. 缺口已命名

- 必须明确写成：
  - `req_id`
  - 缺口主题
  - 当前为什么缺

### 2. 预期产出已命名

- 必须提前写清：
  - 这次补完要产出什么
  - 例如：
    - 字段表
    - 验收例
    - 数据可得性裁决补页
    - 权限边界说明

### 3. 补采范围已封顶

- 必须提前写清：
  - 主教材 `1` 个
  - 辅教材 `0-2` 个
  - 课程/系统样例 `0-1` 个

### 4. 回填落点已明确

- 必须明确补完后要回填到：
  - `方案A_需求矩阵_v1.tsv`
  - `方案A_资料资产清单_v1.tsv`
  - 对应裁决页或验收页

### 5. 中止条件已明确

- 必须提前写清：
  - 什么时候认定“补不到”
  - 什么时候必须停止追加

## 二、什么时候必须停止补一个缺口族

- 出现以下任一情况，立即停止：

### 1. 资料数量开始失控

- 单一缺口族超过以下上限：
  - 主教材超过 `1`
  - 辅教材超过 `2`
  - 课程/系统样例超过 `1`

### 2. 补来的资料不能转成产出

- 若拿到新资料后，`7` 天内仍无法产出：
  - 字段表
  - 验收例
  - 裁决补页
  - 降级说明
- 则立即中止，不做二次扩采。

### 3. 缺口边界开始漂移

- 如果原本补的是：
  - `A_REQ_002` 的字段与验收例
- 结果中途开始扩成：
  - 新市场
  - 新博主体系
  - 新课程大书单
- 则立即中止，并回到原缺口定义。

### 4. 出现“顺手再补一个”的冲动

- 若发现当前动作开始变成：
  - “这个也顺便收一下”
  - “那个也许以后有用”
- 一律视为泥潭预警，立即停止新增。

### 5. 当前缺口尚未回填就想开下一个

- 如果当前缺口还没回填到：
  - 需求矩阵
  - 资料资产清单
  - 对应裁决/验收页
- 就不允许开下一个缺口族。

## 三、什么时候可以宣布一个缺口族完成

- 必须同时满足以下 4 条：

### 1. 已形成正式产物

- 至少形成一类正式产物：
  - 字段表
  - 验收例
  - 裁决补页
  - 权限/降级说明

### 2. 已回填到总表

- 已更新：
  - `方案A_需求矩阵_v1.tsv`
  - `方案A_资料资产清单_v1.tsv`

### 3. 已写明仍余什么尾口

- 如果还有尾口，必须写清：
  - 是尾口增强
  - 不是当前阻塞

### 4. 已给出下一步

- 必须明确：
  - 下一个缺口是谁
  - 为什么轮到它

## 四、当前阶段的硬性禁止项

- 禁止重新回到：
  - 大范围书单扩张
  - 大范围课程扩张
  - 大范围博主系统扩张
  - 新市场全景式扩张
- 禁止把当前阶段偷换成：
  - runtime 新开发
  - 回测自动化实现
  - 默认执行逻辑扩展

## 五、当前正式顺序

- 当前只允许按以下顺序推进：
  - `A_REQ_002`
  - `A_REQ_003`
  - `A_REQ_001`

- 在这三个没完成前，不开启：
  - `A_REQ_004`
  - `A_REQ_005`
  - `A_REQ_007`
  - `A_REQ_008`
  - `A_REQ_010`

## 六、泥潭预警信号

- 一旦出现以下话术，说明已经开始偏了：
  - “这个先收着以后用”
  - “顺便把这套也看了”
  - “不如多开一个方向一起做”
  - “这个博主也不错一起补”
  - “这个市场以后可能也要”

- 一旦出现上述信号：
  - 立即停
  - 回到当前 `req_id`
  - 只问一个问题：
    - 这条新资料，是否直接服务当前缺口产出？

## 七、主负责人一句话执行口径

- 当前不是：
  - “继续把资料攒齐”
- 当前是：
  - `一缺口一补采，一补完一回填，补不成就中止，不再泛扩。`
