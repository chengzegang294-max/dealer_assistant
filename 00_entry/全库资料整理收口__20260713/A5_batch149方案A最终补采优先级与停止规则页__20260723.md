## 四、优先级 1：F11 联动解释

- 目标：
  - 把 `files/f11/tdxf11_cfg.xml`
  - `files/f11/js/f10_main.js`
  - `files/f11/js/f10_main_input.js`
  - `pages/通达信F11.html`
  这四类证据压成一页“入口配置 -> 主页面脚本 -> 输入匹配 -> 页面载体”的联动解释。
- 选择原因：
  - 当前这是 README / provenance / triage 都共同点名的最大缺口。
  - 这一步最能解释“系统怎么挂起来”，而不是继续堆局部效果样本。
- 通过条件：
  - 至少形成 `1` 张正式联动说明页
  - 说明清楚：
    - 分类树/入口配置来自哪里
    - 页面脚本负责什么
    - 输入匹配怎么接股票/标的
    - 为什么它不是单个静态 html

## 五、优先级 2：company 高价值页面补进三分表

  - 这一步能继续稳住：
    - 哪些是页面/网页载体
    - 哪些是插件编排
    - 哪些才值得进真公式候选
- 通过条件：
  - 三分表新增 `2-3` 行高价值页面
  - 每行都能明确落到：
    - `页面/网页载体`
    - `插件/菜单编排`
    - `真公式候选`
    之一

## 六、优先级 3：极窄公式截图链补洞

- 目标：
  - 只对当前仍缺双证据的代表类做补洞，不重开批量源码导出。
- 允许补的场景仅限：
  - 某一类代表公式已经有正文 `txt`
  - 但还缺编辑器截图，导致同源性说明不足
  - 且这条缺口会影响既有六卡解释链
- 当前不允许扩大为：
  - 全量系统公式截图工程
  - “再补 3~5 个源码导出”作为默认当前刀
- 通过条件：
  - 最多补到 `1-2` 个真正影响六卡解释链的缺类即停

- 不选“继续扩对象卡”：
  - 因为 `6` 张核心对象卡已经够前台消费，边际收益已显著下降。
