# A5 A股 P0 首页事件卡模板与事件摘要字段层

更新时间：2026-07-19

## 一、用途

- 本页只做：
  - 把
    `A股 P0`
    首页中的
    `今日事件流`
    继续压到
    `事件卡模板`
    与
    `事件摘要字段`
    层
- 本页不做：
  - 主工作区组件细化
  - 标的页记录编辑
  - 问答答案样式
  - 前端实现
  - 新 runtime

## 二、上位约束

- 当前首页唯一主轴仍是：
  - `今日事件流`
- 当前唯一主路径仍是：
  - `事件流 -> 解释卡 -> 决策记录 -> 回看`
- 当前事件卡的作用不是：
  - 资讯流卡片瀑布
  - 研报摘要卡
  - 自由问答入口卡
- 当前事件卡的作用是：
  - 让用户一眼判断
    `这是什么事件`
  - 是否值得点开进入主工作区

## 三、当前事件卡模板

- 当前每张事件卡固定由
  `4`
  层组成：
  1. `事件主标题层`
  2. `对象与时间摘要层`
  3. `关系与状态标签层`
  4. `金融限制短披露层`

## 四、字段分层

### 4.1 必填字段

- 当前事件卡必填固定为：
  - `事件标题`
  - `触发对象`
  - `触发时间`
  - `与持仓关系标签`
  - `已处理/未处理状态`

### 4.2 可选字段

- 当前事件卡可选只允许：
  - `事件类别`
  - `所属分组`
  - `一句话风险提示`

### 4.3 禁填字段

- 当前事件卡禁止直接放：
  - 目标价
  - 收益承诺
  - 大段解释正文
  - 长段 AI 总结
  - 多指标拼盘
  - 复杂图表

## 五、字段显示原则

### 5.1 事件主标题层

- 当前只承担：
  - 用一句短标题说清发生了什么
- 当前不允许：
  - 标题写成一整段分析结论
  - 标题直接下投资建议

### 5.2 对象与时间摘要层

- 当前必须至少显示：
  - `触发对象`
  - `触发时间`
- 当前作用是：
  - 让用户知道事件发生在谁、什么时候

### 5.3 关系与状态标签层

- 当前必须至少显示：
  - `与持仓关系标签`
  - `已处理/未处理状态`
- 当前允许的关系标签口径包括：
  - `持仓相关`
  - `关注相关`
  - `其它`

### 5.4 金融限制短披露层

- 当前每张事件卡都必须有稳定披露位
- 当前披露至少要让用户看见：
  - `still_need_evidence`
  - 相对基准限制仍存在
- 当前披露允许做成：
  - 短标签
  - 短链接
  - 短说明入口
- 当前不允许：
  - 完全隐藏
  - 只放到远处总说明页

## 六、分组口径

- 当前事件卡只允许按轻分组组织：
  - `持仓相关`
  - `关注相关`
  - `其它`
- 当前不允许扩成：
  - 多维筛选器中心
  - 排序配置面板
  - 标签运营后台

## 七、点击交接规则

### 7.1 点击后必须交给主工作区的字段

- 当前点击任一事件卡后，
  必须把以下字段交给主工作区：
  - `事件标题`
  - `触发对象`
  - `触发时间`
  - `与持仓关系标签`
  - `已处理/未处理状态`

### 7.2 点击后的唯一去向

- 当前点击事件卡后，
  唯一正确去向是：
  - 同一首页中的主工作区
- 当前不允许：
  - 跳转新页面
  - 打开独立大弹窗
  - 先进入问答页

### 7.3 点击后的最小结果

- 当前点击后必须至少触发：
  - `选中事件摘要条`
    更新
  - `解释卡主组件`
    加载
  - `决策记录组件`
    进入可填写态

## 八、最小样例类型

### 8.1 正常样例

- 当前正常样例必须同时具备：
  - 全部必填字段
  - 披露位
  - 可点击进入主工作区

### 8.2 缺字段样例

- 当前若缺少可选字段，
  允许继续展示
- 当前若缺少必填字段中的任一项，
  不允许伪装成完整卡
- 当前只能做：
  - 明示信息不完整
  - 禁止写成确定性结论

### 8.3 缺基准限制说明样例

- 当前若卡片涉及：
  - 事件解释预期
  - 策略含义
  - 决策暗示
  但未放披露位，
  视为不通过

### 8.4 已处理状态样例

- 当前已处理事件卡必须能看出：
  - 已处理
- 当前允许保留：
  - 进入主工作区回看当时解释与记录

## 九、桌面端原则

- 当前桌面端事件卡应优先满足：
  - 一眼扫完
  - 一点即入主工作区
- 当前不允许：
  - 单卡信息堆满导致扫读失败

## 十、移动端原则

- 当前移动端事件卡应优先满足：
  - 首屏快速滑读
  - 点开后进入解释与记录详情层
- 当前不允许：
  - 单卡过高
  - 重要字段折叠太深

## 十一、通过标准

- 当前通过标准是：
  - 用户只看事件卡，
    就能快速回答：
    - 发生了什么
    - 涉及谁
    - 什么时候
    - 是否与我有关
    - 是否已处理
  - 点开后能自然进入主工作区解释与记录链
- 若出现以下任一情况，
  视为不通过：
  - 没有披露位
  - 卡片直接写成投资建议
  - 点击后不进入主工作区
  - 必填字段缺失却仍假装完整

## 十二、停止规则

- 当前写清以下内容后即停：
  - 事件卡模板四层
  - 字段的必填 / 可选 / 禁填
  - 披露位
  - 点击交接字段
  - 最小样例类型
- 当前不在本页继续扩：
  - 主工作区实现
  - 标的页补充记录
  - 问答样式层
  - 新 runtime
