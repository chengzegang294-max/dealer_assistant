# A5 信息直播间截图对照与导出缺口页

更新时间：2026-08-01

## 一、这页用途

- 使用“25个直播间带截图”这一批真实材料，对照页面截图与导出 JSON。
- 目标不是争论脚本好坏，而是明确：
  - 当前脚本抓到了什么
  - 还漏了什么
  - 下一刀该怎么修

## 二、当前正式输入

- 运行时批次：
  - `02_runtime\info_live_room_sampling\batch_03__20260801_with_screenshots`

## 三、当前主负责人结论

### 1. 用户判断成立

- 用户说“当前获取的东西不够完整”，这个判断成立。
- 当前不完整，不是因为完全抓不到，而是因为：
  - 页面里可见的多条历史消息卡片，被压成了单条摘要字段
  - 导出 JSON 缺少“页面当前可见的消息列表”

### 2. 当前脚本已抓到的部分

- `room_anchor`
  - 本批 `25 / 25` 已抓到可用房间名
- `display_date / display_time`
  - 能抓到一条代表性时间
- `excerpt`
  - 能抓到一段正文摘要

### 3. 当前仍明显偏弱的部分

- `topic_anchor`
  - 本批约 `13 / 25` 仍偏弱
  - 常见问题包括：
    - 抓成正文开头长句
    - 抓成 `讲师`
    - 抓成 `11223344`
    - 抓成名字或时间串

- 多条消息结构
  - 截图里经常能看到：
    - 多条历史消息卡片
    - 每条都有自己的时间与正文
  - 但旧版导出只保留：
    - `1` 条 `display_date`
    - `1` 条 `display_time`
    - `1` 段 `excerpt`
  - 这会导致：
    - 页面上下文被压扁
    - 人工复核时会感觉“你没有看完整”

## 四、当前已做修复

- 已更新：
  - `20_tools_workspace\batch_07_info_live_room_tools\live_info_current_page_export_v1.js`

- 本次新增字段：
  - `visible_messages`
  - `heuristics.visible_message_count`

### 新字段含义

- `visible_messages`
  - 导出当前内容区里可见的前几条历史消息
  - 每条包含：
    - `display_date`
    - `display_time`
    - `text`

### 这次修复的意义

- 后续再导出时，不再只是“单条摘要”
- 会开始保留“当前页可见消息列表”
- 这能明显缩小：
  - 用户肉眼看到的页面
  - 与 JSON 实际保留下来的内容
  之间的落差
