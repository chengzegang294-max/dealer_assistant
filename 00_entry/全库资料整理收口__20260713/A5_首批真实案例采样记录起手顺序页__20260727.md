# A5 首批真实案例采样记录起手顺序页

更新时间：2026-07-27

## 一、这页用途

- 本页只做：
  - 冻结首批真实案例采样记录的起手顺序
  - 明确先写哪两张记录卡最稳
  - 把每张记录卡当前缺的证据写清楚

- 本页不做：
  - 个案收益判断
  - 有效性结论

## 二、当前为什么要先做这页

- 当前已经有：
  - 采样准备页
  - 最小字段合同页
  - 记录模板页

- 当前若直接散着写样例卡，
  容易重新回到：
  - 先写哪张不稳
  - 每张卡缺什么不统一

- 所以当前先补：
  - `起手顺序页`

## 三、当前首批起手顺序

### 3.1 第一张记录卡

- 当前对象组合：
  - `HYDB行业对比 / 沪深涨跌停 -> 上榜资金`

- 当前联动类型：
  - `背景先坏_触发后退`

- 当前优先原因：
  1. 已有联动样例作底
  2. 对象职责分工清楚
  3. 最容易先验证
     `背景怎么坏 -> 触发怎么退 -> 先降级职责`
     这一条链

- 当前缺的证据：
  - 可追溯的时间锚点
  - 可追溯的来源锚点
  - 背景与触发变化的对应片段

### 3.2 第二张记录卡

- 当前对象组合：
  - `ZSDB指数对比 -> 打板资金`

- 当前联动类型：
  - `触发先乱_背景也脏`

- 当前优先原因：
  1. 已有联动样例作底
  2. 当前动作升级路径简单
  3. 最容易先验证
     `波动失控 -> 先降权 -> 必要时回观察位`
     这一条链

- 当前缺的证据：
  - 可追溯的指数背景异常锚点
  - 可追溯的打板资金延续不稳锚点
  - 两者在同一案例中的并列来源

## 四、当前不作为首批起手的对象组合

- 当前暂不优先：
  - 三个以上背景对象叠加两个以上触发对象的大拼盘

- 原因是：
  - 首批真实案例采样的目标是
    `把记录卡写顺`
    ，
    不是先追求复杂度

## 五、当前首批记录卡的验收口径

- 当前每张记录卡至少要满足：
  1. 能写出 `sample_id`
  2. 能写出 `source_anchor`
  3. 能写出 `background_change`
  4. 能写出 `trigger_change`
  5. 能写出 `action_escalation`
  6. 能写出 `still_need_evidence`

- 若上述任一项写不出来，
  当前就不能把它算作正式采样记录完成

## 六、主负责人裁决

- 当前正式裁决为：
  1. 首批真实案例采样记录固定先做两张
  2. 第一张先做：
     `HYDB行业对比 / 沪深涨跌停 -> 上榜资金`
  3. 第二张再做：
     `ZSDB指数对比 -> 打板资金`
  4. 当前下一手直接切到：
     `首张真实案例采样记录卡`

## 七、当前 still_need_evidence

- 当前继续保留：
  1. 每张卡的证据来源是否足够硬
  2. 首批两张卡完成后是否值得扩样
  3. 首批两张卡仍然不是金融有效性结论

## 八、一句话口径

- 当前真实案例采样已经不再只是“准备一下”，而是正式冻结了首批起手顺序：
  先做
  `HYDB行业对比 / 沪深涨跌停 -> 上榜资金`
  ，
  再做
  `ZSDB指数对比 -> 打板资金`
  。
