# A5 Pi角色最小合同页

更新时间：2026-07-31

## 一、这页用途

- 本页只做：
  1. 冻结 `Pi` 的最小角色边界
  2. 说明 `Pi` 替代什么、不能替代什么
  3. 说明 `Pi` 增加什么价值、增加什么成本

## 二、这页属于哪条线

- 文件类型：`REPO_GLOBAL`
- 推荐落点：`00_entry\全库资料整理收口__20260713\`
- 原因：
  - 这是协作结构级合同，
    需要作为正式入口长期回看
- 是否允许放根目录：`no`
- 是否需要后续迁移：`no`

## 三、先纠偏：这不是新主线

- 当前必须明确：
  - `Pi`
    不是新的项目主线
  - `Pi`
    也不是信息源问题的解决器

- 当前主线仍然是：
  - `信息源分层与优先级明确`
  - `Tushare 权限与字段覆盖审计`
  - `为金融测试做标准化准备`

- 本页只解决：
  - 若未来让 `Pi` 进入系统，
    它只能做什么
    不能做什么

## 四、Pi 的最小角色定义

- 当前正式定义：
  - `Pi = 陪练 / 解释 / 复盘辅助位`

- 更具体地说，
  `Pi`
  当前只允许承担 3 种最小职责：

1. `陪练型提问者`
   - 把已经冻结的正式页
     翻译成用户可继续追问的问题

2. `解释层重述者`
   - 把已有正式结论
     用更自然、连续、易懂的语言重新解释

3. `复盘引导者`
   - 在一轮真实任务结束后，
     帮用户做轻量复盘、
     澄清误解、
     固化判断框架

## 五、Pi 明确可以替代什么

- 当前允许 `Pi` 替代的，
  只有以下摩擦位：

1. 用户直接啃长文档的理解摩擦
2. 正式结论转成问答时的解释摩擦
3. 任务结束后缺少复盘提问者的摩擦
4. 概念之间不容易串起来时的重述摩擦

## 六、Pi 明确不能替代什么

- 当前明确禁止 `Pi` 替代：

1. `Trae` 的主线判断与正式裁决
2. `Cursor` 的审校与编码向检查
3. `OpenWebUI` 的多方案讨论位
4. `Tushare / 东方财富 / 连板天梯`
   这些信息源本身
5. 任何正式数据源选择拍板
6. 任何编程、工程执行、代码修改主责
7. 任何金融有效性结论

## 七、Pi 的输入与输出合同

### 7.1 允许的输入

- `Pi`
  当前只允许消费：
  1. 仓内已经冻结的正式页
  2. 已裁决的正式结论
  3. 一轮真实任务后的复盘素材

- 当前不允许直接把：
  - 未裁决草稿
  - 临时粘贴区
  - 未验证页面摘录
  当作它的主输入

### 7.2 允许的输出

- `Pi`
  当前只允许输出：
  1. 解释性重述
  2. 复盘问题单
  3. 理解笔记
  4. 待澄清问题列表

- 当前不允许输出：
  1. 正式裁决页
  2. 正式信息源排序
  3. 编码实现方案拍板
  4. 交易建议

## 八、Pi 的增值与成本

### 8.1 增值

- 当前确认的主要增值有：
  1. 让正式页更容易被消化
  2. 让“解释即训练”成立
  3. 让真实任务后的复盘更连续
  4. 降低用户在复杂长文档前的理解门槛

### 8.2 成本

- 当前确认的主要成本有：
  1. 接入方式可能不稳定
  2. 解释层可能挤占主线时间
  3. 若边界不清，
     容易被误用为裁决者
  4. 若长期使用摩擦太高，
     会变成额外维护负担

## 九、Pi 与训练用户能力的绑定方式

- 当前正式绑定方式冻结为：
  - `解释即训练`
  - `复盘即训练`

- 当前不采用：
  - 独立训练项目
  - 独立训练课程
  - 脱离真实任务的空练线

- 当前允许的训练挂点只有 2 个：
  1. 正式页解释后的追问
  2. 一轮真实任务结束后的复盘

## 十、Pi 的最小试点条件

- 只有同时满足以下条件，
  才允许进入最小试点：

1. `Pi 接入方式与长期可用性审计`
   已过门槛
2. 试点场景只选
   `解释` 或 `复盘`
   之一
3. 试点输出只保留：
   - 理解笔记
   - 复盘问题
   - 待澄清项
4. 试点不改变当前主线优先级

## 十一、主负责人正式合同

- 当前正式合同冻结为：

1. `Pi`
   当前唯一允许升格的角色是：
   - `陪练 / 解释 / 复盘辅助位`

2. `Pi`
   当前不允许升格到：
   - `编程 AI`
   - `裁决 AI`
   - `执行 AI`
   - `正式数据源拍板位`

3. “训练用户能力”
   当前只允许作为
   `真实任务副产物`
   存在

4. 若后续接入证据不成立，
   `Pi`
   保留为系统外旁路工具，
   不进入仓内正式协作结构

## 十二、当前最小下一步

- 当前最小下一步冻结为：
  1. 先完成
     `Pi 接入方式与长期可用性审计`
  2. 再选一个真实任务场景，
     只试：
     - `解释`
     或
     - `复盘`
  3. 试点通过后，
     再决定是否写
     `Pi 最小试点执行页`

## 十三、一句话口径

- `Pi` 在当前系统里的最小正式角色已经冻结：它只能帮助你理解、追问、复盘，不能替你编程、拍板、执行；它的价值是降低理解摩擦、顺手训练判断能力，但前提是永远挂在真实任务上，不另开主线。
