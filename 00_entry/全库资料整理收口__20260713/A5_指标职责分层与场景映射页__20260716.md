# A5 指标职责分层与场景映射页

更新时间：2026-07-16

## 用途

- 把“每个指标到底负责什么、在什么状态下怎么用”正式收口。
- 避免后续把指标堆成清单，却没有角色、场景和组合逻辑。
- 为后续 `最小信号组合卡` 提供直接上游口径。

## 当前结论

- 同一个指标不应只有一种固定用法。
- 一个指标的用法，要由：
  - 当前市场状态
  - 该指标承担的职责
  - 它在组合中的层级
  一起决定。
- 当前正式口径应写成：
  - `先定义职责，再定义场景，再定义触发写法`

## 一、指标不是按名字分，而是按职责分

- 我们当前不按：
  - `MACD / RSI / 布林 / 均线`
  这种工具清单来组系统。
- 我们当前按：
  - `方向层`
  - `触发层`
  - `过滤层`
  - `仓位层`
  - `退出层`
  来定义角色。

## 二、同一指标在不同场景下可以承担不同职责

### 1. `均线`

- 在 `趋势延续` 场景下：
  - 更适合做：
    - 回踩确认
    - 趋势支撑
  - 典型写法：
    - 上升趋势中回踩均线企稳
- 在 `突破启动` 场景下：
  - 更适合做：
    - 突破确认
    - 收盘站上关键均线
    - 均线金叉后的跟随
  - 典型写法：
    - 收破均线
    - 金叉后放量确认
- 在 `震荡过滤` 场景下：
  - 更适合做：
    - 不交易过滤器
  - 典型写法：
    - 均线纠缠时降低权重或不触发

### 2. `布林带 / 波动带`

- 在 `波动收缩 -> 扩张` 场景下：
  - 更适合做：
    - 触发层
- 在 `极端偏离` 场景下：
  - 更适合做：
    - 过滤层
    - 退出层

### 3. `RSI / 动量摆动类`

- 在 `趋势行情` 场景下：
  - 更适合做：
    - 强弱确认
  - 不适合简单拿来做：
    - 机械超买即卖
- 在 `均值回归` 场景下：
  - 更适合做：
    - 触发层
    - 反转辅助确认

### 4. `成交量 / 量价关系`

- 在 `突破场景` 下：
  - 更适合做：
    - 真实性确认
- 在 `假突破筛选` 下：
  - 更适合做：
    - 过滤层

## 三、当前建议的场景分法

- 场景 A：
  - `趋势延续`
  - 关注：
    - 回踩
    - 趋势支撑
    - 强者恒强
- 场景 B：
  - `突破启动`
  - 关注：
    - 收盘突破
    - 放量确认
    - 结构切换
- 场景 C：
  - `震荡均值回归`
  - 关注：
    - 过度偏离
    - 回归中轴
    - 假突破过滤
- 场景 D：
  - `高波动风险保护`
  - 关注：
    - 降权
    - 缩仓
    - 不交易

## 四、每一层应该重点关心什么

- `方向层`：
  - 当前是不是值得偏多参与
- `触发层`：
  - 什么时候从观察变成动作
- `过滤层`：
  - 哪些信号虽然出现了，但应该拦掉
- `仓位层`：
  - 对了以后上多少，不是上不上
- `退出层`：
  - 什么情况下承认这次逻辑失效

## 五、后续最该重点关注的不是指标名字，而是五类问题

- 问题 1：
  - 这个指标当前承担什么职责
- 问题 2：
  - 它在哪种市场状态下才有效
- 问题 3：
  - 它和谁是互补，不是重复
- 问题 4：
  - 它触发后如何进入仓位与风险层
- 问题 5：
  - 它失效时最典型的坏样子是什么

## 六、后续落地时的最小组合写法

- 一个最小组合不应写成：
  - “均线 + MACD + RSI + 布林”
- 一个最小组合应写成：
  - `方向层：趋势状态`
  - `触发层：突破或回踩`
  - `过滤层：量价 / 波动 / 假突破过滤`
  - `仓位层：按置信度与风险缩放`
  - `退出层：结构破坏或强度衰减`

## 七、主负责人裁决

- 当前先不急着列几十个指标。
- 当前先固定：
  - 职责分层
  - 场景分法
  - 同一指标的多场景用法
- 当前完成 `validation run` 后，下一手优先落：
  - `最小信号组合卡`
- 到那一轮时，优先从以下两个候选开始：
  - `趋势延续 -> 均线回踩确认`
  - `突破启动 -> 收盘突破 + 量能确认`
- 且这条线已正式纳入：
  - 后续多AI讨论主题

## 八、一句话口径

- 指标的价值不在名称，而在它在不同状态下承担什么职责、怎样与别的层协同、最后如何进入风险和仓位。
