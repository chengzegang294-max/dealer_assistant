# A5 A股 P0 首页主工作区组件合同

更新时间：2026-07-19

## 一、用途

- 本页只做：
  - 把
    `A股 P0`
    首页里的
    `主工作区`
    从页面级合同继续压到组件级合同
- 本页不做：
  - 视觉风格
  - 前端技术选型
  - 新 runtime
  - 新 evidence type
  - 标的分析页点击流细化
  - 问答模板细化

## 二、上位约束

- 当前首页唯一主轴仍是：
  - `今日事件流`
- 当前主工作区的角色不是：
  - 第二首页
  - 自由聊天窗
  - 行情大屏
- 当前主工作区只服务于：
  - `看懂当前事件`
  - `完成一次决策记录`
  - `保留当前上下文`
- 当前主工作区必须受：
  - `A5_A股P0原型阶段金融披露与条件式门禁页__20260719.md`
    约束

## 三、当前主工作区的唯一任务

- 当前主工作区唯一任务不是：
  - 展示尽可能多的信息
  - 做研究终端
  - 让用户在这里长期聊天
- 当前主工作区唯一任务是：
  - 在用户点中一条事件后，
    让其在同一块区域内，
    顺着完成：
    - `解释`
    - `记录`
    - `提交回显`

## 四、当前主工作区组件清单

- 当前主工作区固定为
  `4`
  个组件层：
  1. `选中事件摘要条`
  2. `解释卡主组件`
  3. `决策记录组件`
  4. `提交后回显组件`

## 五、组件 1：选中事件摘要条

### 5.1 角色

- 当前组件只承担：
  - 把用户当前正在处理的是哪条事件钉住
- 当前组件不是：
  - 第二张解释卡
  - 大号标题区

### 5.2 最小字段

- 当前必须显示：
  - `事件标题`
  - `触发对象`
  - `触发时间`
  - `与持仓关系标签`
  - `已处理/未处理状态`

### 5.3 交互边界

- 当前切换事件后，
  本组件必须即时更新
- 当前不允许：
  - 切换事件后仍残留上一条事件摘要
  - 把摘要信息藏进二级折叠区

## 六、组件 2：解释卡主组件

### 6.1 角色

- 当前组件是主工作区里的第一核心组件
- 当前组件承担：
  - 把当前事件的最小解释交付给用户

### 6.2 默认字段

- 当前默认必须显示：
  - `事件标题`
  - `触发逻辑`
  - `影响推演`
  - `风险提示`
  - `下一次复查点`

### 6.3 展开字段

- 当前允许展开：
  - `历史类比`
  - `字段释义`
- 当前不允许展开成：
  - 长文研报
  - 多段自由结论
  - 无边界 AI 长回答

### 6.4 文案边界

- 当前解释卡必须使用：
  - 回顾性表达
  - 非承诺式表达
  - 条件式表达
- 当前不得写：
  - `建议买入`
  - `建议卖出`
  - `确定会上涨`
  - `稳定有效`

## 七、组件 3：决策记录组件

### 7.1 角色

- 当前组件是主工作区里的第二核心组件
- 当前组件承担：
  - 把“我看完解释后怎么记这次动作”
    立即落下去

### 7.2 必填字段

- 当前必填固定为：
  - `动作`
  - `理由标签`
  - `预期周期`

### 7.3 可选字段

- 当前可选为：
  - `备注`

### 7.4 默认动作范围

- 当前动作词表固定为：
  - `忽略`
  - `观察`
  - `加仓`
  - `减仓`
  - `调仓`

### 7.5 记录边界

- 当前不允许：
  - 把记录组件做成复杂表单
  - 一次要求用户填太多风险参数
  - 把止盈止损自动计算塞进首版记录区

## 八、组件 4：提交后回显组件

### 8.1 角色

- 当前组件承担：
  - 让用户确认这次记录已落下
  - 让主工作区状态不断裂

### 8.2 最小内容

- 当前提交后必须回显：
  - `本次动作`
  - `理由标签`
  - `记录时间`
  - `当前事件状态已更新`

### 8.3 不允许什么

- 当前不允许：
  - 提交后整区清空
  - 提交后强制跳新页
  - 提交后看不到刚才填了什么

## 九、主工作区的空状态

- 当前未选中事件时，
  主工作区必须只显示：
  - `请选择一条事件，查看解释并记录决策`
- 当前空状态不允许出现：
  - 大片空白
  - 长欢迎语
  - 大图表占位
  - AI 聊天推荐问题

## 十、主工作区的切换规则

- 当前从事件 A 切到事件 B 时，
  主工作区必须整体重载：
  - `选中事件摘要条`
  - `解释卡主组件`
  - `决策记录组件`
- 当前若 A 已提交、B 未提交，
  允许：
  - B 进入空白记录态
- 当前不允许：
  - A 的记录残留污染到 B
  - 不同事件混在一个记录区里

## 十一、主工作区的金融披露位置

- 当前金融披露不能只藏在远处总说明页
- 当前主工作区至少必须有一处稳定入口：
  - `金融限制说明`
  - 或等价短披露链接
- 当前披露必须能回链到：
  - `A5_A股P0原型阶段金融披露与条件式门禁页__20260719.md`
- 当前披露最少应提示：
  - `still_need_evidence`
  - 相对基准限制仍存在

## 十二、桌面端布局原则

- 当前桌面端主工作区顺序固定为：
  1. `选中事件摘要条`
  2. `解释卡主组件`
  3. `决策记录组件`
  4. `提交后回显组件`
- 当前若布局上出现：
  - 记录组件跑到解释卡上面
  - 回显组件比解释卡更抢眼
  视为偏离

## 十三、移动端收口原则

- 当前移动端也必须保持相同顺序：
  - 摘要
  - 解释
  - 记录
  - 回显
- 当前允许：
  - 半屏抽屉
  - 全屏详情
- 当前不允许：
  - 抽屉套抽屉
  - 多层表单跳转

## 十四、当前通过标准

- 当前通过标准不是：
  - 信息更多
  - 组件更多
  - 文案更长
- 当前通过标准是：
  - 用户能在一个连续区域内完成：
    - 看清当前事件
    - 看懂最小解释
    - 做出一次记录
    - 看见提交回显

## 十五、当前禁止项

- 当前不做：
  - 第二主工作区
  - AI 自由聊天主面板
  - 大图表分析区
  - 新闻瀑布流
  - 多市场切换
  - 新 runner
  - 新证据类型
