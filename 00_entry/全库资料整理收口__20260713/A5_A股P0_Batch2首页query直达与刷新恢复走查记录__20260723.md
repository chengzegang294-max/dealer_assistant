# A5 A股 P0 Batch2 首页 query 直达与刷新恢复走查记录

更新时间：2026-07-23

## 一、走查目标

- 验证首页已选事件时，打开标的页会带当前 `eventId`
- 验证直接打开 `/?eventId=...` 时，首页可恢复对应事件工作区
- 验证浏览器刷新后，首页仍保留同一事件上下文

## 二、走查环境

- 本地地址：`http://localhost:5175/`
- 走查事件：`stock-trigger-point-20260720-300750`
- 走查方式：桌面端真实点击流 + 浏览器刷新

## 三、走查路径

- 首页选中 `个股出现启动候选信号 / 宁德时代`
- 点击 `发出打开标的页动作：300750`
- 确认进入 `/stock/300750?eventId=stock-trigger-point-20260720-300750`
- 直接打开 `/?eventId=stock-trigger-point-20260720-300750`
- 在该首页地址执行浏览器刷新

## 四、走查结果

- 通过：首页已选事件后，打开标的页会带上当前 `eventId`
- 通过：直接打开 `/?eventId=stock-trigger-point-20260720-300750` 时，首页主工作区会恢复：
  - `个股出现启动候选信号 / 宁德时代 · 13:14`
- 通过：刷新后 URL 保持不变，首页仍展示同一事件上下文
- 通过：解释区内容与 `发出打开标的页动作：300750` 保持一致
- 通过：本轮未见控制台业务报错、白屏或上下文丢失

## 五、主负责人结论

- `Batch2` 当前已把首页恢复能力从“回链后能带回事件”继续推进到：
  - `query 直达`
  - `浏览器刷新恢复`
- 当前可以把首页事件恢复能力正式冻结为：
  - `基于 query eventId 的最小直达与刷新恢复`
- 当前仍明确不含：
  - `草稿恢复`
  - `多事件历史记忆`
  - `localStorage/sessionStorage`
