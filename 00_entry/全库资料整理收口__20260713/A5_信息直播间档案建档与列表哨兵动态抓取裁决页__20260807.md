## 二、主负责人已同意结论

### 2.1 产品定性（冻结）

- 信息直播间 = 成熟操盘手看法/观点集合
- **允许滞后**：主要服务**第二天操作方向**
- **金股池来源之一**
- 观点与操作建议 = **很辅助、很辅助**的参考，不当盘中主信号

### 2.2 档案要覆盖的现实

| 现象 | 处理口径 |
|------|----------|
| 长时间不更新会沉底 | 不删档；列表按「最后更新」沉底/告警；档案仍保留 |
| 房间换人 | 主键用正式房间名（可加别名表）；主讲/说话人是可变属性 |
| 随时新增房间 | 列表全量扫描进「候选池」；主负责人点头后进置顶/深挖 |
| 多房交易时段同时更新 | 用哨兵发现「谁更新了」，再对优先房深挖；不做全房毫秒级并行 |

### 2.3 抓取分层（冻结）

| 层级 | 名称 | 做法 | 地位 |
|------|------|------|------|
| A | 半自动导出 | 进房 → 当前页 v1.5 → 增量 v1.3 → 贴回 batch_05 | **建档/复盘默认**；有滞后 |
| B | 列表哨兵 + 置顶深挖 | 定时扫直播间列表（时间戳/预览变化）→ 只对置顶/活跃房增量深挖 | **交易时段同步更新的默认方向** |
| C | 多房近实时 | 多标签并行或接口级常驻采集 | **后置**；B 稳定后再评 |

**明确回答「能不能同步更新」：**

- 能，但默认走 **B**，不是「必须全程人手」。
- 也不是立刻上 **C**（成本高、易掉线/风控）。
- A 仍保留为兜底与历史补洞。

## 六、验收门槛（哨兵最小版）

做到以下即算哨兵 v0 可用：

1. 能导出「当前列表快照」JSON（房间名 + 预览 + 时间）
2. 能与上一份快照 diff，列出「今日有更新」房间
3. 置顶房若在更新列表中，能提示「请深挖 / 已深挖」状态
4. 结果落入 runtime，不落临时聊天里
