# 参考交易系统拆包深度枚举说明页

更新时间：2026-07-14

## 用途

- 这份说明只负责统一“参考交易系统现在拆到哪一层”的口径。
- 以后在状态表、索引入口、补采清单里出现深度词时，都以本页为准。

## 当前主原则

- 深度越深，不代表越接近执行逻辑。
- 当前阶段只做资料整理，所以最深也只是：
  - `映射页`
  - `候选层`
  - `合同候选`
- 不把任何参考系统直接写成默认执行逻辑。

## 深度枚举

| 深度枚举 | 含义 | 最低应有产物 | 适用情况 | 当前不要求 |
|---|---|---|---|---|
| `仅边界` | 只完成边界治理与 first-hop | `README / INDEX / boundary说明` | 还不能看清轨道和残余 | 不要求 second-hop |
| `仅边界+second-hop` | 已看清轨道、提升状态和残余区 | `SECOND_HOP_TRACK_INDEX / STATUS表` | 适合继续补细表 | 不要求对象合同 |
| `方法参考包` | 已形成稳定 bundle，但角色仍是方法参考 | `README / manifest / 吸收与分流 / 证据入口` | `NFTRADEZ / Smile_SMC` 一类 | 不要求字段合同 |
| `主题/对象候选` | 已能看出未来可能落到 topic 或 object 的簇 | `候选清单 / landing map / mapping说明` | 概念簇、主题簇、对象壳 | 不要求可运行 |
| `合同候选` | 已能写出字段、关系、最小合同 | `contract notes / field draft / relation entry` | 可量化候选 | 不要求稳定样本 |
| `样本合同候选` | 有合同方向，但还缺 provider/样本审计 | `sample contract / provider audit / evidence gap` | `MFLOW / INSTB` 一类 | 不要求运行入口 |
| `最小运行就绪` | 已有最小样本或最小运行入口 | `minimal runtime / smoke / fallback说明` | `YTC` 一类 | 不要求规模化运行 |
| `半自动运行就绪` | 已可跑，但仍依赖人工 seed 或人工判断 | `semi-auto runner / evidence / seed规则` | `CHZL_BSD` 一类 | 不要求全自动 |
| `映射页` | 只把“资料簇 -> 可吸收资产”映射清楚 | `mapping page / cluster status` | `NFTRADEZ / Smile / TK` 当前最适合 | 不要求对象化 |
| `future_only` | 当前只保留 future bucket，不进入本轮补采 | `future bucket note` | `ATRATIO` 等暂缓线 | 不要求继续下沉 |

## 怎么判断该拆到哪

- 若材料仍偏方法参考、叙事、案例：
  - 优先停在 `方法参考包` 或 `映射页`
- 若材料已经能抽成字段或关系：
  - 进入 `合同候选`
- 若已经有样本和最小可跑入口：
  - 进入 `最小运行就绪`
- 若仍依赖人工 seed 或人工确认：
  - 进入 `半自动运行就绪`
- 若当前价值不足或证据太弱：
  - 挂 `future_only`
