# A5 Pi接入方式与长期可用性审计页

更新时间：2026-07-31

## 一、这页用途

- 本页只做：
  1. 审计 `Pi` 是否存在稳定接入方式
  2. 审计 `Pi` 是否适合长期留在当前系统
  3. 识别 `Pi` 接入对主线执行成本的影响

## 三、先纠偏：信息源主线没有丢

- 当前必须明确：
  - `Pi`
    不是信息源主线的替代物
  - `Pi`
    也不是当前正式数据源问题的答案

- 当前信息源主线继续冻结为：
  1. `Tushare = 正式结构化数据源候选`

  3. `连板天梯 / quicktiny = 高度结构增强源`
  4. 当前最值钱的主线缺口仍是：

  - 给 `Pi` 这条辅助支线做接入审计

## 四、当前为什么要做这页

- 第二轮多 AI 已经收口为：
  1. `Pi` 可以后续植入系统
  2. 但只适合承担：
     - `陪练`
     - `解释`
     - `复盘`
     这一侧
  3. 当前最值得优先补证的唯一缺口是：
     - `Pi 是否具备稳定、低摩擦、可长期使用的接入方式`

- 所以当前这页不是“讨论 Pi 应不应该进”，
  而是把：
  - `能不能接`
  - `接了能不能长期用`
  - `会不会拖慢主线`
  这三个问题正式压实

## 五、当前审计问题

- 当前要审的不是能力强弱榜单，
  而是 4 个更实际的问题：

1. `Pi` 是否存在稳定接入方式
   - API
   - 官方客户端
   - 嵌入式网页/页面桥接
   - 其它低摩擦方式

2. `Pi` 是否可长期可用
   - 是否可持续访问
   - 是否容易失效
   - 是否强依赖高摩擦人工操作

3. `Pi` 接入是否低摩擦
   - 是否需要复杂工程接入
   - 是否必须长期人工搬运
   - 是否会明显打断当前执行链

4. `Pi` 是否会显著增加主线成本
   - 时间成本
   - 维护成本
   - 误用成本
   - 角色漂移成本

## 六、当前已知条件

- 当前已知条件有：
  1. 用户已认可：
     - `Pi 不作为编程的 ai`
  2. 第二轮多 AI 已经冻结：
     - `Pi 不承担主裁决`
     - `Pi 不承担工程执行`
  3. 当前只考虑：
     - `陪练 / 解释 / 复盘`
     场景
  4. 当前不为 `Pi` 单独开系统工程主线

## 七、接入方式候选分层

### 7.1 候选 A：稳定 API / 官方集成

- 理想程度：
  - `最高`

- 若成立，
  说明：
  - `Pi`
    有机会作为系统内低摩擦辅助位长期保留

- 需要确认：
  1. 是否有官方公开接入方式
  2. 是否支持稳定长期使用
  3. 是否有明确限制条件

- 当前状态：
  - `NEED_EVIDENCE`

### 7.2 候选 B：官方客户端或稳定人工旁路

- 理想程度：
  - `中`

- 若成立，
  说明：
  - `Pi`
    可先作为系统外稳定旁路工具使用
  - 但不等于已完成系统接入

- 需要确认：
  1. 是否可长期稳定访问
  2. 是否会造成高频人工切换
  3. 是否足以支撑真实任务复盘场景

- 当前状态：
  - `NEED_EVIDENCE`

### 7.3 候选 C：高摩擦人工搬运

- 理想程度：
  - `低`

- 若只能达到这一层，
  说明：
  - 当前不值得把 `Pi` 升成系统角色
  - 最多保留为偶发外用工具

- 当前状态：
  - `possible_but_not_preferred`

## 八、长期可用性审计表

### 8.1 必审项

1. 是否存在稳定接入入口
2. 是否容易受平台策略变化影响
3. 是否需要高频人工复制粘贴
4. 是否能在真实任务里低成本复用
5. 是否会让“解释层”反客为主拖慢主线

### 8.2 通过条件

- 只有同时满足以下条件，
  才允许后续进入最小试点：

1. 至少存在一种
   `可持续、低摩擦`
   的使用方式
2. 不要求推翻当前协作结构
3. 不要求单独启动新工程主线
4. 只作为
   `陪练 / 解释 / 复盘`
   的轻量辅助位即可成立

### 8.3 拦截条件

- 只要出现以下任一情况，
  当前就不推进：

1. 只能靠高摩擦人工搬运
2. 长期可用性明显不稳
3. 接入后会显著增加主线时间成本
4. 容易把用户误导成
   `Pi 可以参与主裁决`

## 九、主负责人当前审计结论

- 当前正式审计结论为：

1. `Pi`
   当前值得进入
   `接入方式与长期可用性审计`
   阶段

2. 但在拿到接入证据前，
   `Pi`
   只能算：
   - `已完成角色裁决`
   - `未完成接入放行`

3. 当前对接入层的初判为：
   - `若有稳定低摩擦入口，则可进入最小试点`
   - `若只有高摩擦人工搬运，则暂不升格为系统角色`

4. 当前信息源主线不被本页覆盖，
   继续保持：
   - `优先审计 Tushare 权限与字段覆盖`
