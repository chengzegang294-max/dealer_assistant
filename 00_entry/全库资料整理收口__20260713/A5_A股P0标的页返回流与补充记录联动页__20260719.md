# A5 A股 P0 标的页返回流与补充记录联动页

更新时间：2026-07-19

## 一、用途

- 本页只做：
  - 把
    `标的分析页`
    与
    `问答下钻页`
    之间的返回流、
    上下文恢复、
    补充记录入口
    收成正式页
- 本页吸收：
  - 标的页点击流中的返回流原则
  - 问答下钻模板中的回答边界
- 本页不做：
  - 问答模型实现
  - 新页面结构重写
  - 首页主工作区实现

## 二、上位约束

- 当前标的页仍服务于：
  - `最近发生了什么`
  - `为什么触发`
  - `最近怎么处理过`
  - `我还能问什么`
- 当前问答下钻仍只是：
  - 上下文增强器
- 当前返回流必须保证：
  - 原标的不丢
  - 原事件不丢
  - 原解释不丢
  - 记录入口不断

## 三、返回流的最小对象

- 当前返回流固定围绕
  `4`
  个对象：
  1. `当前标的`
  2. `当前事件`
  3. `当前解释`
  4. `最近决策记录或补充记录入口`

## 四、从标的页进入问答下钻

### 4.1 进入前必须锁定的上下文

- 当前进入问答下钻前，
  必须先锁定：
  - `标的名称/代码`
  - `当前事件标题`
  - `当前解释卡关键字段`
  - `still_need_evidence`

### 4.2 不允许什么

- 当前不允许：
  - 未选事件就进入问答下钻
  - 进入时丢掉当前解释上下文

## 五、从问答下钻返回标的页

### 5.1 返回后必须恢复

- 当前返回标的页后，
  必须恢复：
  - 原标的页头摘要
  - 原事件选中态
  - 原解释区内容
  - 原记录区位置或入口

### 5.2 不允许什么

- 当前不允许：
  - 返回后回到首页
  - 返回后默认切到另一条事件
  - 返回后解释区变空白

## 六、问答结果与记录区的联动

- 当前问答结果若涉及：
  - 对理由标签的解释
  - 对上次动作的复盘
  - 对下一次复查点的补充
  则必须允许用户顺手回到：
  - `最近决策记录区`
  - 或 `补充记录`
    入口

## 七、补充记录入口原则

- 当前补充记录入口只允许做：
  - 在已有记录基础上补备注
  - 在当前事件上下文下继续记录
- 当前不允许做成：
  - 完整账本后台
  - 第二套复杂编辑页

## 八、补充记录的最小字段

- 当前补充记录最小只允许：
  - `补充备注`
  - `补充时间`
- 当前不要求重新填写：
  - `动作`
  - `理由标签`
  - `预期周期`
  除非用户主动改写整条记录

## 九、问答后推荐下一步

- 当前问答完成后，
  只允许推荐以下下一步：
  1. `回到标的页继续看解释`
  2. `查看最近决策记录`
  3. `补充这次记录`
  4. `返回首页继续看事件流`
- 当前不允许推荐：
  - 脱离当前标的的新股票
  - 无上下文的自由聊天

## 十、异常态处理

- 当前若返回失败或上下文恢复失败，
  必须至少提示：
  - 当前无法完整恢复原上下文
  - 可返回原标的页重新选择该事件
- 当前不允许：
  - 静默丢失当前事件
  - 让用户不知道刚才问的是哪条事件

## 十一、桌面端最小联动流

1. 用户在标的页点某条事件
2. 看解释
3. 进入问答下钻
4. 看见基于当前事件的回答
5. 点击返回
6. 回到原事件解释区
7. 如有需要，
   再去：
   - 查看最近记录
   - 或补充记录

## 十二、移动端最小联动流

1. 用户进入标的页
2. 点一条事件
3. 进入问答详情层
4. 完成阅读后返回
5. 回到原事件上下文
6. 底部仍可触达：
   - 最近记录
   - 补充记录入口

## 十三、通过标准

- 当前通过标准是：
  - 用户在问答下钻之后，
    不会迷失当前标的与当前事件，
    并且还能自然回到：
    - 解释
    - 记录
    - 回看
    这条主路径
- 若出现以下任一情况，
  视为不通过：
  - 返回后丢失当前事件
  - 问答结果无法回到记录区
  - 补充记录被做成第二套复杂流程
