# A_REQ_001 权限边界与降级说明

更新时间：2026-07-15

## 用途

- 把 `A_REQ_001` 后续最容易误写的边界正式钉死。
- 这份文件只回答：
  - 什么能写
  - 什么不能写
  - 缺失时怎么降级

## 当前正式口径

- `default = daily_only`
- `minute = sample_only_with_provenance`
- `level2 = unavailable_in_current_runtime`

## 一、允许写法

### 允许写成正式可复现输入的

- `1d` A股 OHLCV catalog
- 已有 provenance 的定点分钟样本

### 允许写成“样本可得但未 formalize”的

- `60m/5m` 外部分钟包
- 分钟级 provider 候选与限频记录

### 允许写成 future_only 的

- `Level-2`
- 席位逐笔
- 更细盘口增强线

## 二、禁止误写

- 禁止把：
  - 日线或周线 probe
  写成：
  - 分钟级已就绪

- 禁止把：
  - 外部分钟样本包
  写成：
  - runtime 默认主 provider

- 禁止把：
  - Level-2 候选线
  写成：
  - 当前主路线已可用

## 三、降级规则

### 场景 1：缺分钟级正式入口

- 降级到：
  - `daily_only`
- 允许补充：
  - `sample_only_with_provenance`
- 不允许：
  - 伪装成批量分钟输入

### 场景 2：分钟 provider 限频或权限受阻

- 降级到：
  - 本地定点样本验证
- 必须补：
  - provenance
  - provider friction 说明

### 场景 3：缺 Level-2 权限

- 降级到：
  - `future_only`
- 不回填：
  - 任何伪字段
- 不生成：
  - 假定可执行合同

## 四、当前中止条件

- 如果有人提议：
  - 顺手把 `Level-2` 也纳入当前 runtime 合同
- 当前默认结论：
  - `中止`
- 原因：
  - 仓内无 fresh-run 实证
  - 成本/权限边界未闭合

## 五、一句话口径

- 当前 `A_REQ_001` 的正式可执行输入只到：
  - `daily`
- 分钟级只到：
  - `带 provenance 的样本层`
- Level-2 只到：
  - `future_only`
