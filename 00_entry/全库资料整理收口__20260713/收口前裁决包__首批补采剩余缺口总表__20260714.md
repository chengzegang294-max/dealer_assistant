## 用途

- 这份总表只负责把首批补采 `4` 个对象在“收口前”还剩什么缺口一次写清。
- 当前目标不是继续发散补材料，而是把：
  - 已补到哪
  - 还差哪一刀
  - 哪些属于硬阻塞
  - 哪些只是尾部增强
  固化成统一裁决口径。

## 当前总裁决

- 首批补采的剩余缺口已经从“大范围不确定”收缩为：
  - `batch_145` 的更贴近 `Market Profile / Initial Balance` 原始图例或源码段
  - `batch_146` 的更完整原作者 Pine 源码段与参数区块
  - `batch_148` 的更强校验记录或结构真值增强
- `batch_147` 的真实 `5m/60m` 小样本实物已经通过外部历史分钟包吸收闭合
- `batch_145 / batch_146 / batch_148`
  - 当前都属于可继续补强、但已不再阻塞“口径收口”的尾部缺口
- 因而当前最稳的后续顺序是：
  - 先用本总表把首批尾口复核清楚
  - 再接 `MFLOW / INSTB` 的多AI主负责人裁决
  - 然后再正式切 `方案B`

## 分层判断

### 一、硬门槛缺口

- 当前无未闭合的首批补采硬门槛。
- `batch_147`
  - 已通过外部历史分钟包补件完成闭合。

### 二、软门槛缺口

- `batch_145`
  - 已经从“只有历史 recovered”推进到“相邻平台页 + 同主题 Initial Balance 页 + 结构化公式摘录页 + 2-period 原始 phrasing 确认 + 图例包 + 经典 glossary 图例 + `CBOT handbook` 原始体系线索”。
  - 当前问题是证据强度还不够硬，不是没有入口；剩余缺口已缩到更完整原始扫描图示或源码段。
- `batch_146`
  - 已有结构化公式摘录页，且 `GainzAlgo / AG Pro` 双原作者页都已补到 detailed methodology，并见到源码首屏。
  - 当前问题已经收缩为：仍缺更完整 Pine 源码正文、参数截图或更硬默认值证据；另已补 `AGPro family invite-only / Source code disabled` 访问边界说明。
- `batch_148`
  - 第二只 seed 已落最小真实弱证据，且已跑出 `semi_auto` stub 输出，并已补更强校验记录页。
  - 当前问题是还没补后续是否继续降人工依赖的判断说明或更强结构真值增强，不是缺基本结构。
