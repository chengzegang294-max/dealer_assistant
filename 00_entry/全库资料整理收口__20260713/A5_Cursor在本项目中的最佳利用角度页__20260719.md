# A5 Cursor 在本项目中的最佳利用角度页

更新时间：2026-07-19

## 一、用途

- 本页只做：
  - 把
    `Cursor`
    在当前项目里的最佳使用角度正式冻结
- 本页不做：
  - 重新分配主负责人
  - 重新改写
    `Trae`
    的执行角色
  - 把
    `Cursor`
    包装成金融真值裁判

## 二、当前总判断

- 当前最适合把
  `Cursor`
  当成：
  - `编码向统筹与审校器`
- 当前不适合把
  `Cursor`
  当成：
  - 多家 AI 讨论主持人
  - 金融结论最终裁判
  - 长主线唯一执行者

## 三、最值得利用的 6 个角度

### 3.1 角度 1：跨文件一致性审校

- 最适合让
  `Cursor`
  去做：
  - 找字段冲突
  - 找点击流前后不一致
  - 找状态链是否有断点
  - 找上位合同与下游细化页是否口径漂移
- 当前这是它最值钱的地方之一，
  因为它更像：
  - 快速扫仓审校器

### 3.2 角度 2：实现前组件拆解

- 最适合让
  `Cursor`
  去做：
  - 把正式页压成前端组件树
  - 列出 props / state / event contract
  - 判断哪些对象该共区、哪些不该拆页
- 这类任务非常像：
  - 编程前的结构化拆解

### 3.3 角度 3：类型/字段合同检查

- 最适合让
  `Cursor`
  去做：
  - 统一字段名
  - 统一必填 / 可选 / 禁填
  - 检查是否缺主键或绑定字段
  - 提前发现未来实现时最容易打架的字段

### 3.4 角度 4：实现方案 A/B 对照

- 最适合让
  `Cursor`
  去做：
  - 两种组件实现结构对比
  - 两种状态管理方式对比
  - 两种页面拆分方式对比
- 但当前前提是：
  - 题目必须收窄
  - 不让它泛谈产品梦想

### 3.5 角度 5：代码评审与回归风险扫描

- 最适合让
  `Cursor`
  去做：
  - 看 diff
  - 找实现是否偏离合同
  - 找边界遗漏
  - 找哪些测试或验收点最该补
- 当前这类工作非常贴合：
  - 编程 AI
    的优势

### 3.6 角度 6：实现前阻塞清单

- 最适合让
  `Cursor`
  去做：
  - 现在要真做前端，
    还缺哪些合同
  - 哪些页已经够实现
  - 哪些页还停在概念层
  - 当前一手最短实现链是什么

## 四、当前不该把 Cursor 用在哪

- 当前不该让
  `Cursor`
  主做：
  - 多AI讨论发起与主持
  - 金融有效性最终裁决
  - 开放式产品方向大讨论
  - 需要长链执行与大面积回填的连续收口
- 原因不是它不能参与，
  而是：
  - 这些地方它的性价比不高
  - 更容易空讲或漂移

## 五、最推荐的调用模板

- 当前最推荐把
  `Cursor`
  叫来做的题型是：
  1. `请检查这几页的字段/状态/点击流是否互相冲突`
  2. `请把这套合同压成实现前组件树与接口表`
  3. `请比较两种实现结构，给出编程角度推荐`
  4. `请对这批改动做代码审校，找偏离合同的点`

## 六、对当前 A股 P0 的直接建议

- 当前
  `A股 P0`
  这条线最适合调用
  `Cursor`
  的地方是：
  - 首页事件卡模板页、
    四卡页、
    主工作区页
    之间的字段与点击交接一致性检查
  - 下一手
    `B`
    / `C`
    的实现前阻塞差异对照
  - 若要开始前端，
    让它先压组件树与接口合同

## 七、一句话口径

- 当前最准确的一句话是：
  - `Cursor`
    在本项目里最值钱的用法，
    不是当讨论主持人，
    而是当
    `编码向统筹与审校器`
    来用：
    查一致性、
    压组件树、
    做实现对照、
    看回归风险。
