## 四、当前最像什么样的失效

## 4.1 第一高频失效：波动失控型

- 当前更像出现于：
  - 高波动、
    高噪音、
    事件拉扯很强的时候

- 典型表现：
  1. 资金活跃度看起来还亮，
     但边界反复穿越
  2. 强度并没有稳定转成可延续推进
  3. 触发后很快进入
     `乱跳`
     与
     `来回回收`

- 当前默认处理：
  - `先降权`
  - 污染更重时，
    `回观察位`

## 4.2 第二高频失效：事件退潮型

- 当前更像出现于：
  - 事件窗口后，
    热度影子还在，
    但不再配继续当动作触发器

- 典型表现：
  1. 事件热度先走，
     资金跟随开始衰退
  2. 触发逻辑不再稳定延续
  3. 还能解释背景，
     但已经不该继续推动作

- 当前默认处理：
  - `先降级职责`
  - 从
    `触发层`
    退回
    `过滤层 / 背景说明`

## 五、当前更适合接哪类风险约束语言

- 从
  `NFTRADEZ`
  当前优先借用的，
  不是交易术语，
  而是这类边界口径：

1. `逻辑未坏，但当前先降权。`
   - 对应：
     `波动失控型`
2. `当前先退一层职责，不再继续当触发依据。`
   - 对应：
     `事件退潮型`
3. `当前噪音过大，先回观察位。`
   - 对应：
     强污染状态

- 当前不写成：
  - `打板资金一弱就直接退出`
  - `打板资金一强就默认加权`

## 六、当前更适合接哪类 explain / review 骨架

- 从
  `Smile_SMC`
  当前更适合借的是：
  - `发生了什么 -> 为什么降级 -> 现在归到哪一类`
    这种 review 骨架

- 当前对
  `打板资金`
  更适合的解释模板是：

1. `发生了什么`
   - 这次资金活跃确实出现，

2. `为什么降级`
   - 因为当前更像

     或
     `事件退潮型`
3. `现在归到哪一类`
   - 从
     `触发层`
     降到
     `过滤层`
     或
     `回观察位`

## 七、当前处理动作建议

| 当前情形 | 当前更适合的处理动作 | 备注 |
| --- | --- | --- |
| 高波动乱跳但逻辑未完全坏 | `先降权` | 不急着升级成退出 |
| 事件窗口退潮，触发不再稳定 | `先降级职责` | 从触发退回过滤 |
| 噪音过大、边界连续穿越 | `回观察位` | 先承认信号污染 |
