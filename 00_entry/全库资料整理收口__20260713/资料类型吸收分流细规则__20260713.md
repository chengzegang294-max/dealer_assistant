# 资料类型吸收分流细规则

更新时间：2026-07-13

## 作用

- 这份规则页只回答一件事：
  - 不同资料类型进入仓库后，到底该按哪一种力度处理：
    - `只吸收摘要`
    - `必留 raw`
    - `可直接开 batch`
    - `archive_only/reference_only`
- 它是 `最后一轮资料收集拆包路径清单__20260713.md` 的细化页。

## 先判四类结论

### 1. `只吸收摘要`

- 含义：
  - 原件可以不长期挂在主阅读链
  - 但必须把核心信息吸收到正式说明页
- 典型结果：
  - 摘要卡
  - 状态表
  - 去向表
  - glossary / mapping note

### 2. `必留 raw`

- 含义：
  - 原件本体必须保留在 `00_raw_snapshot/`
  - 不能只留一张摘要卡就删掉
- 典型结果：
  - 原文摘录
  - 导出稿
  - 原图/截图
  - 页面正文摘录

### 3. `可直接开 batch`

- 含义：
  - 这类材料已经值得形成独立批次闭环
  - 需要 `README / manifest / provenance / execution card / artifact index`
- 典型结果：
  - 新建 `10_source_library_archive/<batch>/`

### 4. `archive_only/reference_only`

- 含义：
  - 只保留历史价值或参考价值
  - 不进入当前默认主阅读链
- 典型结果：
  - 历史镜像回链
  - reference note
  - 不继续对象化

## 判定优先级

- 先问：
  - 这份资料是不是当前仓里唯一或关键原始证据
- 再问：
  - 它有没有稳定复用价值，而不是一次性浏览
- 再问：
  - 它是不是已经能支撑一个独立补采/吸收任务
- 最后才问：
  - 要不要继续对象化或进入 second-hop

## 三个直接判法

### 一、什么时候只能“只吸收摘要”

- 满足任一情况即可优先摘要：
  - 原件信息密度很低
  - 内容大部分是重复表述
  - 关键结论已经能在一张状态表里固定
  - 原件本身不是关键证据，只是解释材料
- 典型对象：
  - 去向表
  - 主题簇映射
  - 版本对照表
  - 统一说明页

### 二、什么时候必须“必留 raw”

- 满足任一情况就必须留 raw：
  - 这是唯一原始证据
  - 后续可能要回查原文措辞
  - 存在截图、导出稿、参数页这类不可逆损失
  - 当前只是先做弱证据/历史回收，不宜提前压扁
- 典型对象：
  - 网页正文
  - 视频导出稿
  - 图像证据
  - 样本 csv/json/tsv
  - 手工 seed

### 三、什么时候可以“直接开 batch”

- 满足以下组合更适合直接开 batch：
  - 已有一个明确对象或方法名
  - 当前缺口不是一句备注能解决
  - 需要持续补证
  - 后续会有多份 raw / note / index 一起增长
- 典型对象：
  - `batch_145 ~ batch_148` 这类补证批
  - 新参考系统吸收批
  - 原件量大、需要 provenance 闭环的专题批

## 当前项目里的直接裁决样例

### 样例 1：`NFTRADEZ` 导出稿

- 当前裁决：
  - `必留 raw`
  - 再叠加：
    - 主题簇表
    - 资产落点映射
    - 字段抽取模板
- 原因：
  - 导出稿是方法参考包的原始证据
  - 但 repo-global 真值不需要把每篇全文重写进总台账

### 样例 2：`Smile_SMC` 截图 raw

- 当前裁决：
  - `必留 raw`
- 原因：
  - 截图是关键证据位
  - 不能只留下文字总结

### 样例 3：`batch_145 / batch_146` 网页补证

- 当前裁决：
  - `可直接开 batch`
  - 且 batch 内必须：
    - `必留 raw`
- 原因：
  - 这些页面直接服务定义/参数补证
  - 不能只在台账上说“已经看过”

### 样例 4：`batch_147` provider/降级说明

- 当前裁决：
  - 说明页本身是：
    - `只吸收摘要`
  - 但未来真实 `60m/5m` 样本到位后：
    - 样本实物必须：
      - `必留 raw`

### 样例 5：`batch_148` 第二只 seed

- 当前裁决：
  - seed 脚手架说明：
    - `只吸收摘要`
  - `601991_SH_structure_seed_v1.tsv`：
    - `必留 raw`
- 原因：
  - 说明页负责讲口径
  - seed 文件本体才是可验证输入

## 当前不允许的误判

- 不把“看过网页”当成已经吸收 raw。
- 不把“有一张状态表”当成原件可以删。
- 不把 `csv / json / tsv / seed` 只记在 README 里而不保留文件本体。
- 不把营销页默认当 `必留 raw`，除非它含唯一参数或定义。
- 不把旧仓整目录直接搬成新仓主入口。
