# A5 第二日期批次吸收后最小回填页

更新时间：2026-07-30

## 一、这页用途

- 本页只做：
  - 冻结第二日期来源批次在 3 张图真正落盘后，
    最小需要回填哪些状态
  - 避免后面接入完成后，
    又回到“文件到了但 manifest/状态没改”的半成品状态

## 二、当前最小回填动作

- 第二日期 3 张图一旦真正落到批次目录，
  当前最小回填动作冻结为：

1. 更新 `manifest_v1.tsv`
   - 3 张图的 `status`
     从 `pending_absorb`
     改成 `absorbed`
   - `source_note`
     统一写成：
     `from 暂时存放 吸收`
2. 生成一份吸收结果摘要
   - 记录 3 张图是否都已存在
   - 记录 manifest 是否已更新
   - 记录当前是否可进入输入包验收
3. 再进入：
   - 输入包计划行回填
   - 单输入包验收
   - 两日期门槛重跑

## 三、当前先不强求什么

- 当前最小回填阶段，
  先不强求：
  1. README 立刻写长说明
  2. provenance 立刻补长段文字
  3. 增强页一起吸收

- 当前最关键的是：
  - `3 张图存在`
  - `manifest 状态已改`
  - `可进入下一步验收`

## 四、当前脚手架口径

- 当前运行时脚手架应至少做到：
  1. 校验 3 张图是否存在
  2. 更新 manifest 对应行
  3. 写出吸收结果 JSON

## 五、主负责人裁决

- 当前正式裁决为：
  1. 第二日期批次吸收后，
     先收最小回填，
     不再把时间花在补长说明上
  2. 当前最值钱的动作是：
     让第二日期样本最快进入现有验收链

## 六、一句话口径

- 第二日期批次一旦落到仓里，
  当前先做
  `manifest 改 absorbed + 生成吸收摘要`，
  然后立刻进输入包验收。
