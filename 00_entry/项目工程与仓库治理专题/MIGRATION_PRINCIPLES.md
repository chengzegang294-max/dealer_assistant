# Migration Principles

## 目的

- 这份文件规定什么内容可以迁入 `仓库根目录`，什么内容不可以。
- 目标是避免新目录再次变成旧目录那种“来源、产物、备份、临时文件混在一起”的状态。

## 可以迁入

- 当前主线明确依赖的最小对象包
- 当前运行时真正要执行的脚本、参数、样本、合同
- 当前必须持续维护的活跃文档
- 对某个活跃对象有直接续跑价值的最小证据副本
- 已完成筛选和说明的来源库材料小批次
- 已完成筛选和说明的冻结总结材料小批次

## 不可以直接迁入

- 整包来源库
- 整包冻结总结层
- 整包旧运行时目录
- 乱码文件、损坏备份、无说明副本
- 只为“以后也许有用”而先搬进来的材料

## 迁入前必须回答

1. 这个对象为什么必须进入新目录？
2. 它进入后属于哪个层级目录？
3. 它是活跃对象、运行时依赖、还是文档说明？
4. 它是否会和旧目录形成双真源？
5. 如果后续升级，谁是唯一维护位置？

## 迁入规则

1. 先定位置，再迁对象
2. 先迁最小集，不迁整包
3. 先写入口说明，再允许继续扩展
4. 同一对象只能有一个活跃维护位置
5. 旧目录默认冻结，不再和新目录并行扩写
6. 运行产物、生成脚本和备注说明必须一起成组进入，不允许只迁结果文件

## 受控归档层

- `10_source_library_archive`
  - 只接收按批次筛选后的来源库材料
  - 每一批都要写明：
    - 来源位置
    - 迁入原因
    - 当前对象关联
    - 是否已去重
- `11_frozen_summaries_archive`
  - 只接收按批次筛选后的冻结总结材料
  - 每一批都要写明：
    - 原冻结位置
    - 当前是否仍有阅读价值
    - 是否存在活跃替代文档
    - 是否包含乱码或损坏风险
- 两层都不是旧仓库镜像，也不是默认收纳桶。

## 当前默认裁决

- `trading_analysis` 继续作为历史仓库保留
- `trading_assistant` 作为新的干净工作根目录
- 若未来要迁 `DY-R1 / KD_MTF_P0`，应优先迁“最小活跃对象包”，而不是复制旧目录全部背景材料

## 暂存规则

- 暂时拿不准是否该迁入的内容，先放 `99_inbox`
- 进入 `99_inbox` 不等于已经成为正式结构
- 只有完成分类和职责声明后，才允许从 `99_inbox` 转入正式目录

## 运行产物补充规则

- 任何 `csv / log / tester report / gif` 进入新仓库前，都要满足：
  - 能回指到生成脚本、EA、probe 或配置
  - 能说明当前作用
  - 能区分 `fresh_run` 和 `historical_recovered`
- 详细口径统一看：
  - `00_entry\ARTIFACT_NOTE_CONTRACT.md`
