# A股 P0 验证清单

更新时间：2026-07-11

## 用途

- 把 A 股 P0 当前尚未完全锁死、必须通过数据验证、原型验证或用户验证来确认的条目集中列出。
- 与 `00_entry/A股_P0_功能合同__20260711.md` 配套使用：
  - 功能合同只写已冻结条目
  - 本清单只写 `NEED_EVIDENCE`
- 避免把“还没验证”的口径误写成真值，也避免后续实现时忘记验证关键假设。

## 使用边界

- 当前适用于：
  - A 股 P0 合同收口后的验证阶段
  - 原型、数据脚本、线框、埋点、用户测试前的准备
- 当前不适用于：
  - 多市场扩展验证
  - 历史/在线数据总体架构验证
  - API、数据库、代码实现细节争论

## 验证项总表

### V01 量价异常阈值触发密度

- 当前假设：
  - `20日均量 1.8 倍 + 当日涨跌幅绝对值 > 4.5%` 适合作为 A 股 P0 的主阈值
- 为什么需要验证：
  - 若触发太多，首页事件流会过载
  - 若触发太少，系统会显得沉默
- 建议方法：
  - 用近一段 A 股历史数据跑离线统计
  - 观察每日触发数量、行业分布、持仓相关覆盖率
- 建议观察项：
  - 日均触发数
  - 高峰日触发数
  - 持仓相关事件占比
  - 误报样例与漏报样例
- 建议通过标准：
  - 先看是否落在一个可消费区间，再决定是否微调阈值

### V02 主力资金主触发口径

- 当前假设：
  - `主力资金` 适合作为首页主触发
  - `北向资金` 更适合作为增强标签
  - `融资融券` 不应进入首页主触发
- 为什么需要验证：
  - 主力资金阈值可能在牛/熊/震荡市表现不一致
  - 北向与主力的时效性和覆盖范围并不完全相同
- 建议方法：
  - 用不同市场阶段样本做分段统计
  - 对比主力资金、北向资金与后续事件价值密度
- 建议观察项：
  - 触发频次
  - 信号后续可解释性
  - 与次日或后续阶段表现的弱相关性
- 当前重点问题：
  - `连续2日`
  - `占成交额 > 3%`
  - 是否会在震荡市过吵

### V03 业绩预期差口径

- 当前假设：
  - `实际 vs 一致预期偏差`
  - 或 `同比显著变化`
  可以作为业绩事件触发条件
- 为什么需要验证：
  - 一致预期数据是否稳定可得，直接影响功能是否可落地
- 建议方法：
  - 先确认是否具备稳定一致预期口径
  - 若无，则设计降级方案
- 建议降级方向：
  - 降级为 `同比显著变化`
  - 或只生成简版提醒，不生成全字段解释卡

### V04 行业轮动阈值敏感度

- 当前假设：
  - `相对大盘偏离 + 成交活跃度放大`
  可以构成 P0 的行业/板块轮动事件
- 为什么需要验证：
  - 在普涨或普跌环境下，行业排名变化可能产生大量伪触发
- 建议方法：
  - 用历史样本观察行业轮动类事件在不同市场环境下的触发分布
- 建议观察项：
  - 普涨日是否过度触发
  - 普跌日是否过度触发
  - 是否真的能提供持仓解释增量

### V05 历史类比最小样本量

- 当前假设：
  - 第二层行业统计在 `样本数 >= 5` 时展示
  - `样本数 < 5` 时隐藏统计，仅保留第一层
- 为什么需要验证：
  - 样本过少容易误导
  - 样本门槛过高又可能长期没有统计可看
- 建议方法：
  - 对常见事件类型统计行业内近一年样本量分布
- 建议观察项：
  - 各事件类型的行业样本覆盖度
  - `N=5` 是否过松或过紧

### V06 影响推演文案理解

- 当前假设：
  - `方向 + 强度 + 常见路径 + 复查点`
  是 P0 最稳妥的解释模板
- 为什么需要验证：
  - 用户可能把“常见路径”误当成未来预测
  - 文案过长会拖慢决策
- 建议方法：
  - 对比两类原型：
    - 只有方向与复查点
    - 包含常见路径的完整模板
  - 做定性访谈或轻量 A/B 测试
- 建议观察项：
  - 用户是否把它理解为预测
  - 是否提升决策记录意愿
  - 是否增加过度交易冲动

### V07 移动端交互可用性

- 当前假设：
  - 移动端可以通过底部抽屉、固定底栏或等价方式，完成：
    - 阅读解释
    - 记录决策
- 为什么需要验证：
  - 在手机端，解释卡过长可能把决策入口压得太深
  - 键盘弹起也可能遮挡复查点或按钮
- 建议方法：
  - 做移动端低保真或可点击原型
  - 让测试用户完整走一遍：
    - 接收事件
    - 打开解释
    - 记录决策
    - 回看历史
- 建议观察项：
  - 决策入口是否被忽略
  - 底部抽屉是否拥挤
  - 键盘是否遮挡关键信息

### V08 “调仓”动作理解

- 当前假设：
  - `调仓` 指 `持仓内部切换，总仓位不变`
- 为什么需要验证：
  - 用户可能把 `调仓` 误理解成 `减仓`、`换股`、`观望后再说`
- 建议方法：
  - 在线框或原型测试中，观察用户是否正确理解动作定义
- 建议观察项：
  - 是否频繁误选
  - 是否需要 tooltip 或示例说明
