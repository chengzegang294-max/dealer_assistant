# A股 P0 离线验证产出落点说明

更新时间：2026-07-12

## 用途

- 提前定义首轮离线验证的脚本、结果页、统计表和历史产物应该落到哪一层。
- 避免真正开始跑时把临时脚本、统计表、结论页和历史产物混在一起。
- 保证后续验证资产既能被回看，也不会直接污染 repo-global 合同层。

## 使用边界

- 当前只定义 A 股 P0 首轮离线验证资产的推荐落点。
- 当前不强制创建目录，只先固定口径。
- 当前不处理：
  - 生产数据仓
  - 正式数据库
  - 长期运行 pipeline

## 资产分类

### A01 Repo 级入口文档

- 类型：
  - `REPO_GLOBAL`
- 推荐落点：
  - `00_entry/`
- 包含：
  - 功能合同
  - 验证清单
  - 验证任务单
  - 执行卡
  - 结论门槛
- 说明：
  - 只放固定入口与真值导航，不放大体量结果文件

### A02 首轮验证脚本

- 类型：
  - `WORKING`
- 推荐落点：
  - `02_runtime/<a_share_p0_validation_family>/`
- 包含：
  - 扫描脚本
  - 统计脚本
  - 结果汇总脚本
- 说明：
  - 谁执行它，就放到谁的 runtime 线下

### A03 单次验证结果页

- 类型：
  - `WORKING`
- 推荐落点：
  - `02_runtime/<a_share_p0_validation_family>/reports/`
- 包含：
  - `T01` 单项结果页
  - `T02` 单项结果页
  - 首轮汇总结论页
- 说明：
  - 属于当前工作线的重要输出，但还不是 repo-global 合同

### A04 统计表与中间产物

- 类型：
  - `ARCHIVAL`
- 推荐落点：
  - `12_tooling_runtime_archive/<validation_batch>/`
- 包含：
  - csv
  - tsv
  - log
  - 临时扫描快照
- 说明：
  - 大体量产物优先进归档层，不回灌到 `00_entry`

### A05 会话级临时中转

- 类型：
  - `TEMPORARY`
- 推荐落点：
  - `20_tools_workspace/<validation_batch>/scratch/`
  - 或当前工作线的临时子目录
- 包含：
  - 一次性命令回显
  - 临时筛选表
  - 试跑备注
- 说明：
  - 禁止长留根目录

## 默认回链要求

- 从 `00_entry` 的执行卡，能回到：
  - runtime 执行入口
  - 结果页
- 从 runtime 结果页，能回到：
  - 原始统计表
  - 对应输出模板
- 从归档层结果表，能回到：
  - 生成脚本
  - 结果页

## 不同资产不该放的地方

- 统计 csv 不进 `00_entry`
- 临时跑数备注不进主合同
- repo 级入口文档不塞进 `12_tooling_runtime_archive`
- 一次性 scratch 不默认留在根目录

## 当前推荐最小目录形态

```text
00_entry/
  A股_P0_功能合同__20260711.md
  A股_P0_离线验证执行卡__20260712.md
  A股_P0_离线验证结论门槛__20260712.md

02_runtime/<a_share_p0_validation_family>/
  run_*.py
  reports/
    T01_*.md
    T02_*.md
    first_round_summary.md

12_tooling_runtime_archive/<validation_batch>/
  *.csv
  *.tsv
  *.log
```

## 当前护栏

- 不为“找起来方便”把所有东西都堆到 `00_entry`
- 不让中间大表和合同层混层
- 不让一次性临时文件长期占住用户视野主路径
