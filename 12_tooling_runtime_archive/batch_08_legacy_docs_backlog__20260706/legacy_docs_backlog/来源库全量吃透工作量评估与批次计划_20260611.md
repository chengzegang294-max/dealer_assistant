## 2. 你要走的路线对应多少工作量

### 只扫库、不吃透

- 内容：目录扫描、文件打标签、去重、建立索引
- 估算：`2-4` 个工作日

### 扫库并吃透到“可分流”

- 内容：读完、归类、判断哪些已吸收/可重开/future bucket/仅保留来源库
- 估算：`8-15` 个工作日

### 扫库并吃透到“首批可执行重开”

- 内容：在上一步基础上，再形成首批可量化重开清单与最小实现计划
- 估算：`12-20` 个工作日

## 3. 为什么工作量会上升

- 来源库里有大量课程稿、规则壳、方法学文本，不是直接一眼就能变成字段。
- `00_大隐体系`、`00_交易系统书籍` 中有不少内容更像系统框架，需要先做“可量化 / 不可量化”切分。
- `02_原子化拆解文件` 虽然已原子化，但仍不等于已经完成字段实现和证据审计。
- 方案 B 已落地后，还要同步维护四份主文档和总索引，避免再次出现分层漂移。
