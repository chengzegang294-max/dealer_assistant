# N03 市场结构/突破质量资料整理说明

## 本目录定位

- 目标：只收 `BOS / CHOCH / failed breakout / close-confirmed / repaint audit`。
- 角色：条件收集，不直接进 gate。
- 红线：不把 ZigZag/未来函数包装成“马上可用的无重绘结构门控”。

## 已落盘文件

- `CHOCH-BOS-ICT__gist.pine`
  - 给了 fractal / pivot 两种结构识别模式。
  - 适合做“确认逻辑”审计。
- `BOS_CHOCH_Indicator__github.pine`
  - 把 BOS/CHOCH/FVG/Fib 混在一起。
  - 可作为反例，提醒我们要裁剪出本轮允许的边界。
- `Smart_Money_Structure__GainzAlgo__page_excerpt.md`
  - 高复杂度 open-source 结构框架样本。
  - 明确包含 CHOCH/BOS + volatility adaptation + MTF + volume confirmation。
- `Institutional_Market_Structure_BOS_CHoCH__algo_aakash__page_excerpt.md`
  - 中高复杂度结构定义页。
  - 明确把 `confirmed swings`、`close-confirmed break`、`extra confluence` 分层写开。
- `Regime_Adaptive_SMC__Dots3Red__page_excerpt.md`
  - 复杂 SMC 框架页。
  - 价值在于把 `confirmed pivots do not repaint` 与 `BOS/CHoCH inherit pivot delay` 同时写清。
- `N03_字段草案_v1.md`
  - 已把现有来源收成第一版字段草案。
  - 明确拆开定义层字段、审计层字段、越界内容。

## 当前判断

- 这类资料最重要的不是“信号多不多”，而是：
  - swing 点如何确认
  - break 用 wick 还是 close
  - 标签会不会后移
  - 结构点是否依赖未来 K 线
- `BOS_CHOCH_Indicator__github.pine` 虽然信息量大，但超出了本轮边界，因为它混入了 FVG/Fib。
- `CHOCH-BOS-ICT__gist.pine` 更适合用来拆“fractal delayed confirm”与“pivot confirm”的差别。
- `Smart_Money_Structure__GainzAlgo__page_excerpt.md` 适合拿来做“复杂框架怎样宣称 non-repainting”的审计样本，但不能反向定义我们的 N03 最小边界。
- `Institutional_Market_Structure_BOS_CHoCH__algo_aakash__page_excerpt.md` 适合当作“定义层与过滤层拆分”的清晰样本，尤其是把 `close beyond tracked level` 保留下来。
- `Regime_Adaptive_SMC__Dots3Red__page_excerpt.md` 适合当作“非重绘披露要写到对象级别”的样本：哪些 live 元素会变，哪些 confirmed pivots 最终稳定。
- `N03_字段草案_v1.md` 标明：当前已够做 v1，但仍未收集完全，且大多数复杂页仍不是源码级证据。

## 最小审计清单

- 是否允许 `wick touch` 就算 break。
- 是否要求 `close beyond level`。
- 是否用 `ta.pivothigh/ta.pivotlow` 或 fractal 逻辑，若使用则明确延迟确认根数。
- 是否出现“历史上看着很干净，但实时会移动/消失”的 ghost line 或重标记。
- 若带 FVG / Fib / order block，只把结构定义段保留，其余视为越界内容。
