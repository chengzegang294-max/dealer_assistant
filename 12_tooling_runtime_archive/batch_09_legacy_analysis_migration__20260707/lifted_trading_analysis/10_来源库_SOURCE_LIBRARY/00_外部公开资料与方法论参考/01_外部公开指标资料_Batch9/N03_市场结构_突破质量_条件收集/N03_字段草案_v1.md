# N03 字段草案 v1

## 定位

- 目标：把已收集的 `BOS / CHOCH / confirmed swing / close-confirmed / repaint audit` 资料收成字段草案。
- 使用边界：只做定义层与审计层，不直接当门控实现。
- 当前结论：N03 已经够做第一版字段草案，但**仍未收集完全**，而且很多脚本天然带延迟确认。

## 字段分层

- A层：定义层，可做结构事件标签
- B层：审计层，必须与定义层分开
- C层：越界层，本轮不吸收

## A层：定义层字段

| field_name | type | 含义 | 当前口径 | 主要来源 |
|---|---|---|---|---|
| `swing_mode` | string | 摆点确认方式 | `pivot` / `fractal` / `custom` | CHOCH-BOS-ICT / Dinkelfras |
| `swing_left_bars` | int | 左侧确认根数 | 仅记录，不预设统一默认值 | pivot/fractal 样本 |
| `swing_right_bars` | int | 右侧确认根数 | 仅记录，不预设统一默认值 | pivot/fractal 样本 |
| `swing_high_confirmed` | int | 是否出现已确认 swing high | 只认确认后的 swing | 多来源一致 |
| `swing_low_confirmed` | int | 是否出现已确认 swing low | 只认确认后的 swing | 多来源一致 |
| `break_confirmation_mode` | string | 结构突破确认方式 | `close` 或 `wick`；Dots3Red 已补到 `conf_mode="Close"` 样本 | Dinkelfras |
| `break_level_price` | float | 本次被突破的结构价位 | tracked structure level | algo_aakash |
| `bos_event` | int | 结构延续突破事件 | 与 prevailing direction 同向 | 多来源一致 |
| `choch_event` | int | 结构切换事件 | 与 prevailing direction 反向 | 多来源一致 |
| `structure_direction` | string | 当前结构方向 | `bullish/bearish/neutral` | 多来源归纳 |
| `structure_event_bar_close_confirmed` | int | 事件是否要求收盘确认 | `1=close beyond level` | Dinkelfras / algo_aakash |

## B层：审计层字段

| field_name | type | 含义 | 当前建议 |
|---|---|---|---|
| `pivot_confirm_delay_bars` | int | pivot/fractal 带来的确认延迟 | 必须显式披露；当前已有 `pivot_len=7` 与 `swingLen=10` 样本 |
| `confirmed_pivot_non_repaint` | int | confirmed pivot 是否最终稳定 | 可保留为对象级披露 |
| `structure_label_inherits_pivot_delay` | int | BOS/CHoCH 标签是否继承 pivot 延迟 | 对 pivot-based 脚本通常为 1 |
| `current_bar_visuals_mutable` | int | 当前 bar 的 live 可视元素是否会变化 | 复杂 SMC 脚本需单独披露 |
| `close_vs_wick_risk_note` | string | close / wick 口径差异说明 | 用于审计说明，不直接策略化 |
| `future_leak_risk_flag` | int | 是否可能含 zigzag / future leak 风险 | 一旦不确定先标 1 |
| `extra_confluence_used` | string | 是否附加 displacement / EMA / volume / HTF | algo_aakash 已补到 4 因子样本；仅做审计，不混进定义层 |
| `source_complexity_tier` | string | 来源复杂度 | `minimal/medium/complex` |

## C层：本轮越界内容

- `FVG`
- `order block`
- `premium/discount`
- `Fib`
- `regime adaptation`
- `HTF overlay`
- `volume scoring`
- `EMA momentum confirmation`

这些经常和 BOS/CHoCH 同页出现，但都不属于当前 N03 最小定义层。

## 当前建议的最小事件逻辑

- `swing_high_confirmed` / `swing_low_confirmed`
  - 先确认摆点
- `break_confirmation_mode`
  - 明确是 `close` 还是 `wick`
- `bos_event`
  - 价格突破已跟踪结构位，且方向与现有结构一致
- `choch_event`
  - 价格突破已跟踪结构位，且方向与现有结构相反

## 审计红线

- 不得把 `confirmed pivot 不重绘` 误写成“信号实时无延迟”。
- 不得把 `wick break` 和 `close break` 混成同一个事件。
- 不得把带 FVG / order block / Fib 的复合脚本直接宣称为 N03 最小实现。
- 若来源只写 `non-repainting`，但没说清对象是谁，就不能给高置信度。
- `algo_aakash` 的 displacement / EMA / volume / HTF 以及 Dots3Red 的 regime / OB / FVG，都只能作为过滤层或审计层，不得回写成定义层字段。

## 未收集完全备注

- 目前大多数 TradingView 结构页仍是正文摘录，不是源码级证据。
- `Regime-Adaptive SMC` 虽然把对象级 repaint 行为写得很好，且已补到 `pivot_len=7`、`conf_mode=Close/Wick`、`smooth_len=6`，但仍缺原始源码页来核：
  - live pivot 更新时机
  - confirmed pivot 固化时机
  - BOS/CHoCH 标签刷新时机
- `Institutional Market Structure BOS and CHoCH` 已补到 `ta.pivothigh/low`、`swingLen=10`、`displacement > 1.2x ATR` 与 4 因子 confluence，但还没核清 displacement filter 是事件前过滤、事件后评分，还是纯展示层。
- `CHOCH-BOS-ICT__gist.pine` 提供了 fractal 与 pivot 两种模式，但还需要后续单独整理两者的延迟差异表。
- 当前还没系统补齐 failed breakout 的对象级字段，因此 `failed_breakout_event` 暂不进入 v1。

## 当前可执行裁决

- A层字段可进入研究侧结构标签草案。
- B层字段必须和定义层一起记录，不能省略。
- C层内容继续留在来源说明，不并入当前 N03 最小边界。
