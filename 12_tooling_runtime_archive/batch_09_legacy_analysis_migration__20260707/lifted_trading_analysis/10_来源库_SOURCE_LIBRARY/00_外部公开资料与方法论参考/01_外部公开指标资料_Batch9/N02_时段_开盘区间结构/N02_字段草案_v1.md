# N02 字段草案 v1

## 定位

- 目标：把已收集的 `session / opening range / initial balance / acceptance outside range` 资料收成可映射字段。
- 使用边界：先服务于时段上下文和研究标签，不直接等同于完整 ORB 策略。
- 当前结论：N02 已经具备第一版字段草案条件，但**仍未收集完全**。

## 字段分层

- A层：opening range / session 核心字段
- B层：IB 与 acceptance 条件字段
- C层：统计面板和策略说明，不进入当前最小字段层

## A层：可先落盘字段

| field_name | type | 含义 | 当前口径 | 主要来源 |
|---|---|---|---|---|
| `session_id` | string | 当前会话标识 | 如伦敦/纽约/自定义窗口 | README / USER_GUIDE |
| `session_timezone` | string | 会话时区 | 必须单独落盘，避免 DST 偏移 | joveteo ORB |
| `opening_range_window_minutes` | int | OR 建立窗口时长 | 常见 30/60/90/120 分钟 | README / USER_GUIDE |
| `opening_range_high` | float | 开盘区间高点 | OR 建立窗口内最高价 | joveteo ORB |
| `opening_range_low` | float | 开盘区间低点 | OR 建立窗口内最低价 | joveteo ORB |
| `opening_range_mid` | float | 开盘区间中值 | `(ORH + ORL) / 2` | joveteo ORB |
| `opening_range_width` | float | 开盘区间宽度 | `abs(ORH - ORL)` | joveteo ORB |
| `opening_range_width_pct_open` | float | OR 宽度相对开盘价比例 | `or_range / session_open_price` | joveteo ORB |
| `session_open_price` | float | 当前会话开盘价 | 用于 width threshold 等判定 | joveteo ORB |
| `opening_range_defined` | int | OR 是否已完成建立 | 会话结束后 OR 高低点已固定 | joveteo ORB |
| `or_break_high` | int | 是否突破 OR 高点 | 可按 close 或 high/low 触发源区分 | joveteo ORB |
| `or_break_low` | int | 是否突破 OR 低点 | 可按 close 或 high/low 触发源区分 | joveteo ORB |
| `first_break_direction` | string | 首次突破方向 | `up/down/none` | joveteo ORB |
| `target_trigger_source` | string | 目标命中判定源 | `close` 或 `high_low` | joveteo ORB |
| `width_error_day` | int | OR 过窄不可交易日 | 默认样本用 `< 0.2% of open` | joveteo ORB |

## B层：条件字段

| field_name | type | 当前建议 | 暂不直接固化原因 |
|---|---|---|---|
| `session_bias` | string | 可记录 `bullish/bearish/neutral` | bias 依赖实现细节，当前只拿到 OR 中值相对前值等样本 |
| `ib_high` | float | 第一小时高点 | IB 与 OR 时间窗口不一定一致，需分开记 |
| `ib_low` | float | 第一小时低点 | 同上 |
| `ib_range` | float | 第一小时区间宽度 | 同上 |
| `ib_break_direction` | string | IB 突破方向 | 需明确与 OR breakout 事件分离 |
| `ib_accept_2period` | int | 是否在 IB 外持续 2 个 30m 周期 | 已有较完整文章证据，且在多个 breakout 场景中被反复强调；仍不是源码实现 |
| `ib_regime_narrow_or_wide` | string | IB 属于窄/宽区间 | 语义已较清楚，但仍缺统一阈值与跨市场口径 |
| `ib_failed_breakout_event` | int | 突破后是否回到 IB 内 | 文章已明确 `failed breakout = price returns into IB`，先作为条件候选 |
| `custom_session_used` | int | 是否启用自定义 session | 可保留，但更多是配置元数据 |
| `session_ma_bias` | string | SMA/EMA/RMA/WMA/VWAP 所示会话偏向 | 目前来源混有可视趋势层，不宜直接固化 |

## C层：暂不进入当前字段

- `profit_days / loss_days / error_days` 统计面板
- `first breakout priority` 下的收益归因逻辑
- `options premium decay` 策略说明
- `vertical spread`、`swing trading application`
- 具体提醒、告警 UI、颜色面板

这些在来源里很多，但属于应用层/面板层，不是当前 N02 最小字段。

## 建议的最小事件逻辑

- 先建立 OR：
  - `opening_range_high`
  - `opening_range_low`
  - `opening_range_width`
- 再记录突破：
  - `or_break_high`
  - `or_break_low`
  - `first_break_direction`
- 最后单独记录可交易性：
  - `width_error_day`
  - `opening_range_width_pct_open`

## 审计备注

- `session_timezone` 必须显式保留，否则夏令时和跨市场对齐会漂移。
- `IB` 和 `ORB` 不能混成一个字段组；IB 默认偏第一小时定义，ORB 可自定义更短或更长窗口。
- `target_trigger_source` 若允许 `high/low`，则事件更敏感；若用 `close`，确认更稳。
- 统计面板里的“profit/loss/error day”是脚本作者定义的 outcome 层，不等于我们的最小字段层。
- `Initial Balance Breakout` 文章已补到 `Open-Drive / Rotational / Expansion / Gap Reversal` 四类 breakout 语义，可用于解释 `ib_accept_2period` 和 `narrow/wide`，但暂不单独落类型枚举字段。

## 未收集完全备注

- 目前 N02 主要来源仍集中在 joveteo ORB 一套资料和一篇 IB 文章，来源多样性还不够。
- `Initial Balance Breakout` 目前是定义文章，不是源码级证据，因此：
  - `ib_accept_2period`
  - `ib_regime_narrow_or_wide`
  - `ib_failed_breakout_event`
  目前只能作为条件字段。
- 还没系统补到：
  - London open / NY open 的多市场对照样本
  - session overlap / killzone 类时段页
  - failed opening range breakout 的对象级字段
- 当前还没把 ORB 的“目标线/胜率面板”拆成完全独立的研究层字段。

## 当前可执行裁决

- A层字段可以开始进入研究侧时段上下文字段草案。
- B层字段先作为定义增强和条件标签保留。
- C层内容继续只留在来源说明，不进入当前 N02 最小边界。
