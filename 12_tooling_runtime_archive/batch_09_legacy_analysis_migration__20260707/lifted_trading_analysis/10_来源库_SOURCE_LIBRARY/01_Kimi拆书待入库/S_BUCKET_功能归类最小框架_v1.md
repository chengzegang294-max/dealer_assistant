# S 桶功能归类最小框架

更新时间：2026-06-22

## 目标

- 不打乱当前按来源整理的真值结构。
- 在现有 `来源目录 -> 代表作 proof -> staging` 之上，新增一层“功能映射层”。
- 让后续组合不再只能按“来源”找材料，而能按“功能”找对象。

## 当前裁决

- 现阶段不直接改物理目录。
- 现阶段采用“双层结构”：
  - 第一层：`来源层`
    - 保留当前 `GROUP / S桶 / 子主题` 结构。
    - 负责审计、删源边界、回溯原始上下文。
  - 第二层：`功能层`
    - 只承载对象卡、功能标签、组合关系、成熟度判断。
    - 不承载原始 PDF 作为唯一真值。

## 为什么现在先做功能层

- 当前来源目录适合“吃透一批材料”，但不适合“跨来源拼策略”。
- 后续真正要复用的不是“某篇研报来自哪家券商”，而是：
  - 它能做什么
  - 需要什么输入
  - 输出是什么
  - 能和谁组合
  - 在什么条件下失效
- 因而现阶段应先把来源资料转成“功能对象”，再考虑更大的功能库重组。

## 最小功能桶

### 1. 按用途

- `选股`
- `择时`
- `执行`
- `风控`
- `组合构建`
- `归因解释`

### 2. 按处理层

- `原始数据`
- `特征/因子`
- `信号`
- `过滤器`
- `打分/排序`
- `仓位/资金管理`
- `执行约束`
- `复盘评估`

### 3. 按适用范围

- `日频`
- `高频/日内`
- `横截面`
- `时序`
- `单资产`
- `多资产`

### 4. 按成熟度

- `只读概念`
- `已摘公式`
- `已知输入输出`
- `可做 DIAG_ONLY`
- `可进入候选组合`
- `已验证不推荐`

## 当前三主题在功能层的优先映射

- `01_高频微观`
  - 优先映射到：`原始数据 / 特征 / 执行 / 归因解释`
  - 常见角色：`高频 alpha 线索`、`资金/机构动向跟踪`、`微观结构解释`
- `03_机器学习`
  - 优先映射到：`特征 / 标签 / 验证 / 模型 / 归因解释`
  - 常见角色：`模型框架`、`防过拟合`、`标签设计`、`因果/解释`
- `04_多因子`
  - 优先映射到：`因子库 / 组合构建 / 择时 / 风控`
  - 常见角色：`单因子测试`、`因子合成`、`因子择时`、`风格轮动`

## 进入功能层的最低门槛

- 不能只看标题和目录名。
- 至少要满足以下之一：
  - 已有明确公式或规则摘录
  - 已能说清输入和输出
  - 已能定位它更像 `alpha / filter / risk / execution / explanation`
- 只有达到这个门槛，才允许进功能卡片。

## 当前不做

- 不把原始 PDF 挪到新的“功能目录”下。
- 不把还没嚼碎的材料硬贴功能标签。
- 不把 `Kimi` 的第一轮归纳结果直接写成“已实现”。

## Kimi 在这层的角色

- 负责第一轮批量嚼碎：
  - 摘主旨
  - 提输入/输出
  - 提功能标签草案
  - 提可组合关系草案
- 不负责最终裁决：
  - 不负责删源边界
  - 不负责 proof 真值
  - 不负责“是否已可用”的最终判定

## 当前最顺推进顺序

1. 继续沿 `03_券商研报` 三主题做代表作 proof。
2. 对已 proof 的代表作逐批建立对象卡。
3. 先做“功能映射表”，后做“功能库入口”。
4. 等对象卡累计到足够密度，再决定是否单独生成功能目录。
