# Kimi 拆书待入库说明

## 作用

- 这个目录专门放：
  - `Kimi` 或其他外部 AI 的拆书整理产物
  - 人工复核后的结构化 `md`
  - 批次检查、吸收清单、对象候选清单
- 这里是“待入库区”，不是正式吸收后的来源库正文区。
- 正式吸收前，默认都视为：
  - `secondary_structured_note`
  - 不等同于原书原文
  - 不等同于源码级证据

## 你怎么放

- 一组书的正式产物，放进对应 `GROUP_XX` 子目录。
- 若同组产出多个 `part` 文件，就整组放一起，不要拆到根目录。
- 原始 `epub / pdf / txt` 默认不需要重复放进这里。
- 每组建议额外放一个 `manifest_v2.tsv`，用于后续量化预处理、字段抽取与批量校验。
- 只有在你准备删除外部源目录、但仍希望仓库内保留原始文件时，才把原始文件迁移到：
  - `GROUP_08_A股量化_数据研究__SOURCE_RAW`
- 这里优先放：
  - 最终 `md`
  - 人工备注 `md`
  - 批次检查或吸收清单

## 根目录这些文件是什么

- `README_放这里.md`
  - 本目录总说明，不放聊天回帖
- `Kimi拆书待入库_批次检查_v1.md`
  - 对整个待入库区做分组检查与优先级裁决
- `GROUP_05_GROUP_06_首批可吸收清单_v1.md`
  - `GROUP_05 + GROUP_06` 的第一轮吸收候选清单
- `GROUP_05_GROUP_06_统一吸收壳_v1.md`
  - `GROUP_05 + GROUP_06` 的统一吸收模板
- `GROUP_06_to_N02_对象候选清单_v1.md`
  - 从 `GROUP_06` 向 `N02` 继续推进的对象候选入口

## 当前归档纪律

- 根目录只放“跨组说明 / 批次检查 / 跨组吸收文件”。
- 每个 `GROUP_XX` 子目录只放该组自己的产物。
- 当前启用的“删源可用”组：
  - `GROUP_08_A股量化_数据研究/06_pdf_retained_cut_v2`
  - `GROUP_09_完善体系书库_切割产物`
- 不要再把长篇外部 AI 回复直接贴进 `README`。
- 若需要保留外部 AI 原话：
  - 优先单独落成检查文件
  - 或先提炼后再同步进长期主文档

## 后续归档原则

- 只有在完成：
  - 去重
  - 证据分层
  - 与现有来源库对齐
  - 写入主文档/索引
  之后，才会从这里转进正式来源库正文。
