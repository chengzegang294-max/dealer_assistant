## 1. 系统定位

本系统是一个 **A股纯多头中低频量化交易系统**，核心特征：

| 维度 | 设定 |
|------|------|
| 市场 | A股（沪深主板/创业板/科创板） |
| 方向 | 纯多头（T+1约束，无做空） |
| 频率 | 中低频（日线为主，分钟线为辅） |
| 选股 | 技术面+基本面双层过滤 |
| 架构 | 明朝内阁混合治理（五态动态切换） |
| 回测 | 强制CSCV-PBO<50%，诚实性优先 |

**核心理念**: *回测不是证明策略好，而是证明策略不坏。*

## 3. 核心数据流

### 3.1 日频交易循环（主要路径）

```
交易日 15:00 收盘后:
│
├─→ DataPipe.get_daily(ts_code, n_days=252)
│    └─→ AkShare / Tushare / 本地Parquet缓存
│
├─→ StockPriceSeries.to_volfac_input(lookback=60)
│    └─→ VolFacRawInput(close_60d=..., historical_vol_1y=...)
│
├─→ VolatilityFactor.calculate()
│    └─→ ObjectCardOutput(signal_strength, filter_action, size_scalar)
│
├─→ 所有对象卡输出汇总 → 内阁投票
│    └─→ 通过? → 生成奏折(Memorial)
│    └─→ 否决? → 输出ABORT编码
│
├─→ 风险管理：Kelly + VanTharp + VolTarget
│    └─→ 最终仓位 = 信号仓位 × size_scalar × vol_scalar
│
└─→ 次日 09:30 开盘执行（T+1约束，前日信号次日执行）
```

### 3.2 数据依赖矩阵

| 对象卡 | 所需数据 | 数据源 | 更新频率 | A股落地状态 |
|--------|---------|--------|---------|------------|
| VOLFAC | 日收盘价60日 | Tushare/AkShare | 日频 | ✅ proxy_quantizable_now |
| ATRATIO | Level-2逐笔 | 付费数据 | 实时 | ❌ 纯多头无效 |
| MFLOW | 大单资金流向 | Tushare/Choice | 日频 | ⚠️ needs_extra_data |
| CHZL_BSD | 缠论笔/段 | 日K线 | 日频 | ✅ 可编码 |
| BPB | K线形态 | 日K线 | 日频 | ✅ 可编码 |
| TKR7 | AO背离 | 日K线 | 日频 | ✅ 可编码 |
| VOLTARGET | VOLFAC输出 | 内部 | 日频 | ✅ 可编码 |

## 4. 五态治理模式速查

| 模式 | 触发条件 | 首辅 | 次辅 | 新仓 | 投票门槛 | Kelly | VanTharp |
|------|---------|------|------|------|---------|-------|----------|
| **常态** (NORMAL) | 默认 | 联合票拟 | 联合票拟 | ✅ | 3卡 | Half | 2% |
| **牛市** (BULL) | VOLFAC strength≥2 | 独断 | 顾问 | ✅ | 2卡 | Full | 3% |

| **危机** (CRISIS) | strength≤-2 | 停摆 | 停摆 | ✅(独裁) | 独裁 | 独裁 | 事后 |

## 6. 关键设计约束（不可违背）

1. **A股纯多头约束**: ATRATIO 等做空因子只能输出空信号，不得强行适配
2. **T+1执行约束**: 信号T日生成，T+1日执行，禁止日内回转
3. **小盘股冲击成本**: ADV≤3000万时单票仓位≤5%，冲击成本模型已冻结
4. **回测诚实性**: CSCV-PBO<50%为硬门槛，不能通过的因子直接废弃
5. **量化标注保守**: 只有常规A股数据可落地的保留 `proxy_quantizable_now`

## 7. 下一步路径建议

基于现有资产串联结果，最自然的推进顺序：

```
Phase 1（当前）: 对象卡逐个编码 + 数据管道落地
    → VOLTARGET（依赖VOLFAC，下一个最自然）
    → PERIOD_QUEEN（系统心脏，决定全局）

Phase 2: 策略组合 + 回测框架
    → StrategyBundle 抽象
    → CSCV-PBO 回测诚实性检验
    → 多因子组合（Alpha101池引入）

Phase 3: 实盘对接
    → 券商API（QMT/Ptrade）
    → 实时数据流
    → 治理控制台监控
```
