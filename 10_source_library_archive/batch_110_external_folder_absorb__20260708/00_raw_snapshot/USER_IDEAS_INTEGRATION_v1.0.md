## 第一部分：用户问题 2 — 小周期数据与仓库结构标准化

### 问题 2.1：需要保留小周期（15 分钟、5 分钟）吗？技术指标用得上吗？

**用户的原始问题**："需要保留小周期，像 15 分钟，5 分钟这种级别的图吗？技术指标用得上的吗？"

**答案：需要保留，但分场景使用。**

根据搜索验证和系统设计，小周期数据的使用规则如下：

#### 小周期数据的适用场景

| 时间框架 | 适用场景 | 在系统中的角色 | 数据存储优先级 |
|----------|----------|----------------|---------------|
| **日线（DAILY）** | 选股、趋势判断、缠论笔/中枢 | 核心框架 | **必须保留** |
| **周线（WEEKLY）** | 多周期对齐、KD MTF、宏观趋势 | 上下文注入 | **必须保留**（从日线合成） |
| **60 分钟（60MIN）** | 多周期 S/R（YTC）、缠论分钟级笔 | 精细执行 | **建议保留** |
| **15 分钟（15MIN）** | 日内突破确认、精细入场点 | 可选增强 | **有条件保留** |
| **5 分钟（5MIN）** | VP 成交量分布、高频波动率 | 可选增强 | **有条件保留** |
| **1 分钟（1MIN）** | 仅用于高频/日内策略 | 不纳入核心系统 | **暂不保留** |

#### 小周期数据的具体用途

```text
1. YTC（YTC 微结构）
   - 需要 60min 数据用于多周期 S/R 框架
   - 15min 数据用于精细入场点确认
   - 用途：当日线 S/R 确认后，15min 提供精确入场时机

2. VP（成交量分布）
   - 日频 VP：用于选股和趋势判断（核心）
   - 5min VP：用于日内 VA 突破确认（可选）
   - 用途：5min 数据可以更早发现 POC 偏离和 VA 突破

3. BPB（突破回调）
   - 日线：识别突破和回调（核心）
   - 15min：确认回调结束和入场时机（可选增强）
   - 用途：15min 可以更精确地判断 callback_depth 是否有效

4. TKR7（AO 背离）
   - 日线：常规背离判断（核心）
   - 60min：日内背离预警（可选）
   - 用途：60min 背离可以提前预警日线级别的反转

5. 缠论（CHZL）
   - 日线：笔/中枢/买卖点（核心）
   - 60min：分钟级笔用于精细止损（可选）
   - 用途：60min 的笔可以帮助优化日线级别的止损位置
```

#### 小周期数据的存储策略

```text
策略：分层存储，按需加载

第一层（常驻内存）：
  - 日 OHLCV（全 A 股，2018-2024）
  - 周线 OHLCV（从日线合成）

第二层（按需加载）：
  - 60min OHLCV（关注的标的，最近 3 个月）
  - 15min OHLCV（关注的标的，最近 1 个月）
  - 5min OHLCV（关注的标的，最近 1 周）

第三层（实时获取）：
  - 1min OHLCV（仅日内策略使用，不长期存储）

加载规则：
  - 当策略需要 15min 数据时（如 YTC 多周期 S/R），从磁盘按需加载
  - 当策略不需要时，不加载（节省内存）
  - 使用 Feature Store 缓存（按 symbol/timeframe/date 索引）

数据合成方法：
  - 日线 ← 从分钟级合成（验证一致性）
  - 周线 ← 从日线 resample('W') 合成
  - 60min/15min/5min ← 从 1min 合成或直接从数据源获取
```

#### 小周期数据的回测注意事项

```text
1. 数据对齐：
   - 分钟级数据必须与日线的 close 对齐（误差 < 0.1%）
   - 处理 A 股午间休市（11:30-13:00）导致的时间序列不连续

2. 避免未来信息泄露：
   - 分钟级策略只能使用当前 K 线及之前的数据
   - 不能在 9:30 使用 15:00 的数据

3. 计算性能：
   - 分钟级数据量是日线的 240 倍（1 日 = 240 根 1min K 线）
   - 使用 polars 替代 pandas 处理分钟级数据
   - 预计算并缓存常用指标（如 ATR、EMA、MACD）

4. 数据缺失：
   - 分钟级数据可能缺失（如停牌、数据商未提供）
   - 缺失时标记为 NaN，不强制填充（避免引入噪音）
```

```text
      "source": "tushare",
      "created_at": "2024-01-15",
      "version": "1.0",
      "hash": "sha256:..."

  - 检查缺失率（< 5%）

  - 使用 DVC（Data Version Control）管理大型数据文件

步骤 6：通知与同步（建议执行）
  - 更新数据可用性审计清单（DATA_AVAILABILITY_AUDIT.md）
  - 通知相关对象卡的实现者（如 MFLOW 需要新数据，通知 MFLOW 开发者）
```

## 第二部分：用户素材 1 — 私人投研管家的整合

### 用户的核心想法（来自视频笔记）

用户观看了一个关于"私人 AI 投研管家"的视频，核心想法包括：
- 不是预测涨跌，而是建立投资纪律和复盘框架
- 宏观环境分析：利率、汇率、流动性、风险偏好、政策 5 个维度
- 大盘看板：跟踪核心资产（沪深 300、恒生、黄金等）
- 资产配置监控：现金、股票、ETF、债券、黄金的比例
- 风险雷达：估值偏热、跌破均线、波动率放大等
- AI 投研日报：自动总结宏观、资金、主线
- 策略验证：记录 AI 判断与实际走势的偏差，修正模型

### 与现有交易系统的整合方案

```text
整合点 1：宏观环境分析 → 第一层（环境识别）的扩展

  现有系统：PeriodQueen 的七态是基于 A 股情绪周期的
  用户想法：增加宏观环境 5 维度（利率、汇率、流动性、风险偏好、政策）
  
  整合方案：
    - 在 PeriodQueen 对象卡中增加宏观环境评分字段
    - macro_score（0-100）= 五个维度加权平均
    - 当 macro_score < 30 → 无论情绪周期如何，整体偏向防御
    - 当 macro_score > 70 → 情绪周期允许时，整体偏向进攻
    - 这是一种"宏观过滤器"，与情绪周期形成双重过滤

  新增字段：
    pq_macro_score          FLOAT(0-100)  -- 宏观环境综合评分
    pq_macro_interest_rate  FLOAT         -- 利率环境评分
    pq_macro_exchange_rate  FLOAT         -- 汇率环境评分
    pq_macro_liquidity      FLOAT         -- 流动性环境评分
    pq_macro_risk_appetite  FLOAT         -- 风险偏好评分
    pq_macro_policy         FLOAT         -- 政策环境评分

整合点 2：大盘看板 → 选股层的扩展

  现有系统：选股层基于 MFLOW/VOLFAC/INSTB 等 A 股因子
  用户想法：跟踪核心资产（沪深 300、恒生、黄金等）的强弱
  
  整合方案：
    - 在 DataLoader 中增加跨资产数据加载能力
    - 新增 MARKET_BREADTH_P0_A 对象卡（市场宽度）
    - 跟踪核心资产的 RSI、趋势、成交量，判断整体市场强弱
    - 市场宽度差时，PeriodQueen 的 entry_min_votes 提高（更严格）

整合点 3：资产配置监控 → 风控层的扩展

  现有系统：风控层关注单票风险（Van Tharp 2%）
  用户想法：关注整体仓位结构（现金/股票/债券/黄金比例）
  
  整合方案：
    - 在 RiskArchitecture 中增加组合层面风控
    - 组合风险上限 = 6%（总风险，Van Tharp 扩展）
    - 资产集中度检查：单一资产类别 > 60% → 预警
    - 现金比例检查：现金 < 10% → 预警（无法应对突发风险）

整合点 4：策略验证 → 回测报告模板的扩展

  现有系统：回测产出绩效报告（夏普、回撤等）
  用户想法：记录 AI 判断与实际走势的偏差，修正模型
  
  整合方案：
    - 在回测报告中增加"判断偏差分析"章节
    - 记录每次交易的：预测方向 vs 实际方向、预测幅度 vs 实际幅度
    - 定期生成"偏差统计报告"：识别系统的系统性偏差（如总是过早入场）
    - 这与 KELLY 的自适应模式联动：偏差大时自动降级 Kelly 模式

整合点 5：AI 投研日报 → 自动化报告生成

  现有系统：回测框架是批量的，没有日报概念
  用户想法：每日自动生成投研日报
  
  整合方案：
    - 在 backtest_engine/performance/ 中增加 DailyReportGenerator
    - 每日自动运行：
      1. 计算 PeriodQueen 当前状态
      2. 计算宏观环境评分
      3. 扫描风险雷达信号
      4. 生成持仓诊断
      5. 输出 Markdown 格式日报
    - 日报模板见下文"回测报告模板"
```

## 第三部分：用户素材 2 — 因子大赛选手的洞察整合

### 用户的核心想法（来自视频笔记）

用户观看了第二届因子大赛选手的分享，核心洞察包括：
- 承认不确定性：猜不准市场，学会用 AI 处理不确定性
- 风险暴露而非预测：赚钱不靠预测涨跌，靠合理的风险暴露
- XGBoost 模型：树模型比神经网络更稳健，适合量价数据
- 因子切割：把波动效率分为上涨效率和下跌效率，提升信息增益
- 低相关因子：组合低相关因子是"免费的午餐"
- 数学基础：线性代数和概率统计是地基
- 亲手跑代码：不要只看书，要跑通模型

### 与现有交易系统的整合方案

```text
整合点 1：承认不确定性 → 系统设计的哲学基础

  现有系统：已明确"只读结构，不预测"的原则
  用户想法：进一步强调"猜不准市场"的量化世界观
  
  整合方案：
    - 在系统架构文档中明确声明：本系统不预测价格，只管理风险暴露
    - 对象卡的信号不是"预测涨/跌"，而是"结构确认后的风险暴露"
    - 例如：CHZL_BSD 的 3Buy 不是"预测涨"，而是"趋势结构确认后的风险暴露"
    - 这与 PeriodQueen 的"交易权限"而非"交易预测"一致

整合点 2：因子切割 → 因子工程的扩展

  现有系统：VOLFAC 的 id2_std_3m 是标准波动率
  用户想法：把波动率切割为上涨效率和下跌效率
  
  整合方案：
    - 在 VOLFAC 对象卡中增加因子切割字段：
      volfac_up_efficiency    FLOAT  -- 上涨效率（上涨日的波动率）
      volfac_down_efficiency  FLOAT  -- 下跌效率（下跌日的波动率）
      volfac_efficiency_ratio FLOAT  -- 上涨效率 / 下跌效率（>1 表示上涨更强）
    - 上涨效率与下跌效率的相关性通常较低 → 组合使用信息增益更高
    - 这与 GAS "因子切割论"一致

整合点 3：低相关因子 → 投票机制的优化

  现有系统：投票机制要求同一 function_bucket 最多贡献 2 票
  用户想法：低相关因子组合是"免费的午餐"
  
  整合方案：
    - 在投票机制中增加"因子相关性检查"：
      - 计算各对象卡信号的历史相关性矩阵
      - 若两个对象卡相关性 > 0.90 → 标记为冗余，只取其一
      - 若相关性 < 0.30 → 标记为互补，投票时给予额外权重
    - 例如：MFLOW（资金流向）和 VOLFAC（波动率）相关性低 → 互补
    - 例如：KD MTF 和 CHZL_BEICHI（都基于 MACD）相关性高 → 可能冗余

整合点 4：XGBoost 模型 → 未来扩展方向（机器学习模块）

  现有系统：当前系统全是规则驱动（确定性对象卡）
  用户想法：用 XGBoost 处理复杂量价数据
  
  整合方案：
    - 当前版本：暂不引入 XGBoost（保持系统确定性，避免黑盒）
    - 未来版本（v2.0）：在投票机制中引入 XGBoost 作为"元投票器"
      - 输入：各对象卡的信号、宏观环境、市场宽度
      - 输出：最终投票权重（动态调整各对象卡的权重）
      - 用途：不是替代对象卡，而是优化投票权重分配
    - 这符合用户的"AI 处理不确定性"的理念，但保持透明性

整合点 5：数学基础 → 开发者要求

  现有系统：未明确对编程 AI 的数学要求
  用户想法：线性代数和概率统计是地基
  
  整合方案：
    - 在 MASTER_PROGRAMMING_INSTRUCTION 中增加：
      "编程 AI 必须理解：
        - 线性代数（矩阵运算、特征分解）—— 用于多因子组合优化
        - 概率统计（假设检验、贝叶斯推断）—— 用于信号置信度评估
        - 时间序列分析（平稳性、自相关）—— 用于回测统计有效性"
    - 所有指标计算必须有数学公式推导，不能只调用现成库
```
