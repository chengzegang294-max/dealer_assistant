# 明朝内阁混合架构：动态制度切换方案 v1.0

> **本文档全部内容源于用户（仓库所有者）的想法，由 Kimi 整理完善。**
> 版本：v1.0 | 状态：方案设计阶段 | 核心设计：以明朝内阁为基底，按市场状态动态切换制度模式
> 设计理念："治大国若烹小鲜"——不同市况用不同治理模式，不僵化、不守一

### 1.2 常态模式的核心规则

```text
【常态模式触发条件】
  PeriodQueen 状态：POWER_TRANSITION 或 MACULAR_FADE
  市场特征：震荡、分化、无明确趋势
  系统目标：稳健运行，不犯大错

【常态模式的制度规则】

1. 内阁票拟规则：
   - 首辅（基本面）和次辅（技术面）必须联合票拟
   - 两者意见一致 → 直接生成票拟方案
   - 两者意见冲突 → 召开"内阁会议"，形成统一意见或分别陈述
   - 票拟方案必须包含：基本面依据 + 技术面依据 + 联合信心度

2. 六科审查规则（常态严格度：中）：
   - 吏科：检查对象卡成熟度（shell_only 的对象卡不能参与票拟）
   - 户科：Kelly 计算 + VolTarget 检查
   - 兵科：对象卡信号互锁检查（至少 3 个对象卡确认）
   - 刑科：Van Tharp 硬性上限检查（≤2%）
   - 工科：数据质量检查（无缺失、无异常）
   - 五科全部通过 → 盖印送批红
   - 任一科封驳 → 退回内阁修改

3. 皇帝批红规则：
   - 内阁票拟 + 六科通过 → 自动批红（用户不介入）
   - 皇帝可以"留中不发"（暂不决策，继续观察）
   - 皇帝可以"中旨"（绕过内阁和六科，直接下令）——慎用
```

## 二、动态切换：四种特殊模式

> 核心思想：不同市场状态，制度自动变形。不是"一套制度打天下"，而是"因时制宜、因地制宜"。

### 模式切换总览

```
│                                                                     │

│  ──────────────────────────┼───────────────┼────────────────────── │
│  ATTACK_SUSTAINED          │  内阁集权模式   │  六科放宽，快速通道     │
```

### 模式一：牛市——内阁集权模式（ATTACK_SUSTAINED / REMAINING_WARMTH）

> **理念**：牛市要的是效率，不是制衡。内阁权力扩大，六科审查放宽，允许"中旨"快速通道。
> **类比**：战时体制——首辅独断，六科从简，一切为了效率。

```
┌─────────────────────────────────────────────────────────────────────┐
│                      牛市：内阁集权模式                               │
│                                                                     │
│  皇帝（用户）                                                        │
│    │                                                                │
│    │ 保留权力，但日常不介入                                          │
│    ▼                                                                │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                   内阁（首辅主导）                             │   │
│  │                                                             │   │
│  │   首辅大学士（基本面+技术面合并）                              │   │
│  │        │                                                    │   │
│  │        │ 票拟权集中                                           │   │
│  │        │ （次辅有建议权，但首辅可独断）                         │   │
│  │        ▼                                                    │   │
│  │   ┌─────────────┐                                           │   │
│  │   │  票拟方案    │ ──────┐                                   │   │
│  │   └─────────────┘       │                                   │   │
│  │                         │ "中旨快速通道"                      │   │
│  │                         │ 六科从简审查                        │   │
│  │                         ▼                                   │   │
│  │              ┌─────────────────┐                           │   │
│  │              │  六科（从简审查） │                           │   │
│  │              │                 │                           │   │
│  │              │ • 只查 Van Tharp │                           │   │
│  │              │ • Kelly/VolTarget 放宽                      │   │
│  │              │ • 对象卡数量降为 2 个即可                    │   │
│  │              │ • 工科免检      │                           │   │
│  │              └─────────────────┘                           │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

**牛市模式的具体规则**：

```text
【触发条件】
  PeriodQueen 状态：ATTACK_SUSTAINED 或 REMAINING_WARMTH
  附加条件：连续 5 日上涨家数 > 2000 或 沪深 300 20 日涨幅 > 5%

【制度变形】

1. 内阁结构变形：
   - 首辅权力扩大：可以"独断票拟"，不需要次辅联署
   - 次辅角色降级：从"联合决策者"变为"顾问"（有建议权，无否决权）
   - 理由：牛市中技术面信号频繁且可靠，不需要基本面逐一确认

2. 六科审查变形（从简）：
   - 吏科：免检（所有对象卡都允许参与，包括 shell_only）
   - 户科：Kelly 用"激进模式"（full Kelly，不除以 2）
   - 兵科：对象卡数量要求从 3 个降为 2 个
   - 刑科：Van Tharp 上限从 2% 放宽到 3%
   - 工科：免检（数据质量不检查，默认通过）
   - 审查时间：从"逐笔审查"变为"批量审查"（每日收盘后统一审查）

3. 快速通道机制：
   - "中旨快速通道"：首辅可以直接生成"中旨"（不经过六科审查）
   - 快速通道条件：
     a) 标的已在持仓中（加仓）
     b) 对象卡信号 strength ≥ 9（极强信号）
     c) 过去 10 笔快速通道交易的胜率 > 60%
   - 快速通道的仓位限制：单次不超过 5%

4. 退出条件：
   - PeriodQueen 状态切换为 POWER_TRANSITION 或 MACULAR_FADE
   - 或：快速通道连续 3 笔亏损 → 自动关闭快速通道，回归常态审查
```

### 模式二：熊市——台谏监察模式（BEAR_LOOKING_UP / MACRO_CALIBRATION）

> **理念**：熊市要的是保命，不是赚钱。御史台和谏官前置，审查极严，宁可错过也不做错。
> **类比**：苛政时期——台谏权力极大，内阁小心翼翼，一切以稳健为上。

```

│                                                                     │
│  皇帝（用户）                                                        │
│    │                                                                │
│    │ 批红权，同时可接受台谏直达上奏                                  │
│    ▼                                                                │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │              台谏系统（前置监察）                              │   │
│  │                                                             │   │
│  │   御史台（事后纠劾）          谏官（事前预警）                │   │
│  │        │                            │                       │   │
│  │        │ 每笔交易后审查              │ 每笔交易前预警        │   │
│  │        │ 发现违规→纠劾              │ 发现风险→上谏        │   │
│  │        ▼                            ▼                       │   │
│  │   ┌─────────────┐            ┌─────────────┐              │   │
│  │   │  纠劾书      │            │  谏言书      │              │   │
│  │   └─────────────┘            └─────────────┘              │   │
│  │                                                             │   │
│  │  台谏独立于内阁，可直接向皇帝上奏                              │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                          │                                          │
│                          ▼                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                   内阁（谨慎票拟）                             │   │
│  │                                                             │   │
│  │   首辅（基本面）        次辅（技术面）                        │   │
│  │        │                      │                             │   │
│  │        │ 联合票拟，但必须      │                             │   │

│  │   • 吏科：仅允许 mature 对象卡                                │   │
│  │   • 户科：Kelly 用"保守模式"（quarter Kelly）                │   │
│  │   • 兵科：需 5 个对象卡同时确认                               │   │
│  │   • 刑科：Van Tharp 降到 1%                                   │   │
│  │   • 工科：逐笔数据质检                                        │   │
│  └─────────────────────────────────────────────────────────────┘   │
```

**熊市模式的具体规则**：

```text
【触发条件】
  PeriodQueen 状态：BEAR_LOOKING_UP 或 MACRO_CALIBRATION
  附加条件：连续 10 日下跌家数 > 2500 或 沪深 300 20 日跌幅 > 8%

【制度变形】

1. 台谏系统前置：
   - 御史台从"事后监察"变为"事后+事中监察"
     • 每笔交易执行后 1 小时内，御史台必须出具"纠劾书"
     • 纠劾内容：交易是否合规、是否违反策略、盈亏是否合理
   - 谏官从"不定期进谏"变为"每笔交易前进谏"
     • 每笔交易前，谏官必须出具"谏言书"
     • 谏言内容：当前市场风险点、该交易的潜在风险、是否建议暂缓
   - 台谏可以直接向皇帝上奏（绕过内阁和六科）
     • 触发条件：发现"重大风险"（如单票风险 > 3%、组合回撤 > 15%）

2. 内阁票拟变形（谨慎）：
   - 首辅和次辅必须"联署票拟"（任何一方不同意，就不能票拟）
   - 票拟方案必须包含"风险自评"（内阁自己对这笔交易的风险评估）
   - 票拟信心度 < 7 的一律不送六科，直接"留中不发"

3. 六科审查变形（加严）：
   - 吏科：仅允许 mature 对象卡参与，future_bucket 一律封驳
   - 户科：Kelly 用"保守模式"（quarter Kelly = f* / 4）
   - 兵科：对象卡数量要求从 3 个提高到 5 个
   - 刑科：Van Tharp 上限从 2% 降到 1%
   - 工科：逐笔数据质检（不允许任何数据缺失）
   - 审查方式：从"批量审查"变为"逐笔实时审查"

4. 交易限制：
   - 禁止开新仓（只允许减仓或持有）
   - 除非：谏官出具"无风险谏言" + 六科全通过 + 皇帝批红
   - 即使开新仓，仓位上限为 3%

5. 退出条件：
   - PeriodQueen 状态切换为 GESTATION 或 POWER_TRANSITION
   - 或：沪深 300 连续 5 日上涨，且成交量放大
```

### 模式三：震荡/过渡期——三省分权模式（GESTATION）

> **理念**：震荡市方向不明，需要严格制衡。三省严格分离，增加信息流转成本，避免冲动交易。
> **类比**：平稳时期——中书省草拟、门下省审议、尚书省执行，各司其职，互相牵制。

```
┌─────────────────────────────────────────────────────────────────────┐
│                      震荡期：三省分权模式                             │
│                                                                     │
│  皇帝（用户）                                                        │
│    │                                                                │
│    │ 御批（最终决策权）                                              │
│    ▼                                                                │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐          │
│  │   中书省     │───→│   门下省     │───→│   尚书省     │          │
│  │   基本面部   │    │   仓管/风控  │    │   技术面部   │          │
│  │              │    │              │    │              │          │
│  │ • 草拟诏令   │    │ • 审议封驳   │    │ • 六部执行   │          │
│  │ • 划定选股池 │    │ • 风险审查   │    │ • 具体交易   │          │
│  │ • 价值标准   │    │ • 仓位裁定   │    │ • 止损跟踪   │          │
│  └──────────────┘    └──────────────┘    └──────────────┘          │
│                                                                     │
│  三省严格分离：                                                      │
│  • 中书省不能直接下单（不越权）                                      │
│  • 尚书省不能修改诏令（只执行）                                      │
│  • 门下省不能提案（只审查）                                          │
│  • 诏令必须经过三省流转，不能跳过                                    │
└─────────────────────────────────────────────────────────────────────┘
```

**震荡期模式的具体规则**：

```text
【触发条件】
  PeriodQueen 状态：GESTATION
  附加条件：沪深 300 20 日振幅 > 10% 但涨跌幅 < 3%（震荡特征）

【制度变形】

1. 三省严格分离：
   - 中书省（基本面）草拟诏令 → 门下省（仓管）审议 → 尚书省（技术面）执行
   - 诏令必须经过三省流转，不能跳过任何一省
   - 尚书省（技术面）不能自行决定交易，必须等中书省诏令 + 门下省盖印

2. 中书省规则：
   - 每季度更新选股池（不能频繁调整）
   - 诏令必须包含：选股理由、价值标准、行业配置
   - 诏令有效期：30 天（过期必须重拟）

3. 门下省规则：
   - 对每笔交易进行"封驳审查"
   - 封驳后必须给出"修改意见"（不是简单否决）
   - 连续封驳 3 次同一标的 → 触发"标的冻结"（30 天内不再审查该标的）

4. 尚书省规则：
   - 六部分工明确：
     吏部：对象卡管理（只使用 mature 对象卡）
     户部：资金管理（Kelly half + VolTarget）
     礼部：信号规范（统一输出格式）
     兵部：交易执行（严格按诏令执行，不能擅自修改）
     刑部：止损追踪（触发止损立即执行）
     工科：数据管道（每日数据质检）

5. 仓位限制：
   - 单票仓位上限 8%
   - 总仓位上限 50%
   - 现金比例 ≥ 30%

6. 退出条件：
   - PeriodQueen 状态切换为 ATTACK_SUSTAINED（进入牛市）
   - 或：切换为 BEAR_LOOKING_UP（进入熊市）
   - 或：震荡持续超过 60 天 → 触发"系统复盘"，用户介入调整
```

### 模式四：极端/危机——皇帝独裁模式（EXTREME_VOL / HALT）

> **理念**：极端行情下，任何制度都太慢。内阁停摆，六科解散，台谏待命，一切由皇帝（用户）直接决策。
> **类比**：战时紧急状态——独裁官上任，一切为了 survival。

```
┌─────────────────────────────────────────────────────────────────────┐
│                      危机：皇帝独裁模式                               │
│                                                                     │
│  皇帝（用户）                                                        │
│    │                                                                │
│    │ 全面接管                                                        │
│    ▼                                                                │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                   独裁官（用户指定）                           │   │
│  │                                                             │   │
│  │   独裁官可以是：                                              │   │
│  │   • 首辅（基本面视角）                                        │   │
│  │   • 次辅（技术面视角）                                        │   │
│  │   • 六科中的某一科（如刑科/户科）                             │   │
│  │   • 用户亲自担任                                              │   │
│  │                                                             │   │
│  │   独裁官权力：                                                │   │
│  │   • 可以绕过所有审查直接决策                                   │   │
│  │   • 可以修改任何系统参数                                       │   │
│  │   • 可以一键清仓/一键满仓                                     │   │
│  │                                                             │   │
│  │   独裁官限制：                                                │   │
│  │   • 任期最长 10 个交易日                                      │   │
│  │   • 任期结束后必须提交"独裁报告"                               │   │
│  │   • 连续两次独裁 → 触发"系统大修"                              │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  内阁：停摆（首辅、次辅暂停票拟，转为顾问角色）                       │
│  六科：解散（审查职能暂停，改为"事后审计"）                         │
│  台谏：待命（发现极端风险时可直接向皇帝上奏）                         │
└─────────────────────────────────────────────────────────────────────┘
```

**危机模式的具体规则**：

```text
【触发条件】
  PeriodQueen 状态：EXTREME_VOL 或 HALT
  附加条件（满足任一）：
    a) 沪深 300 单日跌幅 > 7%
    b) 全市场跌停家数 > 500
    c) 波动率指数（VIX  equivalent）> 40
    d) 用户手动触发"紧急状态"

【制度变形】

1. 内阁停摆：
   - 首辅和次辅停止票拟
   - 转为"顾问角色"：可以向独裁官提供建议，但没有决策权
   - 顾问建议必须包含："如果我掌权，我会怎么做"（供独裁官参考）

2. 六科解散：
   - 六科的"事前审查"职能暂停
   - 转为"事后审计"职能：
     • 每笔独裁官的交易，六科在交易后 24 小时内审计
     • 审计报告直接提交皇帝
   - 若审计发现"重大违规"（如单笔亏损 > 10%），六科可以向皇帝上奏

3. 台谏待命：
   - 御史台和谏官不停止工作
   - 但职能从"审查"变为"情报收集"
   - 台谏可以向独裁官提供：市场风险情报、舆情情报、历史类比情报

4. 独裁官任命：
   - 由皇帝（用户）在危机触发时立即任命
   - 默认任命：首辅（基本面视角，适合"价值抄底"型危机）
   - 若危机是"流动性危机"（如 2015 年股灾）→ 任命户科（资金管理视角）
   - 若危机是"技术性崩盘"（如闪崩）→ 任命次辅（技术面视角）

5. 独裁官权限：
   - 可以一键清仓（全部卖出）
   - 可以一键满仓（全部买入）
   - 可以修改任何系统参数（如临时提高 Van Tharp 上限）
   - 可以暂停任何对象卡
   - 每笔交易不需要审查，但必须在 1 小时内记录"决策理由"

6. 独裁官限制：
   - 任期最长 10 个交易日
   - 任期结束后必须提交"独裁报告"：
     • 做了什么决策
     • 结果如何
     • 建议未来如何改进系统
   - 若独裁期间产生亏损 > 15% → 强制触发"系统大修"

7. 退出条件：
   - PeriodQueen 状态切换为非 EXTREME_VOL/HALT
   - 独裁官任期结束
   - 用户手动解除紧急状态
```

## 三、模式切换的触发与回退机制

### 3.1 自动切换规则

```text
【切换触发器】

触发器 1：PeriodQueen 状态变化
  • GESTATION → ATTACK_SUSTAINED → 切换为"内阁集权模式"
  • ATTACK_SUSTAINED → POWER_TRANSITION → 切换为"常态内阁模式"
  • POWER_TRANSITION → BEAR_LOOKING_UP → 切换为"台谏监察模式"
  • BEAR_LOOKING_UP → MACRO_CALIBRATION → 保持"台谏监察模式"
  • 任何状态 → EXTREME_VOL/HALT → 切换为"皇帝独裁模式"

触发器 2：技术指标异常
  • 沪深 300 单日涨跌幅 > 5% → 触发"模式审查"
    • 若当前是牛市模式 → 审查是否保持
    • 若当前是常态/震荡模式 → 可能切换为危机模式
  • 波动率指数（VIX equivalent）> 30 → 触发"模式审查"
  • 连续 5 日成交量 < 20 日均量 50% → 可能切换为震荡模式

触发器 3：系统绩效异常
  • 连续 5 笔交易亏损 → 触发"模式审查"
    • 若当前是牛市模式 → 可能强制切换为常态模式（快速通道关闭）
  • 组合回撤 > 15% → 触发"模式审查"
    • 若当前不是熊市模式 → 强制切换为台谏监察模式
  • 组合回撤 > 25% → 强制切换为皇帝独裁模式

触发器 4：用户手动触发
  • 用户可以随时通过控制台切换模式
  • 用户切换后，系统记录"手动切换原因"（用户必填）
```

### 3.2 模式回退（冷却期）

```text
【回退规则】

从集权模式回退：
  • 触发条件：快速通道连续 3 笔亏损
  • 回退动作：关闭快速通道，回归常态审查
  • 冷却期：3 个交易日（3 天内不能重新开启快速通道）

从台谏模式回退：
  • 触发条件：沪深 300 连续 5 日上涨，且谏官连续 3 天出具"无风险谏言"
  • 回退动作：台谏从前置变为后置，六科审查从加严变为常态
  • 冷却期：5 个交易日

从独裁模式回退：
  • 触发条件：任期结束 或 PeriodQueen 状态恢复正常
  • 回退动作：独裁官卸任，内阁复职，六科恢复审查
  • 冷却期：10 个交易日（10 天内不能再次任命独裁官）

模式切换日志：
  • 每次模式切换必须记录：
    - 切换时间
    - 切换前模式
    - 切换后模式
    - 触发原因（自动/手动）
    - 触发时的市场状态
    - 切换后的第一笔交易结果
```

### 4.1 内阁票拟接口（统一）

```python
class Cabinet:
    """内阁：负责票拟（联合提案）"""
    
    def __init__(self, regime_mode: str):
        """
        regime_mode: 当前制度模式
          - "normal": 常态内阁模式
          - "bull": 内阁集权模式
          - "bear": 台谏监察模式
          - "oscillation": 三省分权模式
          - "crisis": 皇帝独裁模式（内阁停摆）
        """
        self.regime_mode = regime_mode
        self.shoufu = FundamentalMinister()   # 首辅（基本面）
        self.cifu = TechnicalMinister()       # 次辅（技术面）
    
    def propose(self, symbol: str, objects: dict) -> dict:
        """
        票拟：生成交易提案
        根据 regime_mode 调整票拟规则
        """
        if self.regime_mode == "bull":
            # 牛市：首辅可以独断
            return self.shoufu.unilateral_propose(symbol, objects)
        elif self.regime_mode == "bear":
            # 熊市：必须联署，且信心度要求更高
            return self.joint_propose(symbol, objects, min_confidence=7)
        elif self.regime_mode == "oscillation":
            # 震荡期：中书省草拟，尚书省不能自行决定
            return self.zhongshu_propose(symbol, objects)
        else:
            # 常态：标准联合票拟
            return self.joint_propose(symbol, objects, min_confidence=5)
```

### 4.2 六科审查接口（统一）

```python
class SixDepartments:
    """六科给事中：负责审查"""
    
    def __init__(self, regime_mode: str):
        self.regime_mode = regime_mode
        self.departments = {
            "li": ObjectCardDepartment(),      # 吏科
            "hu": CapitalDepartment(),         # 户科
            "bing": TradingDepartment(),       # 兵科
            "xing": RiskDepartment(),          # 刑科
            "gong": DataDepartment(),          # 工科
        }
    
    def review(self, proposal: dict) -> dict:
        """
        审查票拟方案
        根据 regime_mode 调整审查严格度
        """
        if self.regime_mode == "bull":
            # 牛市：从简审查
            return self.simplified_review(proposal)
        elif self.regime_mode == "bear":
            # 熊市：加严审查
            return self.strict_review(proposal)
        else:
            # 常态/震荡：标准审查
            return self.standard_review(proposal)
    
    def simplified_review(self, proposal: dict) -> dict:
        """牛市从简审查：只查 Van Tharp"""
        result = {"verdict": "PASS", "stamp": "六科印", "restrictions": []}
        
        # 只查刑科（Van Tharp）
        xing_result = self.departments["xing"].check_van_tharp(proposal)
        if not xing_result["pass"]:
            result["verdict"] = "REJECT"
            result["reason"] = xing_result["reason"]
        
        # Kelly 用激进模式
        result["kelly_mode"] = "aggressive"  # full Kelly
        
        # 对象卡数量降为 2
        result["min_objects"] = 2
        
        return result
    
    def strict_review(self, proposal: dict) -> dict:
        """熊市加严审查：五科全查，标准提高"""
        result = {"verdict": "PASS", "stamp": "六科印", "restrictions": []}
        
        # 吏科：仅 mature 对象卡
        li_result = self.departments["li"].check_maturity(proposal, allow_shell_only=False)
        if not li_result["pass"]:
            result["verdict"] = "REJECT"
            result["reason"] = li_result["reason"]
            return result
        
        # 户科：Kelly 保守模式
        hu_result = self.departments["hu"].check_kelly(proposal, mode="conservative")
        if not hu_result["pass"]:
            result["verdict"] = "REJECT"
            result["reason"] = hu_result["reason"]
            return result
        result["kelly_mode"] = "conservative"  # quarter Kelly
        
        # 兵科：需 5 个对象卡
        bing_result = self.departments["bing"].check_objects(proposal, min_count=5)
        if not bing_result["pass"]:
            result["verdict"] = "REJECT"
            result["reason"] = bing_result["reason"]
            return result
        
        # 刑科：Van Tharp 降到 1%
        xing_result = self.departments["xing"].check_van_tharp(proposal, limit=0.01)
        if not xing_result["pass"]:
            result["verdict"] = "REJECT"
            result["reason"] = xing_result["reason"]
            return result
        
        # 工科：逐笔质检
        gong_result = self.departments["gong"].check_data_quality(proposal, strict=True)
        if not gong_result["pass"]:
            result["verdict"] = "REJECT"
            result["reason"] = gong_result["reason"]
            return result
        
        return result
```

### 4.3 模式切换控制器

```python
class RegimeModeController:
    """
    制度模式切换控制器
    根据 PeriodQueen 状态和市场指标，自动切换制度模式
    """
    
    def __init__(self):
        self.current_mode = "normal"  # 默认常态
        self.mode_history = []        # 模式切换历史
        self.cooldown_end = None      # 冷却期结束时间
    
    def check_switch(self, pq_state: str, market_data: dict, performance: dict) -> str:
        """
        检查是否需要切换模式
        返回：新模式 或 None（不切换）
        """
        # 检查冷却期
        if self.cooldown_end and datetime.now() < self.cooldown_end:
            return None
        
        # 根据 PeriodQueen 状态判断
        if pq_state in ["ATTACK_SUSTAINED", "REMAINING_WARMTH"]:
            new_mode = "bull"
        elif pq_state in ["BEAR_LOOKING_UP", "MACRO_CALIBRATION"]:
            new_mode = "bear"
        elif pq_state == "GESTATION":
            new_mode = "oscillation"
        elif pq_state in ["EXTREME_VOL", "HALT"]:
            new_mode = "crisis"
        else:
            new_mode = "normal"
        
        # 检查是否需要切换
        if new_mode != self.current_mode:
            # 记录切换
            self.mode_history.append({
                "timestamp": datetime.now(),
                "from": self.current_mode,
                "to": new_mode,
                "trigger": f"PeriodQueen={pq_state}",
            })
            self.current_mode = new_mode
            
            # 设置冷却期
            self.cooldown_end = datetime.now() + timedelta(days=3)
            
            return new_mode
        
        return None
    
    def manual_switch(self, new_mode: str, reason: str) -> bool:
        """
        用户手动切换模式
        """
        self.mode_history.append({
            "timestamp": datetime.now(),
            "from": self.current_mode,
            "to": new_mode,
            "trigger": f"MANUAL: {reason}",
        })
        self.current_mode = new_mode
        return True
```

## 六、总结：混合架构的核心优势

```text
1. 不僵化：不同市况用不同制度，不搞"一套制度打天下"

5. 有兜底：极端情况下皇帝独裁，确保系统不会失控
6. 有融合：以明朝内阁为核心，融合三省六部的制衡、台谏的监察、现代企业的高效
```
