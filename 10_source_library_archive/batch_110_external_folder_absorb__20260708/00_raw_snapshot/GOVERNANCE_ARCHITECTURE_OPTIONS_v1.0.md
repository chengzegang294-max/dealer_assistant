> **本文档全部内容源于用户（仓库所有者）的想法，由 Kimi 整理完善为可供选择的架构方案。**
> 版本：v1.0 | 状态：方案设计阶段 | 目标：提供 4 种不同风格的组织架构供用户选择
> 核心隐喻：技术面、基本面、仓管三者的关系，类比国家机器的三权分立与制衡

## 前言：为什么用"三权分立"来设计投资系统

用户的核心洞察：

> "技术面和基本面和仓管之类，三者可以互相制约讨论。类似法院和警察局和立法会。"

这个类比极其精准。一个投资系统的核心矛盾，与国家治理的核心矛盾是相通的：

| 国家治理问题 | 投资系统对应问题 |
|-------------|----------------|
| 立法会制定法律，但不能执法 → 避免立法者滥权 | 基本面说"这个有价值"，但不能直接下单 → 避免价值投资者盲目抄底 |
| 警察局执行法律，但不能自己立法 → 避免执法者独裁 | 技术面说"现在出现信号"，但不能无视估值 → 避免技术交易者追高风险股 |
| 法院审查一切，但不能立法也不能执法 → 避免司法者越权 | 仓管说"这笔交易风险太大"，一票否决 → 避免重仓单票导致爆仓 |

**三权分立的投资哲学**：
- **基本面** = 回答"**什么值得投**"（价值判断，立法权）
- **技术面** = 回答"**什么时候进出**"（时机判断，行政/执法权）
- **仓管/风控** = 回答"**能不能做**"（风险审查，司法/否决权）

三者互相独立、互相制约、缺一不可。任何一方独大都会导致系统崩溃：
- 基本面独大 → 死扛价值陷阱（如 2021 年后的中概互联）
- 技术面独大 → 追高风险股/频繁交易（如 ATR 通道突破在震荡市失效）
- 仓管独大 → 过度保守，永远空仓错过机会

## 方案 A：美式三权分立（Strict Separation of Powers）

> **理念**：三权严格分离，任何一方不能兼任另一方职能。决策链长，但制衡最强。
> **适合**：风险厌恶型投资者，追求稳健，宁可错过也不错。

### A.2 各部门职能详解

#### 立法会（基本面部）——"什么值得投"

```text
成员：A5 财报估值（郭永清）、A5 上市公司财报分析、行业研究员

权力：
  ✓ 划定选股池（全 A 股中哪些可以进入候选池）
  ✓ 制定价值标准（PE/PB/ROE 阈值、成长性要求）
  ✓ 行业配置规则（当前超配/低配哪些行业）
  ✓ 财报审查（季度更新，剔除财务造假/业绩暴雷标的）
  ✓ 对仓管部提出的"风险规则"有建议权（但无决定权）

限制：
  ✗ 不能直接下单交易（不能执法）
  ✗ 不能修改仓管的风险上限（不能干预司法）
  ✗ 技术面信号出现时，基本面只能"通过/否决"，不能"修改"

工作产物：
  - 选股池名单（每季度更新）
  - 行业配置权重表
  - 财报评分卡（每只股票的"基本面健康度"）
```

#### 警察局/行政机构（技术面部）——"什么时候进出"

```text
成员：CHZL_BSD、BPB、VP、TKR7、YTC、KD MTF、缠论体系

权力：
  ✓ 在选股池内生成买卖信号
  ✓ 计算止损/止盈位置
  ✓ 跟踪趋势状态（多周期对齐）
  ✓ 提出"交易申请"给仓管部审查

限制：
  ✗ 不能交易选股池外的标的（无立法权）
  ✗ 不能突破仓管设定的仓位上限（被司法审查）
  ✗ 信号被仓管否决后，不能强行执行

工作产物：
  - 交易申请单（标的、方向、价位、止损、对象卡依据）
  - 多周期对齐报告
  - 对象卡信号强度评分
```

#### 法院（仓管/风控部）——"能不能做"

```text
成员：Van Tharp 硬性上限、Kelly Criterion、Volatility Targeting、PeriodQueen

权力：
  ✓ 对每一笔交易申请进行风险审查
  ✓ 一票否决权（风险超标时无条件否决）
  ✓ 裁定最终仓位大小（Kelly + VolTarget 调制）
  ✓ 裁定是否进入"危机模式"（连续亏损后的保守状态）
  ✓ 对基本面的"行业配置权重"有审查权（若某行业权重过高，可要求调整）

限制：
  ✗ 不能自己生成交易信号（不能立法也不能执法）
  ✗ 否决必须给出明确理由（不能无理由否决）
  ✗ 连续否决 3 次以上，必须触发"系统复盘"（避免过度保守）

工作产物：
  - 风险审查意见书（通过/否决 + 理由）
  - 仓位裁定书（最终仓位大小）
  - 危机状态宣告（若触发）
```

### A.3 决策流程（以一笔买入为例）

```
步骤 1：立法会（基本面）
  标的 "000001.SZ" 是否在选股池中？
    → 否 → 直接驳回，不进入下一步
    → 是 → 通过基本面审查，发"基本面通过令"

步骤 2：警察局（技术面）
  收到基本面通过令后，计算对象卡信号：
    CHZL_BSD：3Buy，strength=8
    BPB：1st pullback，strength=7
    MFLOW：主力流入确认
    → 投票通过（≥3票）
  生成交易申请单：
    标的：000001.SZ
    方向：LONG
    入场价：当前价
    止损：zs.zd - 0.1ATR
    依据：[CHZL_BSD, BPB, MFLOW]

步骤 3：法院（仓管）
  收到交易申请单后，独立审查：
    1. Van Tharp 检查：|entry - stop| × 计划仓位 / 总资产 ≤ 2%？
       → 否 → 一票否决，发"风险超标否决令"
    2. Kelly 计算：历史胜率 45% → f*=0.18 → 半凯利=0.09
    3. VolTarget：当前波动率 15% → scalar=0.67
    4. PeriodQueen：当前 ATTACK_SUSTAINED → 允许 FULL 仓位
    5. 综合裁定：final_scalar = min(0.09, 0.67, 1.0) = 0.09
    → 仓位 9%，通过
  发"仓位裁定书"：
    裁定：通过
    最终仓位：9%
    依据：Kelly 限制为主因

步骤 4：执行
  警察局收到仓位裁定书后，执行买入。
  若法院否决，警察局必须放弃该交易，不得申诉。
```

### A.4 制约机制总结

| 制约方向 | 机制 | 示例 |
|----------|------|------|
| 基本面 → 技术面 | 技术面只能在选股池内交易 | 000002.SZ 不在选股池 → 技术面信号自动无效 |
| 技术面 → 仓管 | 仓管审查每一笔交易申请 | 信号强但风险超标 → 仓管一票否决 |
| 仓管 → 基本面 | 仓管可以要求基本面调整行业权重 | 某行业占比 80% → 仓管要求分散 |
| 仓管 → 技术面 | 仓管裁定最终仓位，技术面只能执行 | Kelly 算得 9% → 技术面不能擅自买 15% |
| 用户 → 全部 | 用户可以"修宪"（改参数）、任命大法官 | 用户调整 Van Tharp 上限 |

### A.5 优缺点

| 优点 | 缺点 |
|------|------|
| 制衡最强，单点故障风险最低 | 决策链长，可能错过快速机会 |
| 基本面不会被技术面带偏 | 三部门各自为政，信息传递有延迟 |
| 仓管不会被交易冲动影响 | 紧急行情下（如突发利好），流程太慢 |
| 责任清晰，出问题容易追责 | 需要三个部门都"在线"，维护成本高 |

## 方案 B：英式议会制（Parliamentary System）

> **理念**：技术面+基本面联合组阁（多数党执政），仓管作为反对党监督，用户作为君主有最终权。效率较高，制衡适中。
> **适合**：平衡型投资者，追求效率与稳健兼顾。

### B.2 核心设计：联合政府

```text
首相/内阁 = 基本面 + 技术面联合执政

与美式三权分立的最大区别：
- 美式：基本面和技术面互相独立，技术面不能违背基本面的选股池
- 英式：基本面和技术面联合组阁，共同制定交易提案

联合决策机制：
  1. 基本面提供"价值方向"（看多/看空/中性）
  2. 技术面提供"技术信号"（买入/卖出/观望）
  3. 两者方向一致 → 联合生成交易提案
  4. 两者方向冲突 → 触发"内阁会议"（讨论机制，见下文）

联合提案格式：
  ```
  提案编号：PROP-20240624-001
  提案人：基本面部（财政大臣）+ 技术面部（内政大臣）
  标的：000001.SZ
  方向：LONG
  基本面依据：PE=12，低于行业均值；ROE=18%，成长性良好
  技术面依据：CHZL_BSD 3Buy + BPB 1st pullback + MFLOW 主力流入
  联合信心度：8/10
  建议仓位：15%（Kelly 优化后）
  ```
```

### B.3 议会（仓管）的不信任票机制

```text
议会通常不直接否决提案，而是可以投"不信任票"：

不信任票触发条件（满足任一）：
  1. 单票风险 > 2%（Van Tharp 硬性触发）
  2. 组合总风险 > 6%
  3. 连续 3 笔联合提案的联合信心度 < 5（基本面和技术面分歧大）
  4. 市场进入 EXTREME_VOL（波动率极端）

不信任票后果：
  - 内阁必须重组（基本面和技术面重新协商）
  - 或者触发"提前大选"（用户介入决策）
  - 议会不能直接否决，但可以要求内阁修改提案

信任投票（Confidence Vote）：
  - 每个交易提案附带"信任投票"
  - 议会通过 = 信任投票通过
  - 议会要求修改 = 信任投票延迟
  - 议会投不信任 = 内阁重组
```

### B.4 内阁会议（基本面与技术面的讨论机制）

```text
当基本面和技术面方向冲突时，触发内阁会议：

冲突场景 1：基本面看多，技术面看空
  基本面：PE=10，极度低估，应该买入
  技术面：处于下降趋势，无买入信号
  → 内阁会议结论："观望"，等待技术面确认
  → 不生成交易提案

冲突场景 2：基本面看空，技术面看多
  基本面：PE=80，高估，应该回避
  技术面：突破前高，放量上涨
  → 内阁会议结论："投机性轻仓"（10% 以下仓位）
  → 生成降级提案，仓管审查更严格

冲突场景 3：基本面中性，技术面强烈看多
  基本面：估值合理，无特别优势
  技术面：多周期共振，5 个对象卡同时发出信号
  → 内阁会议结论："趋势跟随"，跟随技术面
  → 生成标准提案

内阁会议的决策规则：
  - 优先听从"联合信心度高"的一方
  - 若信心度相近，以"风险更低"的方案为准
  - 若无法达成一致，提交给用户（君主）裁决
```

### B.5 君主（用户）的权力

```text
用户不是每笔交易都介入，而是拥有"保留权力"：

常规权力（自动执行）：
  - 内阁提案 + 议会通过 → 自动执行，用户不介入

保留权力（触发时介入）：
  1. 御准权：内阁提案 + 议会通过，但用户可以选择"拒绝御准"
     → 适用于用户有不同看法时
  2. 紧急状态宣告：用户可以直接宣布"市场进入紧急状态"
     → 所有交易暂停，等待用户指令
  3. 解散议会：用户认为系统参数需要大修时，可以"解散议会"
     → 重置所有风控参数，重新校准
  4. 任命权：用户可以任命/罢免"大臣"（调整对象卡的权重或激活状态）
```

### B.6 优缺点

| 优点 | 缺点 |
|------|------|
| 基本面和技术面联合决策，信息融合度高 | 若两者长期冲突，系统可能瘫痪 |
| 仓管不直接否决，而是要求修改，更灵活 | 议会的不信任票机制可能导致频繁重组 |
| 用户有最终权，但不介入日常 | 用户权力过大可能导致系统依赖用户判断 |
| 效率高于美式，适合快速市场 | 内阁会议的讨论机制需要明确的规则，否则流于形式 |

## 方案 C：瑞士委员会制（Collegial System）

> **理念**：七人委员会集体领导，各核心对象卡/维度各有一票，仓管作为"联邦议会"可以推翻委员会决议，重大决策需用户复决。共识驱动，异议触发深度讨论。
> **适合**：喜欢集体讨论、重视共识、愿意花时间深入分析的投资者。

### C.2 七人委员会的成员设计

```text
委员 1：基本面/财政委员（A5 财报估值）
  职责：评估标的的基本面质量（PE/PB/ROE/成长性）
  投票权：基本面通过 = YES，基本面不通过 = NO

委员 2：估值/经济委员（A5 估值模型）
  职责：评估标的的估值水平（绝对估值/相对估值）
  投票权：估值合理 = YES，估值过高 = NO

委员 3：资金/流向委员（MFLOW）
  职责：评估资金流向（主力流入/流出/早盘意图）
  投票权：资金流入 = YES，资金流出 = NO

委员 4：趋势/结构委员（CHZL_TREND + CHZL_BSD）
  职责：评估趋势结构和买卖点（笔/中枢/背驰）
  投票权：趋势有利 = YES，趋势不利 = NO

委员 5：动量/背离委员（TKR7 + KD MTF）
  职责：评估动量状态（AO 背离/KD 极端区）
  投票权：动量支持 = YES，动量反对 = NO

委员 6：波动/率委员（VOLFAC + VOLTARGET）
  职责：评估波动率环境（高/低/正常波动）
  投票权：波动可控 = YES，波动极端 = NO

委员 7：情绪/周期委员（PeriodQueen + 宏观环境）
  职责：评估市场情绪周期（七态状态）
  投票权：情绪允许 = YES，情绪禁止 = NO

投票规则：
  - 每笔交易需要至少 4/7 委员投 YES
  - 3/7 或更少 → 不通过
  - 若 4/7 但委员 7（情绪委员）投 NO → 触发"深度讨论"
```

### C.3 深度讨论（Deep Deliberation）机制

```text
当投票结果处于"模糊区"（4/7 勉强通过，或 3/7 接近通过）时，触发深度讨论。

模糊区定义：
  - 4/3/0（4YES, 3NO, 0ABSTAIN）→ 勉强通过，触发讨论
  - 3/3/1（3YES, 3NO, 1ABSTAIN）→ 僵局，触发讨论
  - 2/5/0（2YES, 5NO）→ 明确不通过，不触发讨论

深度讨论流程：
  1. 每个委员提交"意见书"（为什么投 YES/NO）
  2. 系统自动生成"讨论焦点"（意见分歧最大的维度）
  3. 用户（公民）被邀请阅读意见书，做出最终裁决
  4. 裁决结果记录到"判例库"（供未来类似情况参考）

判例库的作用：
  - 积累"基本面看多但情绪委员反对"时的处理经验
  - 未来遇到类似情况，系统优先参考判例
  - 减少重复讨论，提高效率
```

### C.4 联邦议会（仓管）的推翻权

```text
联邦议会由以下"州代表"组成：
  - Van Tharp 州：单票风险审查
  - Kelly 州：仓位优化
  - VolTarget 州：波动率环境
  - PeriodQueen 州：情绪周期

推翻条件（满足任一）：
  1. 委员会决议的单票风险 > 2% → Van Tharp 州自动推翻
  2. 委员会决议的波动率状态 = EXTREME → VolTarget 州自动推翻
  3. 委员会决议的情绪状态 = HALT → PeriodQueen 州自动推翻
  4. 连续 3 笔委员会决议的胜率 < 40% → Kelly 州提出推翻

推翻程序：
  - 单州推翻 → 委员会必须修改后重提
  - 两州及以上联合推翻 → 决议作废，触发"紧急委员会会议"
  - 紧急委员会会议：用户必须介入，重新评估策略
```

### C.5 优缺点

| 优点 | 缺点 |
|------|------|
| 七维度全面评估，不遗漏任何角度 | 七人投票可能导致 3/3/1 僵局频繁 |
| 判例库积累，系统越用越聪明 | 深度讨论耗时，不适合高频交易 |
| 共识驱动，决策质量高 | 用户需要频繁阅读意见书 |
| 每个委员独立，不容易被单一因素带偏 | 委员会成员的设计需要非常精心 |

## 方案 D：罗马共和制（Roman Republic）

> **理念**：执政官双人互相牵制，元老院（经验规则库）审查一切，保民官（用户）拥有对平民的否决权。强调历史经验与实时制衡的结合。
> **适合**：重视历史经验、相信"太阳底下无新事"的投资者。

### D.2 执政官双人牵制

```text
执政官 A（基本面）和执政官 B（技术面）同时执政，互相牵制：

正常流程：
  1. A 提出"基本面买入提案"
  2. B 提出"技术面买入提案"
  3. 两者方向一致 → 联合提案提交元老院
  4. 元老院审查 → 通过 → 执行

牵制机制：
  - A 提案后，B 有"否决权"（Veto）
  - B 提案后，A 有"否决权"（Veto）
  - 若一方行使否决权，提案无效
  - 否决必须给出理由，记录在"元老院档案"

执政官任期制：
  - 每季度轮换"主导执政官"
  - Q1：基本面主导（A 有提案优先权）
  - Q2：技术面主导（B 有提案优先权）
  - 轮换目的是防止一方长期主导

独裁官（紧急状态）：
  - 市场进入 EXTREME 状态时，可任命"独裁官"
  - 独裁官（用户指定的一方）可以单独决策，不受牵制
  - 任期最长 30 天，到期自动恢复双人执政
```

### D.3 元老院（经验规则库）

```text
元老院不是人，而是一个"历史经验数据库"：

组成：
  1. 历史判例库（类似瑞士制的判例库，但更强调历史类比）
  2. 类似行情回测（当检测到当前行情类似历史某段时，自动回测）
  3. 经典策略库（海龟、价值投资、趋势跟踪等经典策略的参数）
  4. 失败案例库（记录所有亏损交易的共同特征）

元老院的权力：
  - "审查权"：所有提案必须经过元老院审查
  - "警告权"：元老院不直接否决，但可以发"警告"
  - "咨询权"：执政官可以向元老院"咨询历史经验"

元老院的审查输出：
  ```
  元老院审查意见书：
    提案编号：PROP-001
    历史类比：2020-03 疫情暴跌后的反弹（相似度 78%）
    历史结果：当时基本面和价值投资者过早入场，技术面 3Buy 信号出现后 2 周才真正见底
    建议：技术面应等待多周期共振确认，不要急于入场
    风险等级：中等
  ```
```

### D.4 保民官（用户）的否决权

```text
保民官的权力是"保护平民"——在投资系统中，"平民"就是用户的本金。

保民官的否决权触发条件：
  1. 单笔交易风险 > 5%（远超 Van Tharp 2%）
  2. 组合回撤 > 20%（本金安全受威胁）
  3. 用户直觉/经验与系统决议严重冲突
  4. 市场出现"前所未有的"情况（历史判例库无记录）

保民官否决后的程序：
  1. 系统暂停该交易
  2. 记录否决原因
  3. 触发"紧急会议"（用户+执政官+元老院代表）
  4. 用户做出最终裁决
```

### D.5 优缺点

| 优点 | 缺点 |
|------|------|
| 双人牵制，避免任何一方独断 | 两人否决权可能导致系统僵局 |
| 元老院提供历史智慧，不重复犯错 | 历史类比可能误导（"这次不一样"） |
| 保民官保护本金，终极安全网 | 用户否决权使用不当会削弱系统纪律 |
| 任期轮换，防止风格漂移 | 季度轮换可能导致策略不稳定 |

## 对用户（设计者）的选择建议

```text
如果用户的核心诉求是：

1. "我宁可错过，也不能亏大钱" → 选方案 A（美式三权）
   - 仓管的一票否决权最强
   - 基本面独立，不会被技术面带偏追高风险股

2. "我希望基本面和技术面能融合，不要各自为政" → 选方案 B（英式议会）
   - 联合内阁机制让两者共同决策
   - 用户有最终权，但不介入日常

3. "我希望每个角度都被考虑到，不遗漏任何因素" → 选方案 C（瑞士委员会）
   - 七维度全面评估
   - 判例库积累，系统越用越聪明

4. "我相信历史会重复，重视经验和案例" → 选方案 D（罗马共和）
   - 元老院的历史类比是独特优势
   - 双人牵制简单有效

混合建议：
  用户也可以"阶段性切换"：
  - 牛市初期（GESTATION）→ 用方案 B（联合决策，积极建仓）
  - 牛市中期（ATTACK_SUSTAINED）→ 用方案 A（严格分离，稳健持有）
  - 市场震荡（POWER_TRANSITION）→ 用方案 C（七维讨论，避免误判）
  - 熊市/危机 → 用方案 D（双人牵制+历史类比，保护本金）
```

## 对编程 AI 的实现要求（无论选哪个方案）

```text
1. 架构层面：
   - 每个"部门"必须是独立的 Python 类/模块
   - 部门之间通过"提案/审查/否决"的消息机制通信
   - 不能有任何部门直接修改另一个部门的内部状态

2. 消息格式：
   - 提案消息：{proposal_id, from_department, to_department, content, timestamp}
   - 审查消息：{review_id, proposal_id, reviewer, verdict, reason, timestamp}
   - 否决消息：{veto_id, proposal_id, vetoer, reason, timestamp}

3. 审计日志：
   - 每笔交易的完整决策链必须记录
   - 包括：谁提案、谁审查、谁否决、理由是什么
   - 用于事后复盘和判例库积累

4. 用户接口：
   - 无论选哪个方案，用户都必须有一个"控制台"
   - 控制台显示：当前各部门状态、待审提案、已否决议案
   - 用户可以通过控制台行使"保留权力"
```
