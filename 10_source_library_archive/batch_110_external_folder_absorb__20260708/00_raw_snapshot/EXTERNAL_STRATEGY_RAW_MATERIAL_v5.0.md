### 1.2 Interactive Brokers (盈透证券)

来源：[e-futures.com](https://www.e-futures.com/)

**核心特点**：
- 全球多市场接入（美股、港股、期货、外汇、债券）
- 强大的 API：支持 Python、C++、Java、C#，第三方工具可连接
- 低佣金，适合大资金
- TWS (Trader Workstation) 桌面终端功能丰富
- 支持算法交易、智能路由

**适用场景**：多资产、多市场的专业交易者，需要稳定执行和全球接入。

### 1.3 NinjaTrader

来源：[newtrading.io](https://www.newtrading.io/)

**核心特点**：
- **期货专用**：2003 年成立，超过 200 万账户
- **C# NinjaScript**：策略自动化，高度可定制
- **Tick 级回测**：比 K 线级别更精细，反映真实市场微观结构
- **订单流工具内置**：DOM (Depth of Market)、成交量分布
- **终身许可**：一次性付费，无需月订阅
- **佣金**：Micro 合约 $0.09/单边
- **缺点**：仅期货（无股票/外汇），学习曲线陡峭，仅桌面端

**适用场景**：专注期货的系统交易者、日内交易者。

### 1.4 TradeStation

来源：[BrokerChooser](https://brokerchooser.com/)

**核心特点**：
- **EasyLanguage**：专有的策略脚本语言，简化策略编写
- 高级图表和自动化交易
- 低佣金，支持股票/期货/期权
- 强大的回测引擎
- API 支持

### 1.5 QuantConnect (LEAN 引擎)

来源：[CSDN - 量化开源框架对比](https://blog.csdn.net/)

**核心特点**：
- **云端 + 本地双模式**：LEAN 引擎用 C# 编写，开源
- **多语言支持**：Python、C#、F#
- **多资产覆盖**：股票、期货、外汇、加密货币
- **免费版功能完整**，但有交易额度限制
- **社区策略丰富**
- **缺点**：服务器在海外，A 股支持有限，网络可能不稳定

**适用场景**：海外市场投资者，需要多资产策略验证。

### 1.6 MetaTrader 5

来源：[ATAS](https://atas.net/)

**核心特点**：
- **MQL5 生态**：庞大的 EA（专家顾问）、指标、脚本市场
- 支持对冲、策略测试、经济日历
- 稳定运行多年
- **缺点**：界面过时（2010 年代风格），外汇经纪商品质参差不齐，EA 市场低质产品多
- **适用场景**：Forex/CFD 交易者

### 1.7 三大平台对比（NinjaTrader vs TradeStation vs IB）

### 2.2 QMT (迅投 ThinkTrader)

来源：[知乎 - 小白该怎么入手量化平台](https://zhuanlan.zhihu.com/)

**核心特点**：
- **双语言开发**：Python + VBA，同花顺/通达信/大智慧策略可改写
- **本地化运行**：策略编写、回测、模拟均本地执行，不上传服务器，策略保密性高
- **交易品种广泛**：股票、期货、期权、ETF、可转债、两融
- **回测周期全覆盖**：1min、3min、5min... 自定义周期
- **极速交易终端**：券商白名单，低延迟
- **算法交易**：支持标准算法交易、篮子交易
- **缺点**：对编程能力要求高，本地运行对电脑配置有要求

**适用场景**：对策略保密性要求高、有编程能力的专业个人投资者。

### 2.3 PTrade (恒生)

来源：[知乎 - 小白该怎么入手量化平台](https://zhuanlan.zhihu.com/)

**核心特点**：
- **云端托管架构**：部署在券商核心机房，用户只写策略，系统自动运行
- **7×24 稳定运行**：机房硬件保障，不受本地电脑关机影响
- **毫秒级订单响应**：与交易所直连的托管服务器
- **免费 Level-2 行情**：相较于 QMT 的差异化优势
- **全流程自动化**：回测 → 模拟 → 实盘一键完成
- **缺点**：灵活性不够，不支持第三方库，策略放服务器有泄露风险，不能访问外网

**适用场景**：中低频量化投资者，不想维护本地环境的用户。

### 2.4 QMT vs PTrade 详细对比

来源：[CSDN - 一文盘点 QMT 和 PTrade](https://quant.csdn.net/)

| 维度 | QMT | PTrade |
|------|-----|--------|
| **运行方式** | 本地运行 | 云端托管 |
| **策略安全** | 高（不上传） | 中（放服务器） |
| **交易速度** | 快 | 更快（机房直连） |
| **编程门槛** | 高 | 中 |
| **界面** | 专业复杂 | 简洁直观 |
| **第三方库** | 支持 | 不支持 |
| **外网访问** | 支持 | 不支持 |
| **电脑依赖** | 需长时间开机 | 不受电脑影响 |
| **适合人群** | 专业投资者 | 初学者/中低频 |

### 2.5 聚宽 (JoinQuant)

来源：[知乎 - 小白该怎么入手量化平台](https://zhuanlan.zhihu.com/)

**核心特点**：
- 数据丰富：2005 年至今完整 Level-1、财务数据、停复权
- IPython Notebook 研究平台，支持 Python 2/3
- 支持股票、基金、期货回测（日/分钟/Tick）
- 社区活跃，策略分享丰富
- **⚠️ 实盘合作已于 2024 年 12 月终止**（与一创证券）
- 适合研究，不适合实盘

### 2.6 米筐 (RiceQuant)

来源：[SegmentFault](https://segmentfault.com/)

**核心特点**：
- Notebook 环境，因子分析、组合优化工具链完整
- 实盘需 API 对接
- 社区互动活跃，举办量化比赛
- 缺点：实盘对接有一定门槛

### 2.7 BigQuant (宽邦)

来源：[CSDN](https://blog.csdn.net/)

**核心特点**：
- **AI 驱动**：AutoML、机器学习因子挖掘
- **可视化策略生成**：拖拽式，适合非程序员
- 支持日/分钟/Tick 回测
- 实盘支持国金、万和、湘财等券商
- 佣金统一万 2.5

### 2.8 掘金量化 (MyQuant)

来源：[CSDN](https://blog.csdn.net/)

**核心特点**：
- C++/Python，事件驱动回测
- 对接 CTP、恒生 OES，**实盘毫秒级**
- 股票、期货、数字货币全覆盖
- 托管账户 + 自营账户（10 倍杠杆）
- 社区和专业团队支持

## 三、开源量化框架

### 3.1 综合对比表

来源：[CSDN - 量化开源项目对比](https://blog.csdn.net/zhangyunchou2015/article/details/147185325)

| 框架 | 核心类型 | 性能 | 易用性 | 实盘支持 | 社区活跃度 | 主要侧重 |
|------|----------|------|--------|----------|-----------|----------|
| **Backtrader** | 事件驱动 | 中等 | 中等 | 支持(IB) | 活跃 | 灵活的事件驱动回测 |
| **VectorBT** | 向量化 | **极高** | 较高 | 较弱 | 活跃 | 极速向量化回测 |
| **Zipline** | 事件驱动 | 中等 | 中等 | 较弱 | 维护中 | 学术研究 |
| **vn.py** | 事件驱动/平台 | 中等 | 中等偏高 | **核心功能** | **非常活跃** | 全功能交易平台 |
| **WonderTrader** | 事件驱动/平台 | 高(C++) | 中等偏高 | 核心功能 | 活跃 | 高性能交易平台 |
| **qlib** | 向量化/AI | 高 | 中等偏高 | 较弱 | 活跃(MS) | AI 量化研究 |

| **PyBroker** | 向量化 | 高 | 较高 | 不支持 | 较低 | 简洁向量化回测 |

### 3.2 Backtrader（回测之王）

来源：[微信公众号 - 志在量化](https://mp.weixin.qq.com/)

**优点**：
- 完全免费开源
- 事件驱动架构，逻辑清晰
- 支持多数据源、多时间框架
- 内置大量技术指标（TA-Lib 集成）
- 支持参数优化（多进程）
- 佣金、滑点模拟
- Matplotlib 可视化

**缺点**：
- 实盘需大量开发工作
- 对新手不够友好
- 回测速度较慢（纯 Python 事件驱动）
- 原作者维护不活跃

**适用**：复杂策略、多资产、需要精细控制的用户。

### 3.3 vn.py（国内实盘首选）

来源：[CSDN - 量化开源项目对比](https://blog.csdn.net/)

**优点**：
- **实盘导向**：CTP, Femas, UFT, 盈透, 中泰 XTP, 华鑫奇点, 东方证券 OST 等
- 模块化设计（策略引擎、数据服务、风控模块、GUI）
- 自带 GUI，方便监控
- K 线 + Tick 级别回测
- 支持 CTA、跨期套利、算法交易
- 社区非常活跃，持续更新

**缺点**：
- 相对较重，学习曲线陡峭
- 回测性能不如向量化框架
- 主要面向国内市场

**适用**：国内期货/证券实盘交易者，需要一体化平台。

### 3.4 WonderTrader (wtpy)

来源：[CSDN - 量化开源项目对比](https://blog.csdn.net/)

**优点**：
- **C++ 核心**，高性能
- 实盘支持稳定
- 架构清晰（服务层 C++ + 应用层 Python）
- 支持 HFT 高频和中低频回测
- 配套数据工具和监控界面

**缺点**：
- 社区规模略小于 vn.py
- 可能需要 C++ 知识

**适用**：对性能有高要求的国内实盘交易者。

### 3.5 VectorBT

来源：[CSDN - 量化开源项目对比](https://blog.csdn.net/)

**优点**：
- **向量化运算，回测速度极快**
- 与 Pandas 深度集成
- 强大的交互式可视化（Plotly）
- 多品种、多策略、多参数回测

**缺点**：
- 牺牲事件驱动的模拟精度
- 复杂订单逻辑、逐笔模拟较难
- 实盘支持弱

**适用**：快速验证策略想法、大规模参数扫描、组合分析。

### 3.6 qlib（微软 AI 量化）

来源：[CSDN - 量化开源项目对比](https://blog.csdn.net/)

**优点**：
- 微软亚洲研究院发布
- AI 驱动：LightGBM, LSTM 等内置
- 标准化数据格式和模型接口
- 向量化回测效率高

**缺点**：
- 侧重 AI 研究，传统策略支持弱
- 实盘交易非核心功能

**适用**：AI/机器学习量化策略研究。

## 七、Kimi 的取舍与映射

### 7.1 对我们系统的参考价值

| 平台/框架 | 值得借鉴的设计 | 映射到我们的系统 |
|-----------|----------------|------------------|
| **vn.py** | 模块化设计、事件驱动、丰富实盘接口 | 架构分层、BrokerInterface 抽象 |
| **Backtrader** | Cerebro 引擎、多数据源、指标系统 | Pipeline 设计、ObjectCardBase |
| **VectorBT** | 向量化极速回测、多参数扫描 | 未来性能优化方向（polars 已实现部分） |
| **NinjaTrader** | Tick 级回测、订单流工具 | 回测精度参数（诚实性） |
| **QMT** | 本地运行、策略安全、多品种 | 本地部署优先、模式切换 |
| **PTrade** | 云端托管、机房直连、Level-2 免费 | 券商接口层设计、行情接入 |
| **QuantConnect** | 云端+本地双模式、LEAN 引擎 | 三种运行模式（BACKTEST/PAPER/LIVE） |
| **聚宽** | Notebook 研究环境、社区分享 | 未来可扩展的研究模块 |
| **qlib** | 标准化数据格式、模型接口 | 数据管道标准化、特征缓存 |

### 7.2 明确不借鉴的内容

| 不借鉴 | 原因 |
|--------|------|
| MT5 / MQL5 | Forex 专用，A 股不相关 |
| Freqtrade | 仅加密货币 |
| Bloomberg EMSX / Barra | 机构级，年费百万，个人不可用 |
| KDB+/q | 高频专用，需自建机房 |
| 果仁（非编程） | 我们的系统要求编程驱动 |

### 7.3 关键启发

1. **撮合机制必须透明可配置**：不同平台的撮合规则差异巨大，我们的系统必须明确记录使用的撮合假设
2. **本地 vs 云端各有优劣**：QMT（本地安全）vs PTrade（云端便捷），我们的系统应支持切换
3. **事件驱动 vs 向量化**：Backtrader（灵活但慢）vs VectorBT（快但简），我们的系统以事件驱动为主，关键路径可用 polars 向量化加速
4. **vn.py 的模块化设计最值得参考**：策略引擎、数据服务、风控模块、GUI 分离，易于扩展
5. **回测诚实性是关键教训**：各平台滑点、佣金、撮合规则不同，回测结果不可直接比较
