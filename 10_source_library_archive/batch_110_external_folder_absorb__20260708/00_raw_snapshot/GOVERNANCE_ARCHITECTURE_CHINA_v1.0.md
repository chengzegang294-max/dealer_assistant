# 投资管家国内治理架构方案集 v1.0

> **本文档全部内容源于用户（仓库所有者）的想法，由 Kimi 整理完善为可供选择的架构方案。**
> 版本：v1.0 | 状态：方案设计阶段 | 目标：用中国本土制度结构替代国外方案
> 核心原则：不照搬西方，用中国古代制度智慧 + 现代企业治理结构，设计投资系统的组织架构

---

## 前言：为什么用中国制度

用户明确要求："用国内的。我不喜欢国外的结构。"

这不是简单的"换个名字"，而是制度逻辑的深层差异：

| 西方逻辑 | 中国逻辑 | 投资系统映射 |
|----------|----------|-------------|
| 三权分立（互相牵制） | 三省协作（分工明确，上下贯通） | 基本面定方向、仓管审风险、技术面执行 |
| 议会投票（多数决） | 封驳制度（审议后再执行） | 技术面信号先过仓管审查，才能执行 |
| 不信任票（推倒重来） | 谏官弹劾（纠偏不改局） | 风控发现问题，要求修改，但不中断系统 |
| 任期轮换（政党轮替） | 六部各司其职（专业分工） | 每个对象卡有固定职责，不频繁更换 |

**核心洞察**：中国制度的特点是"**分工协作、层级贯通、纠偏不改局**"——这与投资系统需要的"**各尽其职、信息畅通、风控不中断交易**"高度一致。

## 方案一：隋唐三省六部制

> **理念**：中书省草拟（决策）、门下省审议（风控）、尚书省执行（交易），六部分工专业。决策链清晰，风控嵌入流程，不割裂。
> **适合**：追求流程清晰、层级明确、各司其职的投资者。

### 1.2 三省职能详解

#### 中书省（基本面部）——"定方向"

```text
职责：草拟诏令（交易提案的雏形）

权力：
  ✓ 划定选股池（哪些标的有资格进入候选池）
  ✓ 制定价值标准（PE/PB/ROE 阈值）
  ✓ 行业配置权重（超配/低配哪些行业）
  ✓ 财报审查（每季度更新，剔除暴雷标的）
  ✓ 对仓管部提出的"风险规则"有建议权

限制：
  ✗ 不能直接下单（不能越权执行）
  ✗ 诏令必须经过门下省审议才能生效
  ✗ 被门下省封驳后，必须修改重拟

工作产物：诏令草案（选股池名单 + 行业配置 + 价值标准）

对应对象卡：
  - A5 财报估值（郭永清）
  - A5 上市公司财报分析
  - INSTB（机构行为，季频参考）
```

#### 门下省（仓管/风控部）——"审风险"

```text
职责：审议诏令，有权封驳

这是三省六部制的核心创新：风控不是后置检查，而是前置审议。
每一笔交易在发生之前，必须经过门下省的"审议盖章"。

权力：
  ✓ 审查每一笔交易申请（风险是否超标）
  ✓ 封驳权（风险超标时直接否决，无需理由）
  ✓ 仓位裁定（Kelly + VolTarget 计算最终仓位）
  ✓ 盖印权（审查通过后盖印，交付尚书省执行）
  ✓ 对中书省的"行业配置权重"有审查权（若权重过高，可要求调整）

限制：
  ✗ 不能自己生成交易信号（不能越位）
  ✗ 不能修改诏令内容（只能"通过"或"封驳"）
  ✗ 封驳后必须给出明确理由（不能无理由否决）

工作产物：审议意见书（通过 + 盖印 / 封驳 + 理由）

对应对象卡：
  - Van Tharp 硬性上限
  - Kelly Criterion
  - Volatility Targeting
  - PeriodQueen（情绪周期，大环境审查）
```

#### 尚书省（技术面部）——"干实事"

```text
职责：执行诏令，下辖六部具体分工

尚书省不制定规则，只负责把中书省拟定的、门下省审查通过的诏令，通过六部具体执行。

六部设计（对应对象卡分组）：

吏部（组织部）——对象卡管理
  • 职责：所有对象卡的注册、激活、停用
  • 对应：对象卡注册表（object_registry.json）
  • 职能：新对象卡入库审核、成熟度评估、版本管理

户部（财政部）——资金管理
  • 职责：资金流向分析、仓位计算、盈亏统计
  • 对应：MFLOW（资金流向）、Kelly（仓位优化）
  • 职能：每日资金日报、盈亏跟踪

礼部（礼仪部）——信号规范
  • 职责：统一信号格式、标准化输出接口
  • 对应：统一输出接口规范（standard_output dict）
  • 职能：确保所有对象卡输出格式一致、字段完整

兵部（国防部）——交易执行
  • 职责：具体买卖执行、止损止盈跟踪、持仓管理
  • 对应：CHZL_BSD、BPB、VP、TKR7、YTC 等执行层对象卡
  • 职能：生成交易指令、跟踪止损、记录交易日志

刑部（司法部）——合规与止损
  • 职责：止损执行、合规检查、异常交易监控
  • 对应：止损规则（CHZL_BSD 三类止损）、Van Tharp 硬性上限
  • 职能：触发止损时立即执行、记录违规交易

工部（建设部）——数据与技术基础设施
  • 职责：数据管道、特征缓存、回测引擎维护
  • 对应：DataLoader、Feature Store、Backtest Engine
  • 职能：ETL 管道维护、数据质量监控、系统性能优化
```

### 1.3 决策流程（以一笔买入为例）

```
步骤 1：中书省（基本面）草拟诏令
  标的 "000001.SZ"：
    PE=12（低于行业均值）→ 基本面通过
    ROE=18%（成长性良好）→ 基本面通过
    所属行业：银行 → 当前行业配置权重 15% → 不超限
  
  中书省输出：
    诏令草案：允许 000001.SZ 进入候选池
    附带价值评分：8/10

步骤 2：尚书省（技术面）六部联动，生成交易申请
  兵部（交易执行）计算对象卡信号：
    CHZL_BSD：3Buy，strength=8
    BPB：1st pullback，strength=7
    MFLOW：主力流入确认
    → 兵部生成交易申请单
  
  礼部（信号规范）检查输出格式：
    ✓ 字段完整
    ✓ 命名规范
    → 礼部盖"格式合格"章
  
  户部（资金）计算初步仓位：
    Kelly：f*=0.18 → 半凯利=0.09
    → 户部附"资金评估"

  尚书省汇总六部意见，提交门下省审议：
    奏折：请求买入 000001.SZ，仓位 9%
    依据：CHZL_BSD + BPB + MFLOW
    附：户部资金评估、礼部格式检查

步骤 3：门下省（仓管）审议，盖印或封驳
  门下省审查：
    1. Van Tharp：|entry - stop| × 9%仓位 / 总资产 = 1.2% < 2% → 通过
    2. VolTarget：当前波动率 15% → scalar=0.67 → 不影响
    3. PeriodQueen：当前 ATTACK_SUSTAINED → 允许交易
    4. 组合风险：当前总风险 4.5% + 1.2% = 5.7% < 6% → 通过
  
  门下省输出：
    审议结果：通过
    盖印："门下省印"
    最终仓位：9%（户部计算的 Kelly 结果）
    交付尚书省执行

步骤 4：尚书省（兵部）执行
  兵部收到盖印诏令 → 执行买入
  刑部同步启动止损跟踪
  工部记录交易日志

若门下省封驳：
  门下省输出：
    审议结果：封驳
    理由：组合风险已 5.8%，再加 1.2% 将超 6% 上限
    建议：减仓其他持仓后再申请，或降低仓位至 5%
  
  尚书省收到封驳 → 停止执行
  中书省收到封驳 → 可修改诏令（如降低仓位）后重拟
```

### 1.4 封驳制度的核心价值

```text
门下省的"封驳权"是中国古代政治的核心创新，也是投资系统的核心风控：

封驳 vs 西方否决：
  西方：法院可以"否决"行政命令 → 推倒重来，效率低
  中国：门下省可以"封驳"诏令 → 退回修改，不改局

在投资系统中的体现：
  - 仓管发现问题 → 不直接终止交易，而是"封驳"（退回修改）
  - 技术面可以修改仓位后重新申请
  - 基本面可以调整选股池后重新草拟
  - 系统不中断，只是"打回重做"

封驳的三种结果：
  1. 完全封驳：风险严重超标 → 必须放弃该交易
  2. 附条件通过：降低仓位后可以通过 → 尚书省修改后重提
  3. 通过：审查无误 → 盖印执行
```

### 1.5 皇帝（用户）的权力

```text
用户作为"皇帝"，拥有以下权力：

常规权力（不介入日常）：
  - 任命/罢免三省主官（调整对象卡的权重和激活状态）
  - 修订"祖宗家法"（修改系统参数，如 Van Tharp 上限）
  - 每季度"御览"绩效报告

保留权力（触发时介入）：
  - 紧急御批：市场极端情况时，用户可直接下令（如"全部清仓"）
  - 否决权：对三省决议有最终否决权
  - 特赦权：对某笔被封驳的交易，用户可特赦通过（慎用）
```

## 方案二：现代企业"三会一层"

> **理念**：股东大会（用户）、董事会（基本面战略决策）、监事会（风控监督）、经理层（技术面执行）。权责边界清晰，符合现代商业思维。
> **适合**：熟悉公司治理、重视合规和风险控制的专业投资者。

### 2.2 各部门职能

#### 董事会（基本面部）——"定战略"

```text
职责：制定投资战略，但不介入日常交易

权力：
  ✓ 划定选股池（哪些行业、哪些市值段可以投资）
  ✓ 制定年度行业配置策略（超配/低配）
  ✓ 审批重大投资（单票超过 10% 仓位需董事会审批）
  ✓ 任免 CEO（经理层负责人）
  ✓ 审议年度投资报告和绩效

限制：
  ✗ 不能直接下单（日常交易由经理层执行）
  ✗ 不能干预经理层的具体交易时机选择
  ✗ 战略决议需监事会审查通过

会议频率：
  - 季度会议（审财报、调行业配置）
  - 临时会议（市场重大变化时）
```

#### 监事会（仓管/风控部）——"盯风险"

```text
职责：独立于董事会和经理层，专门监督风险

权力：
  ✓ 审查所有交易的风险状况
  ✓ 对超标交易有"暂停执行权"
  ✓ 要求董事会/经理层提供风险报告
  ✓ 发现重大风险时，直接向股东大会报告
  ✓ 对 Kelly/VolTarget/Van Tharp 参数有审查权

独立性：
  - 监事会成员不能兼任董事或经理
  - 监事会直接对股东大会负责
  - 监事会主席由股东大会任命

会议频率：
  - 每笔重大交易后审查
  - 月度风险报告
  - 季度全面审计
```

#### 经理层/CEO（技术面部）——"干实事"

```text
职责：在董事会战略框架内，自主执行日常交易

权力：
  ✓ 在选股池内自主生成交易信号
  ✓ 自主决定具体入场/出场时机
  ✓ 管理日常仓位（在董事会设定范围内）
  ✓ 对象卡的日常运行和维护

限制：
  ✗ 不能交易选股池外的标的
  ✗ 单票仓位超过 10% 需董事会审批
  ✗ 必须接受监事会的风险审查
  ✗ 连续亏损 3 笔后，必须向董事会报告

自主权范围：
  - 日常交易：完全自主
  - 重大交易（单票 >10% 或总仓位变化 >20%）：需投委会审议
```

#### 投资决策委员会（联席机制）

```text
重大交易不走"经理层单独决策"，而走"投委会联席审议"：

成员：
  - 董事会代表（基本面部）
  - 经理层代表（技术面部）
  - 监事会代表（风控部）列席，有建议权无投票权

审议事项：
  - 单票仓位 > 10%
  - 新行业首次配置
  - 市场进入 EXTREME_VOL 时的应对
  - 连续亏损后的策略调整

投票规则：
  - 董事会和经理层各一票
  - 一致通过 → 执行
  - 分歧 → 提交股东大会裁决
```

### 2.3 与三省六部制的对比

| 维度 | 三省六部制 | 三会一层 |
|------|-----------|---------|
| **文化基因** | 中国古代官僚制 | 现代公司治理 |
| **风控位置** | 嵌入流程（门下省审议） | 独立监督（监事会） |
| **决策速度** | 中等（需三省流转） | 较快（经理层日常自主） |
| **制衡强度** | 强（封驳权） | 中（监事会监督） |
| **用户角色** | 皇帝（高高在上） | 股东（理性参与） |
| **适合用户** | 喜欢流程感、历史感 | 熟悉企业运营、重视合规 |

## 方案三：明朝内阁-六科给事中制

> **理念**：内阁票拟（基本面+技术面联合提案）、六科给事中封驳（仓管独立审查）、皇帝批红（用户最终决策）。联合决策+独立审查，效率与制衡兼顾。
> **适合**：希望基本面和技术面融合，但又要有独立风控审查的投资者。

### 3.2 票拟与封驳

```text
票拟（内阁联合提案）：
  - 不是基本面单独提案，而是基本面+技术面联合票拟
  - 首辅（基本面大学士）提出价值判断
  - 次辅（技术面大学士）提出技术信号
  - 两者一致 → 联合票拟
  - 两者冲突 → 内阁会议讨论，形成统一意见或分别陈述

封驳（六科给事中审查）：
  - 六科分别从不同角度审查：
    吏科：对象卡是否成熟？是否有未验证的对象卡参与？
    户科：资金计算是否正确？Kelly/VolTarget 参数是否合理？
    兵科：交易信号是否可靠？对象卡互锁是否完整？
    刑科：止损设置是否合理？风险是否可控？
    工科：数据来源是否可靠？是否有数据缺失？
  - 任何一科发现问题 → 可以封驳
  - 六科都通过 → 送皇帝批红

皇帝批红：
  - 常规：内阁票拟 + 六科通过 → 自动批红（用户不介入）
  - 保留：皇帝可以"留中不发"（暂不决策，继续观察）
  - 紧急：皇帝可以直接"中旨"（绕过内阁和六科，直接下令）
```

### 3.3 内阁会议（基本面与技术面的融合机制）

```text
当基本面和技术面冲突时，召开内阁会议：

场景 1：基本面看多，技术面看空
  首辅：PE=10，极度低估，应该买入
  次辅：处于下降趋势，无买入信号
  → 内阁会议结论："留中不发"，等待技术面确认
  → 票拟："建议观望，待 3Buy 出现后执行"

场景 2：基本面看空，技术面看多
  首辅：PE=80，高估，应该回避
  次辅：突破前高，放量上涨
  → 内阁会议结论："投机性轻仓"
  → 票拟："允许轻仓参与（<5%），严格止损"

场景 3：两者一致
  → 直接联合票拟，送六科审查
```

## 方案四：古代谏官-台谏制

> **理念**：御史台（独立监察）+ 谏官（随时进谏）+ 台谏合一（风控与监督一体化）。独立于行政体系，专门纠偏。
> **适合**：重视独立监督、希望系统能自我纠偏的投资者。

│  │  • 有"风闻奏事"权（听到风声即可报告，不需证据）              │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘

### 4.2 台谏的核心权力

```text
御史台（事后监察）：
  - 每笔交易执行后，御史台审查是否合规
  - 发现违规（如突破 Van Tharp 上限）→ 纠劾（记录违规，要求整改）
  - 定期审计绩效（月度/季度），向皇帝报告

谏官（事前预警）：
  - 不等交易发生，随时进谏
  - 发现市场风险（如波动率突然飙升）→ 上谏（预警）
  - 发现策略缺陷（如某对象卡频繁失效）→ 建议调整

风闻奏事（特别权力）：
  - 谏官不需要确凿证据，"听说有风险"即可上谏
  - 在投资系统中：当多个对象卡出现异常信号时，谏官可以预警
  - 目的是"宁可信其有"，提前防范

台谏合一：
  - 御史台和谏官虽然分工不同，但共同组成风控体系
  - 御史台偏重事后审查，谏官偏重事前预警
  - 两者信息互通，形成完整的风控闭环
```

## 核心设计原则（适用于所有方案）

```text
无论选哪个方案，都必须遵守以下原则：

1. 基本面不能执行（立法不执法）
   - 基本面制定选股池和价值标准
   - 但不能直接下单
   - 必须通过技术面或仓管才能落地

2. 技术面不能立法（执法不立法）
   - 技术面只能交易选股池内的标的
   - 不能自行扩大选股范围
   - 不能修改风控规则

3. 仓管不能兼任（司法独立）
   - 仓管只做风险审查，不生成交易信号
   - 仓管不决定买什么，只决定能不能买
   - 仓管有否决权，但没有提案权

4. 用户不介入日常（皇帝垂拱而治）
   - 系统日常运行，用户不干预
   - 只在紧急状态或重大调整时介入
   - 定期"御览"绩效报告

5. 信息上下贯通（奏折制度）
   - 每个层级的决策都有记录（奏折）
   - 记录可回溯、可审计
   - 积累"判例库"，未来参考
```

## 对编程 AI 的实现要求

```text
无论选哪个中国方案，编程 AI 都必须：

1. 部门独立：
   - 每个"省"或"会"是独立的 Python 模块/类
   - 部门之间通过"奏折/提案/审查意见书"的消息格式通信
   - 不能有部门直接修改另一个部门的内部状态

2. 消息格式（奏折制度）：
   ```python
   # 奏折（提案）
   {
       "奏折编号": "ZHE-20240624-001",
       "呈报部门": "中书省/内阁/董事会",
       "事由": "请求买入 000001.SZ",
       "内容": {...},
       "附件": ["基本面评估", "技术信号", "资金计算"],
       " timestamp": "2024-06-24 09:30:00"
   }
   
   # 批红（审查意见）
   {
       "原奏折": "ZHE-20240624-001",
       "审查部门": "门下省/六科/监事会",
       "裁定": "通过/封驳/附条件通过",
       "理由": "...",
       "盖印": "门下省印"
   }
   ```

3. 审计日志（起居注）：
   - 每笔交易的完整决策链必须记录
   - 包括：谁草拟、谁审查、谁封驳、理由是什么
   - 用于事后复盘和判例库积累

4. 用户控制台（御前会议）：
   - 显示当前各部门状态
   - 显示待审奏折、已封驳奏折
   - 用户可以"批红"（通过）、"留中"（暂不决策）、"中旨"（直接下令）
```
