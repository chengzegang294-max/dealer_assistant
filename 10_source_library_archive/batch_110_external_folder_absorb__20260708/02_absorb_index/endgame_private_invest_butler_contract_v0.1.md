# 终局合同层（草案）— 私人投资管家 v0.1

更新时间：2026-07-08

## 目标（你确认的终局效果）

- 覆盖市场：A股 / 外汇 / 币圈主流币 / 期货等。
- 具备能力：基本面 + 技术面分析；结合仓位管理给出分析与建议。
- 交互形态：类似“三权分立”的讨论机构，围绕同一标的/组合给出不同结论，再形成最终结论。
- 功能模块：知道当前持仓、有关注池（watchlist/universe）、对关注标的给出独特看法与建议。
- 当前边界：暂不接入下单软件；未来可能接入。

## 最高优先级原则（你强调的质量要求）

- 可复现：同输入同输出，链路可追溯。
- 不过拟合：不能只在历史上好看；必须有逻辑性与可解释性。
- 文档 + 可跑代码 + 验收样本：每个模块有最小可跑入口与验收。
- 数据：允许付费，强调高性价比。
- 自动化日报：作为默认交付之一。

## 三权分立（建议的机构划分）

- 研究院（Fundamental/Macro）：基本面、宏观、产业链、事件驱动；输出“可证伪”的假设与数据需求。
- 参谋部（Technical/Object Cards）：对象卡信号、投票聚合、跨市场适配；输出“可编码”的规则候选与证据锚点。
- 都察院（Risk/Portfolio）：仓位、风险预算、回撤与止损纪律；输出“是否允许做/做多大/何时停”的约束。
- 内阁（Arbiter/Emperor）：汇总三方意见，产出最终建议与置信区间，并把分歧点固定成后续实验清单。

## 输出形态（最小交付）

- 每日自动化日报（跨市场 + 持仓 + 关注池）。
- 单标的“讨论纪要”（三方意见 + 内阁裁决 + 证据入口）。
- 组合/持仓复核（风险预算变化、集中度、相关性、回撤梯子触发）。

## 验收口径（落到 repo 的最小结构）

- 每个模块都要有：
  - `contract.md/tsv`（输入/输出/边界/依赖数据）
  - 可跑脚本（或可复现实验入口）
  - `acceptance.md`（断言：字段、行数、关键统计、误差上界）
- 回测诚实性：
  - 明确训练/验证分割策略
  - 支持 CSCV/PBO 或等价的稳健性评估

## 非目标（显式不做）

- 不承诺“保证盈利”。
- 不把不可复现/不可验证的 guru 话术写进对象卡硬逻辑。
- 现阶段不做自动下单对接。

## 未决策（需要你拍板的两点）

### D1：建议的“强度”

- 选项 A：只给观点与证据（不输出交易动作）
- 选项 B：给交易计划（entry/stop/target/仓位建议），但不自动执行
- 选项 C：给组合层面的调仓建议（仍不自动执行）

### D2：我在项目里的角色

- 选项 A：偏工程化（把你的想法落到“可跑 + 可验收 + 可维护”的体系）
- 选项 B：偏产品/架构合作者（跟你一起定模块、定交互、定验收）
- 选项 C：双角色（A+B），但需要你明确“哪些决策必须问你，哪些我可直接裁决”
