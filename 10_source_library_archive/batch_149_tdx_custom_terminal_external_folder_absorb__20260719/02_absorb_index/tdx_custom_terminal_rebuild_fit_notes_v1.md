# TDX Custom Terminal Rebuild Fit Notes v1

更新时间：2026-07-20

## 一、这页用途

- 这页只回答一个问题：
  - 这套通达信改版终端里的东西，哪些值得被我们吸收、复刻、映射到我方体系
- 这页不回答：
  - 是否直接照搬整套终端
  - 是否把对方所有页面都做进我方 P0

## 二、我方当前主线前提

- 我方终局口径是：
  - `可解释的投资决策辅助驾驶舱`
- 用户感知口径更接近：
  - `私人投资管家`
- 当前最小闭环仍冻结为：
  - `提醒 -> 解释 -> 记录 -> 回看`
- 因此任何吸收都必须服从：
  - 解释性
  - 可追溯
  - 可裁决
  - 不把终端堆料等同于产品价值

## 三、适合吸收的部分

### 3.1 页面组织方式

- `Page.html` 这类“一个入口挂多个研究页/诊断页/资金页”的组织方式值得吸收。
- 适合映射到我方：
  - 事件详情页里的 `解释 / 相关事件 / 参考资料 / 回看链接`
- 但不应直接复刻成：
  - 无节制外链堆叠的 iframe 集合页

### 3.2 图表示意层

- `kpl-K线图.html`
- `东财K线+资金图.html`

值得吸收的是：

- K 线 + 量能/资金联动的呈现思想
- 不同信息层叠加展示的方式

不应直接照搬的是：

- 对外部第三方 API 的强绑定
- 依赖终端本地路径与特定运行环境的页面拼接

### 3.3 功能入口编码层

- `FeatureID / PadCode / MenuCommand / treeid` 这一套入口编码机制很值得研究。
- 它适合被我们吸收到：
  - 页面动作字典
  - 事件入口合同
  - “从哪里打开、打开后看什么”的显式路由层

### 3.4 真实脚本样本

- `flatjy.lua` 值得继续下钻。
- 原因不是它本身直接能进我方体系，而是它证明：
  - 对方终端里确实有可读逻辑代码
  - 后续“导出指标或脚本源码”这条线是有价值的

## 四、不应直接吸收的部分

### 4.1 整包 UI 壳

- `embui.cfg` 的价值更偏“研究入口组织方法”。
- 不应直接把：
  - 顶栏
  - 侧栏
  - 快捷按钮
  - 终端窗口逻辑
  一股脑搬进我方产品。

### 4.2 强依赖外部站点的页面

- 很多页面只是把：
  - 东方财富
  - 同花顺
  - 股吧
  - 通达信云页
  聚到一起。
- 这类内容可做“参考源列表”，不应直接当成我方核心能力。

### 4.3 尚未导出的指标源码

- 当前没有证据表明我们已经拿到了它的批量指标源码文本。
- 所以当前不能做：
  - 参数还原
  - 全量公式比较
  - 与我方指标体系逐项对齐

## 五、与我方体系的最自然衔接

- 第一层衔接：
  - 学入口组织，不学终端堆料
- 第二层衔接：
  - 学图表信息分层，不抄第三方 API 页面
- 第三层衔接：
  - 学“功能入口编码”和“页面路由”，服务我方可解释工作流
- 第四层衔接：
  - 等拿到代表性指标源码后，再判断是否能映射到我方证据层/解释层

## 六、后续最值钱的补件

- 当前更值钱的，不是立刻导出 `3 到 5` 个代表性指标源码。
- 当前应先做：
  - `可见效果 -> 来源三分表`
  - 先把 `页面 / 网页载体`
  - `插件 / 快捷键 / 菜单编排`
  - `真公式候选`
  三层分开
- 理由是：
  - 现在直接导源码，容易把 `funcs/*.sp` 或 `ECharts` 页面误认成公式正文
- 三分表稳定后，再补：
  - `3 到 5` 个代表性指标源码
  - 每个指标至少补：
    - 公式正文
    - 参数区
    - 图形效果截图
    - 用途说明
- 然后再做：
  - `对方指标 -> 我方体系` 映射卡
  - `可直接复刻 / 可解释借鉴 / 不建议吸收` 三分流

## 七、主负责人裁决

- 当前先把这批材料定位为：
  - `终端级结构吸收批`
- 当前不把它定位为：
  - `指标源码库`
- 下一手若继续深挖，当前唯一值得优先补的是：
  - `可见效果 -> 来源三分表`
- `代表性指标源码导出` 仍保留，但后置到三分表稳定之后
