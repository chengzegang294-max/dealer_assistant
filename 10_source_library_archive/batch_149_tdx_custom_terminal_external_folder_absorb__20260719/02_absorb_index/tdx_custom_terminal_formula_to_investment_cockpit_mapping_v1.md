# TDX Custom Terminal Formula To Investment Cockpit Mapping v1

更新时间：2026-07-20

## 一、这页用途

- 这页把当前已吸收的 `17` 组真实公式样本，先映射到我方 `提醒 -> 解释 -> 记录 -> 回看` 最小 P0 闭环。
- 这页不追求“逐条公式全量对象化”。
- 这页先回答一个更值钱的问题：
  - 这些公式更适合进入我方哪一层？

## 二、主负责人总判断

- 当前拿到的真实公式样本，并不适合被原样照搬成产品功能。
- 它们更适合被拆成三种输入：
  - `提醒触发输入`
  - `解释文案输入`
  - `回看评分输入`
- 真正应避免直接吸收的，是：
  - 花哨主图绘制样式
  - 终端语境强绑定的色彩和图标提示
  - 高耦合的综合大杂烩公式壳

## 四、按四层架构重排

### 1. 提醒层

- 应吸收的核心：
  - `涨停家数 / 连板家数 / 跌停家数`
  - `封板成功资金 / 封板失败资金`
  - `行业涨幅 / 指数涨幅`
  - `强势股评分`
  - `启动点 / 顶底切换 / 转向离场`
- 这些值适合被改造成：
  - 事件卡上的状态徽标
  - 今日事件流的触发条件

### 2. 解释层

- 应吸收的核心：
  - `为什么今天触发`
  - `当前所处环境`
  - `当前属于行业驱动、情绪驱动还是资金驱动`
- 这些值适合被改造成：
  - 首页事件摘要字段
  - 个股页里的解释摘要块

### 3. 记录层

- 应记录的不是公式原值本身，而是压缩后的决策语义：
  - `环境顺风 / 中性 / 逆风`
  - `行业强 / 弱`
  - `热点热度升 / 降`
  - `资金异动强 / 弱`
  - `个股触发 = 启动 / 观望 / 离场`
- 记录层应避免：
  - 把几十个公式中间变量直接写进用户记录草稿

### 4. 回看层

- 最值得回看的不是“某公式当时画了什么线”，而是：
  - 哪类提醒最常出现误报
  - 哪类环境过滤最能减少误判
  - 资金异动与热点热度是否真的有解释力
  - 个股触发信号在不同环境下是否稳定

## 五、首轮对象卡建议

- 第一优先做对象卡的，不是全部 `17` 条公式，而是 `6` 组最值钱样本：
  - `HYDB行业对比`
  - `ZSDB指数对比`
  - `沪深涨跌停`
  - `打板资金`
  - `上榜资金`
  - `启动点`
- 原因：
  - 这 `6` 组已经足够拼出：
    - 环境
    - 热点
    - 资金
    - 个股动作
  - 正好对应我方首页 P0 需要的最小解释闭环

## 六、不建议直接照搬的部分

- `波段操盘`
- `裸K`
- `林森操作系统`
- `短中操盘系统`
- `点石成金`

这些公式的问题不是“没价值”，而是：

- 变量和图形表达过重
- 单公式混合了太多判断维度
- 适合拆解成多个提示条件，不适合一比一搬进产品
