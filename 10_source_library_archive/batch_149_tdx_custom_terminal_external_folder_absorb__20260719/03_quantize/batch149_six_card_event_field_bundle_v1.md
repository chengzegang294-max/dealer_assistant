# Batch149 Six Card Event Field Bundle v1

更新时间：2026-07-20

## 一、用途

- 这页把 `6` 张核心对象卡进一步压成：
  - `首页事件卡字段`
  - `解释卡字段`
- 这页是 `Batch1` 切回代码实现前的最小总表。
- 这页不重开合同。

## 二、上游对象卡

- `沪深涨跌停`
- `打板资金`
- `上榜资金`
- `HYDB行业对比`
- `ZSDB指数对比`
- `启动点`

## 三、EventSummary 最小总表

| 字段 | 填充规则 | 主要来源对象卡 | 说明 |
|---|---|---|---|
| `eventId` | `market-...-<date>` 或 `stock-...-<date>-<symbol>` | 全部 | 用规则化 id，不直接用公式名 |
| `title` | 一句事件标题 | 全部 | 只写人能看懂的事件句子 |
| `subject` | `全市场 / 全市场打板 / 全市场榜单资金 / 全市场指数环境 / 相关行业 / 相关个股` | 六卡各自填充 | 不把原公式名塞进 subject |
| `occurredAt` | 当次触发时间 | 全部 | 与首页事件流时间轴一致 |
| `holdingRelation` | `其它 / 关注相关` | 启动点优先可填 `关注相关`；其余默认 `其它` | 当前不强行做持仓判断 |
| `processStatus` | 初始固定 `pending` | 全部 | 后续由 Batch1 交互更新 |
| `disclosureFlag` | 固定 `still_need_evidence` | 全部 | 禁止把信号伪写成结论 |

## 四、ExplanationPayload 最小总表

| 字段 | 填充规则 | 主要来源对象卡 | 说明 |
|---|---|---|---|
| `eventId` | 同 EventSummary.eventId | 全部 | 一一对应 |
| `title` | 同 EventSummary.title | 全部 | 不重复发明别名 |
| `subject` | 同 EventSummary.subject | 全部 | 统一主体 |
| `logic` | 写触发逻辑，不写参数大杂烩 | 六卡各自输出 | 长度应控制在人能快速阅读的解释句 |
| `impact` | 写事件影响，不写买卖指令 | 六卡各自输出 | 只解释顺风、承接、背书、观察价值 |
| `historyAnalogy` | 可空 | 六卡可选 | 只能轻类比，不写胜率承诺 |
| `nextReviewPoint` | 写下一次复查点 | 六卡各自输出 | 这是最重要的回看钩子 |

## 五、首页最小消费分配

| 前端位置 | 消费字段 | 主要对象卡来源 | 说明 |
|---|---|---|---|
| `今日事件流卡片标题` | `EventSummary.title` | 六卡 | 首页唯一主轴仍是今日事件流 |
| `事件卡副标题/主体` | `EventSummary.subject` | 六卡 | 用来区分市场、行业、个股层 |
| `事件卡时间` | `EventSummary.occurredAt` | 六卡 | 不从公式名派生 |
| `选中事件摘要条` | `title / subject / occurredAt / holdingRelation / processStatus` | 六卡 | 只展示压缩字段，不展示原公式值 |
| `解释卡` | `logic / impact / historyAnalogy / nextReviewPoint` | 六卡 | 作为用户理解当前事件的主要载体 |
| `记录表单前情` | 压缩后的解释结论 | 六卡 | 不直接吃原公式参数 |

## 六、六卡分工

| 对象卡 | 在 Batch1 中的职责 |
|---|---|
| `沪深涨跌停` | 提供市场热度与风险偏好宽度 |
| `打板资金` | 提供热点承接与炸板压力解释 |
| `上榜资金` | 提供资金背书与榜单异动解释 |
| `HYDB行业对比` | 提供行业顺风/逆风背景 |
| `ZSDB指数对比` | 提供大盘环境顺风/逆风背景 |
| `启动点` | 提供个股动作候选与观察价值 |

## 七、禁止项总表

- 禁止把公式名直接当事件标题。
- 禁止把原始公式参数整段塞入 `logic`。
- 禁止把解释字段写成买卖建议。
- 禁止在 `historyAnalogy` 伪造历史胜率。
- 禁止把终端样式、颜色、图标、箭头搬成产品字段。
