## 教程一：Tushare 教程可吸收核心

### 可以直接吸收的部分

- 量化研究不是“拿到接口就结束”，而是完整工程链：
  - 数据获取
  - 预处理
  - 因子构建
  - 因子评估
- 数据下载必须支持：
  - 增量更新
  - 并行拉取
  - 本地存储
- 因子评估至少要有：
  - `IC`
  - `IR`
  - 分层回测
- 项目结构应保持主流程入口 + 模块化函数，而不是脚本杂糅。

### 当前最值得保留的工程思想

- 不要反复全量下载，优先增量更新。
- 不要把 API 当数据库，本地必须落存。
- 不要只有“抓到了数据”，还要能验证信号有效性。

### 不应直接照搬的地方

- 视频里对积分、权限、价格的口播只能作为经验参考，不能当官方真值。
- 视频更偏“量化因子研究工作流”，不等于它自然适配当前仓库的事件驱动 P0。

## 教程二：通达信替代方案可吸收核心

### 可以直接吸收的部分

- `通达信 + pytdx` 对 `OHLCV / 日线 / 分钟线 / Tick` 这一层很有性价比。
- 财务与基础信息不必强求单一源，可以分层补：
  - `AKShare`
  - `雪球`
  - 其他公开源
- 技术指标不必为了“现成因子接口”付费，只要有基础 K 线字段，就能自己算。
- AI 适合承担“指标公式转 Python 计算脚本”的重复劳动。

### 当前最值得保留的工程思想

- 行情底表和财务/公告/资金流不必绑死在一个供应商。
- 先拿到统一底层八字段，再在本地派生技术指标。
- 免费方案适合做底座，但要承认稳定性和口径一致性未必够做唯一真源。

### 不应直接照搬的地方

- 视频把“通达信可替代”说得较满，但当前并没有直接证明它能稳定覆盖：
  - `main_fund_net_inflow`
  - `main_fund_net_inflow_ratio`
  - `northbound_net_inflow`
- 因此它更适合作为“分层替代”，不适合直接宣称“完全等价替代 Tushare”。

## 两篇教程合并后的内化结论

### 当前应该保留的真观点

- `Tushare` 的价值不只是接口本身，而是它把一些 A 股常用字段组织得更像“研究型数据源”。
- `通达信` 的价值不只是免费，而是它能显著降低 `OHLCV / 分钟线` 底座成本。
- 真正该保留的，是“工程骨架”：
  - 增量
  - 缓存
  - 并行
  - 本地宽表
  - 结果评估

### 当前不应被教程带偏的地方

- 不要因为 `Tushare` 贵，就把所有字段都迁到替代源。
- 不要因为 `通达信` 免费，就假设它天然覆盖资金流和事件字段。
- 不要把“教程作者的经验价格判断”直接视作当前官方资费合同。

## 对本仓的直接启发

- `T01/T04/T05` 更适合优先评估 `通达信` 作为底表来源。
- `T02` 仍要单独判断，因为它依赖的 `moneyflow` 在当前实现里是必需字段。
- `T03` 可以接受降级，不必为了“一致预期全字段”被单一数据源长期绑死。
