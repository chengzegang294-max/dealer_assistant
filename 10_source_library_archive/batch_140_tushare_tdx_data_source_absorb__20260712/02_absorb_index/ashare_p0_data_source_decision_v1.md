# A股 P0 数据源裁决 v1

更新时间：2026-07-12

## TASK

- 判断：当前 A 股 P0 到底要不要为 `Tushare` 付费，以及后续应该怎么使用 `Tushare / 通达信 / AKShare / 雪球` 这几类源。

## BACKGROUND

- 当前 A 股 P0 已经把 `T02` 的真实源抓取脚本和预检链路写好。
- 当前真实阻塞已经收缩为：
  - `TUSHARE_TOKEN` 缺失
- 当前 `tushare` 依赖已经补齐，不再是安装问题。
- 当前 `T02` 里：
  - `moneyflow` 是 `required`
  - `northbound` 和 `industry` 是增强项

## KNOWN_CONSTRAINTS

- 当前任务边界只到 A 股 P0，不讨论未来全市场大数据仓。
- 当前不为了“未来也许要用”就提前做高档预付费。
- 当前不把教程作者口播价格直接视作官方真值。
- 当前不因为免费替代看起来顺，就重开整套合同。

## 方案对比

### 方案 A：不充钱，继续等替代源补齐

- 适用条件：
  - 预算极紧
  - 接受 `T02` 暂时继续停在模板级或降级级
- 优点：
  - 当前零现金支出
- 缺点：
  - `T02 moneyflow` 继续卡住
  - 现有 fetcher 与拼接链无法真正验收
- 风险：
  - 项目会长期停留在“入口都写了，但没有真实数据”状态

### 方案 B：只补最小 `2000` 积分层级

- 适用条件：
  - 当前核心目标是尽快打通 `T02 moneyflow`
  - 不打算立刻扩成分钟线、港美股、公告全家桶
- 优点：
  - 用最小成本解当前 P0 最具体的阻塞
  - 与仓内现有 `Tushare` fetcher 直接兼容
- 缺点：
  - 未来若快速扩面，可能还要升档
- 风险：
  - 若后续发现某些额外接口权限仍不够，需要单点再判断

### 方案 C：直接高档充值，继续把 Tushare 当大全量主源

- 适用条件：
  - 已确定未来 1-3 个月会快速扩到更多字段族与更大批量
- 优点：
  - 少碰数据源切换
  - 频次和权限相对更宽
- 缺点：
  - 对当前 P0 需求明显超配
  - 预算沉没风险更高
- 风险：
  - 你为未来假设付费，而不是为当前阻塞付费

### 方案 D：用 `通达信 + AKShare/雪球` 完全替代 `Tushare`

- 适用条件：
  - 当前只做 `OHLCV / 分钟线 / 技术指标`
  - 接受资金流与财务事件口径后续单独再补
- 优点：
  - 对 `T01/T04/T05` 降本明显
  - 行情底座很有性价比
- 缺点：
  - 对当前 `T02 moneyflow` 不能形成直接等价闭环
- 风险：
  - 会从“付费问题”转成“口径拼接和替代源稳定性问题”

## 主负责人最终裁决

- 当前最推荐：`方案 B + 方案 D 的分层组合`
- 具体就是：
  - `Tushare` 只为当前 P0 必需缺口付费
  - `通达信` 优先考虑承担后续 `OHLCV / 分钟线` 底表
  - `AKShare/雪球` 只作为补源，不先升格成唯一真值源

## 为什么这样定

- 不选纯 `方案 A`：
  - 因为 `T02` 不是“未来再说”的问题，而是当前 runtime 主线已经写到最后一公里。
- 不选纯 `方案 C`：
  - 因为当前只是 `T02` 被卡，不值得为远期扩张直接高配。
- 不选纯 `方案 D`：
  - 因为它对 `T01/T04/T05` 很强，但对 `T02 moneyflow` 还不够稳。

## 当前使用建议

### 现在就该怎么做

1. 先注册并配置 `TUSHARE_TOKEN`
2. 若免费积分不足以覆盖 `moneyflow`，只补最小 `2000` 积分层级
3. 用仓内现成链路顺序执行：
   - `check_t02_tushare_env_v1.py`
   - `fetch_t02_moneyflow_tushare_v1.py`
   - `fetch_t02_northbound_tushare_v1.py`
   - `fetch_t02_industry_map_tushare_v1.py`
   - `build_t02_real_input_v1.py`
   - `run_t02_fund_flow_scan_v1.py`

### 后面怎么分层用

- `Tushare`
  - 当前只承担：
    - `T02 moneyflow`
    - `northbound`
    - `industry` 的现成抓取入口
- `通达信`
  - 后续优先评估承担：
    - `daily OHLCV`
    - `minute OHLCV`
    - 技术指标底表
- `AKShare/雪球`
  - 后续优先评估承担：
    - 财务补源
    - 公告/基础信息补源
    - 行业映射补源

## 当前一句话结论

- 现在不是“要不要为 Tushare 长期重仓付费”，而是“要不要花最小成本把当前 A 股 P0 的 `T02` 真实资金链打通”。
- 对这个问题，我的结论是：
  - `要`
  - 但只建议最小付费，不建议高档预付
  - 同时尽快把 `通达信` 纳入后续 `OHLCV` 分层替代路线
