## 一、本说明只回答什么

如何从已确认的两条主请求，抽出**一个交易日**的最小可用样本，并验收通过。

不做：

1. 新接口搜索
2. 多日回填
3. 题材中心并跑
4. 正式调度/全量落库

## 四、抽取步骤（固定顺序）

1. 选定单日 `date`（先用 `20260807` 打通）
2. 登录态各请求 1 次，保存 raw
3. 按最小字段合同裁剪：
   - ladder：保留日层 + boards + stocks 的 required/recommended
   - sector：保留头字段 + rows 的 required/recommended
4. 展开 TSV：
   - ladder 一行一股：`date, board_level, code, name, ...`
   - sector 一行一板块：`tradeDate, sectorCode, sectorName, ...`
5. 写验收页，勾门槛
6. 停。不扩第二日，除非验收失败需要换日复测

## 五、裁剪规则（执行口径）

### ladder

保留：

- `dates[].date/dayOfWeek/totalStocks/pauseRatio`
- `dates[].boards[].level`
- stocks：合同 `required` + `recommended`
- 顶层 `dateRange`、`meta.totalStocks/uniqueStocks/hasRealtimeData`（recommended/optional 按合同）

删除进最小样本：

- `business_scope` / `main_business` / `reason_info`
- 纯展示串与明确 optional/exclude 字段

### sector

保留：

- `success`
- `data.tradeDate/actualTradeDate/universe/mode/snapshotMinute/quoteSnapshotMinute/snapshotTime/total/returned`
- rows：合同 `required` + `recommended`

删除进最小样本：

- `data.quality.*`
- `data.fieldDefinitions.*`
- rows 的 optional 字段

## 七、验收门槛（样本层）

单日样本通过，必须同时满足：

1. 两个 raw HTTP=`200`，JSON 可解析
2. ladder：`dates[0].date == {date}`，`boards` 非空，股票 required 字段无系统性缺失
3. sector：`success == true`，`actualTradeDate == {date}`（或明确记录偏差），`rows` 非空
4. 产出了 min JSON + min TSV + acceptance 页
5. 未新增第三接口

建议记录的核对数字：

- ladder `totalStocks` / 实际展开股票行数
- sector `returned` / 实际展开板块行数
- `kpl_plate_code` 与 `sectorCode` 去后缀 `k` 后的可对齐比例（只记，不强求 100%）
