# A5 A股 P0 Batch1 桌面端第二轮走查记录

  - 记录 `A股 P0 首页工作台 Batch1` 在展示边界继续收紧之后的桌面端第二轮最小走查结果
- 本页不做：
  - 重开产品方向
  - 重开字段合同
  - 扩展到标的页或问答页验收

## 三、主负责人裁决

- 当前桌面端第二轮最小主路径可继续判通过
- 理由：
  - 展示边界继续收紧后，空态、选中态、提交回显、`processStatus` 回写、待处理摘要回流、切事件重置依然成立
  - 当前未出现 adapter 化之后的展示回归
- 当前需要继续写死的边界仍然只有：
  - 搜索动作在 `Batch1` 只验：
    - `发出打开动作`
  - 当前仍不验：
    - 真正跳转标的页
    - 新开详情页
    - 网络请求触发

## 四、桌面端第二轮走查结果

| 步骤 | 结果 | 说明 |
|---|---|---|
| 打开首页 | 通过 | 首屏可见 `今日事件流` 与金融限制披露入口 |
| 不选事件时主工作区为空态 | 通过 | 主工作区显示明确空态提示，没有提前展示旧草稿与旧回显 |
| 点击事件卡进入选中态 | 通过 | 点击后在同一首页进入主工作区，不跳新页 |
| 摘要、解释、记录区连续可见 | 通过 | 适配层下沉后，选中事件摘要、解释卡、记录表单仍连续可见 |
| 填写动作/理由/周期并提交 | 通过 | 选择 `继续观察 / 环境顺风 / 1-3天` 并填写备注后提交成功，立即出现最新提交回显 |
| `processStatus` 回写 | 通过 | 提交后当前事件从 `未处理` 变为 `已处理`，顶部待处理数量从 `6` 变为 `5` |
| 待处理摘要回流 | 通过 | 点击右侧待处理事件后，可回到同一主工作区上下文并切到对应事件 |
| 切事件重置草稿与回显 | 通过 | 切到新事件后，下拉重置、备注清空、旧回显消失，说明旧事件未污染新事件 |
| 搜索入口触发打开动作 | 通过 | 输入 `300750` 后页面内出现 `已发出打开标的页动作：300750` |

## 五、当前未出现的不通过项

- 当前未出现：
  - 记录前看不到解释
  - 提交后回到空状态
  - 提交后看不到回显
  - 切事件后旧草稿污染新事件
  - 提交失败后草稿丢失
  - 披露入口消失
  - 搜索入口只有输入框，没有正式打开动作

## 六、当前边界说明

- 当前搜索动作的通过条件仍然只是：
  - 发出打开动作并给出页面内反馈
- 当前并未验证：
  - 真实标的页跳转
- 因此若未来把 `Batch1` 的搜索要求升级为“必须真实打开标的页”，则这一项需要重新判定，不应沿用本页结果直接升级口径

## 七、当前结论

- 当前这轮桌面端第二轮走查已经足够支持：
  - `Batch1` 继续推进
- 当前最值钱的下一手不是回头补旧合同，而是：
  - 把当前展示边界继续稳定住
  - 视情况补一轮更轻的桌面端回归走查
  - 再考虑是否需要把这条线交给 `Cursor` 做实现向审校
