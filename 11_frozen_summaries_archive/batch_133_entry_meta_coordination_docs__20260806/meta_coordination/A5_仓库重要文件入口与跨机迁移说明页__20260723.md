# A5 仓库重要文件入口与跨机迁移说明页

更新时间：2026-07-23

## 一、这页用途

- 本页只做：
  - 固定“文件很多时先看哪里”的最短入口链
  - 固定仓库内哪些文件属于高优先级真值入口
  - 固定把仓库复制/迁移到其他电脑时的最小检查口径
- 本页不做：
  - 替代各批次 README
  - 承诺所有 runtime 到任意机器都能零配置运行

## 二、主负责人裁决

- 当前仓库并不怕“文件多”，真正风险是：
  - 没有稳定入口链
  - 真值只散落在临时区
  - 批次缺 README/manifest/provenance
  - 迁移时只拷局部目录导致链路断裂
- 当前仓库的防崩口径固定为：
  - `04_active_main_docs` 负责短入口
  - `00_entry` 负责合同/政策/总裁决
  - `10_source_library_archive` 负责来源真值与 raw
  - `02_runtime` 负责执行事实
  - `20_tools_workspace` 负责实现工作区

## 五、重要文件防坍塌规则

- 任何长期复用的 batch 都必须至少具备：
  - `README`
  - `manifest`
  - `provenance`
- 任何“当前活跃状态”不得只写在：
  - 对话
  - 临时文件
  - 本地 `.gitignore` 隐藏修改
- `04_active_main_docs` 只保留短入口，不承接大段 raw 与长执行文。
- `00_entry` 负责 repo-global 判断，不把批次原件混放到根层。
- `暂时存放/` 永远不是重要文件长期落点。

## 六、跨机迁移的最小可用口径

- 若目标只是：
  - 看文档
  - 找入口
  - 继续整理/开发
  则整仓复制或正常 `git clone` 后，仓库是可迁移的。
- 若目标是：
  - 复跑具体 runtime
  - 重启某个前端/脚本环境
  则还要额外检查本机依赖，不允许直接口头宣称“必然可跑”。

## 七、跨机迁移最小检查清单

1. 检查仓库根目录是否完整保留：
   - `00_entry`
   - `04_active_main_docs`
   - `10_source_library_archive`
   - `20_tools_workspace`
   - `02_runtime`
2. 打开：
   - `04_active_main_docs/batch_01_selected/00_主线检索索引.md`
3. 确认当前要继续的批次同时存在：
   - 工作区代码
   - 对应 README
   - 对应 manifest/provenance
4. 若要继续前端工作，再检查目标工作区自己的依赖文件是否齐全：
   - `package.json`
   - lockfile
   - workspace README
5. 若要继续 runtime，再检查对应脚本说明页和输入产物是否仍在 repo 路径内

## 八、不允许的迁移姿势

- 只拷 `20_tools_workspace`，不拷 `00_entry / 04_active_main_docs`
- 只拷某个 batch 的部分 raw，不拷 README/manifest/provenance
- 只保留导出结果，不保留来源说明与索引
- 把本地临时目录当迁移真值源

## 九、当前仍保留的边界

- 当前可以明确说：
  - 仓库的文档入口链与批次组织方式具备可迁移性
  - 重要文件已有短入口和目录角色约束
- 当前不能超前说：
  - 任意机器拿到仓库后，所有脚本和前端都无需补环境即可运行
- 若未来需要“环境级可迁移”承诺，再单独补：
  - 依赖冻结
  - 环境 bootstrap
  - 平台差异检查页

## 十、一句话口径

- 仓库不会因为文件多就崩，前提是继续坚持“短入口在 `04_active_main_docs`、真值合同在 `00_entry`、来源 raw 在 batch README/manifest/provenance”这条链；跨机复制也必须整链带走，不能只拷局部工作区。
