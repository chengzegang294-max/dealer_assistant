## 五、当前真正要讨论什么

- 当前真正要讨论的是：
  1. 技术指标不应按名字堆清单，
     而应按：
     - 职责
     - 市场状态
     - 单子特征
     来组织
  2. 同一指标在不同场景下，
     是否应承担不同职责
  3. 我们真正要长期积累的，
     是否应该是：
     - `指标职责 x 市场特征 x 单子特征`
       的场景矩阵
  4. 回测应该在什么层级进入，
     才不会变成调参泥潭

## 七、当前建议的讨论分层

### 7.1 第一层：通用性层

- 讨论：
  - 每类技术指标本质上在捕捉什么
  - 它更适合承担什么职责
  - 它最典型的失效方式是什么

### 7.2 第二层：市场特征层

- 讨论：
  - 趋势 / 震荡
  - 高波动 / 低波动
  - 风险偏好强 / 弱
  - 量能活跃 / 冷清
    这些状态下，
    哪类指标更适合被启用、
    降权或只做过滤

### 7.3 第三层：单子特征层

- 讨论：
  - 短拿还是长拿
  - 吃弹性还是吃稳定
  - 容忍回撤大还是小
  - 事件驱动还是常规节奏
    这些差异会怎样改写
    指标的用法

### 7.4 第四层：最小回测进入层

- 讨论：
  - 当通用性层 / 场景层 / 单子层
    已经冻结到什么程度，
    才值得进入最小回测

## 八、本轮多AI真正要裁什么

- 本轮真正要裁的是：
  1. 技术指标长期主线，
     是否应明确改写为：
     - `指标职责 x 市场特征 x 单子特征`
       的场景矩阵建设
  2. 当前第一批最值得细化的市场特征维度有哪些
  3. 当前第一批最值得细化的单子特征维度有哪些
  4. 当前最自然的最小讨论顺序是什么
  5. 回测应处于：
     - 立即进入
     - 作为第二阶段
     - 作为第三阶段
     哪一层

## 九、多AI输出合同

- 每个模型至少给出：
  - `保守方案`
  - `平衡方案`
  - `进取方案`

- 每个方案必须写：
  - 技术指标主线应如何组织
  - 应先讨论哪些市场特征
  - 应先讨论哪些单子特征
  - 最小讨论顺序
  - 最小回测切入点
  - 仍需保留的
    `still_need_evidence`

- 每个模型最后必须补：
  - 当前最推荐方案
  - 不推荐另外两个方案的原因
  - 一句
    `当前主线下一步最应该做什么`
